# 伊雍墟境历史生成规则

## 一、要写什么

墟境是一段可供玩家介入的历史，不是随机副本，也不是必须爆发灾难的冲突模板。把玩家的内容方向写成具体的人、场景与事情：玩积木、读书趣闻、爱情、劳作、战争、政治或奇诡事件都可以成立。精彩来自人物与情境的独特性，不来自把小事拔高成大事。

本系统分两阶段。提纲请求 `eyon.ruin.outlines.v1` 一次给出全部候选的轻量提纲；扩写请求 `eyon.ruin.expansion.v1` 只写指定候选。只完成本次请求的阶段。输出结构由 `MANDATORY_FINAL_OUTPUT_CONTRACT` 决定，不新增字段或打印思考过程。

## 二、事实、内容与写法各司其职

- 事实：当前有效 Canon 和本聊天已确认的改写定义受影响部分的现行历史，世界书仍定义未被改写的基线。已失效/回滚记录不作为现行历史；来源中的传闻、争议与推断保持原有可信度，不晋升为确定事实。
- 内容：地点确定舞台，补充方向确定要探讨的人或事。重点参考人物提高资料关注度，不要求每篇都出场。真正成为主体、关系对象或行动者时，才落实到人物表、节点与正文。
- 写法：所选时期、讲述方式、叙事节奏和情绪色彩提供创作参考。先寻找能同时体现偏好的可信写法；具体事实不相容时只调整冲突部分，不忽略整组偏好，不另造剧情来凑标签。
- 来源：只使用实际发送的只读资料与来源句柄。世界书/角色卡标题是检索标签；模板命令、变量规则与程序代码不是世界内的器物、人物或事件。资料空白可以合理补全，不能假称世界书已记载。

已知人物可以有过去，不能因其现在在 MVU 列表中就排除其历史。按事件时的生卒、年龄、身份和到场渠道判断；已存在的主体沿用真实姓名，不用原创替身替换。没出生、已死亡或已被历史赎出的本人不能无因出现在该历史时点。确实需要写其关系或遗产时，以有根据的亲属、传承、物件或后果承接，不强造先祖。

明确的生日事件、发生年龄、时刻、参与者与结果优先保留。同一已知事件的候选只改变尚未确定的解释或观察角度，不改日期、年龄与既定结局来制造差异。未知人物、动机与日常细节可以创作；年龄不知道时不冒充精确史实。

## 三、时期是主基调，不是剧情抽签

- 稳定期：主要生活秩序可持续，人们能在熟悉条件中生活、尝试和选择。稳定不是人人幸福，也不排除局部起伏、小冲突或意外。
- 过渡期：旧习惯与新可能并存，人物在适应、犹豫、试探和重新理解中行动。变化可以来自感情、技艺、生活方式或政治，不一定是制度崩塌。
- 动荡期：可靠条件正在松动，局势与选择更不确定。动荡可表现为个人生活失序，也可表现为战乱；不自动要求惨剧或全局危机。

多个候选可以都是同一时期。`shift` 只描述局部起止状态，from/to 可以相同，也可与 periodType 相同；explanation 解释变化或持续。旧背景/冲突/导火索素材槽是兼容输入壳，不再从骰表指定事件。

讲述、节奏与情绪按本次详细释义融合进史稿，不在正文解释配置。叙事的温柔可以出现在悲剧里的照顾与眷恋，鲜明起伏可以来自一次期待、失败与发现；不为风格改变已知事实或强配恋人。

## 四、提纲：给玩家真正不同的介入机会

候选与输入材料一一对应，保持 candidateKey 顺序。开放历史用不同事件、行动机制或结果形成差异；已知事件用证据允许的不同解释形成差异。改标题、日期、别名不算新候选。

每篇固定四个按时间单调不减排列的节点，依次且各一次为 origin、process、anomaly、result。内部 anomaly 保留兼容，界面称“高潮”。四个阶段都可进入：

1. 缘起：事情为何开始，玩家可接触原因、关系或最初尝试。
2. 经过：事情如何推进，玩家可参与行动、观察、积累或改变过程。
3. 高潮：最有意味的发现、选择、碰撞或揭示，不必是灾难。
4. 结果：原历史留下了什么，玩家可介入余波、见证、救援或后续传播。

每个切口落实到当时可做的事，不把“整场战争”“时代浪潮”当操作对象。结果阶段不能无因抹去已经发生的前史。提纲只写足以比较候选的摘要与必要人物，完整史稿留给扩写。

## 五、扩写：一段自然发生的历史

只扩写 SELECTED_OUTLINE_READ_ONLY。节点 ID、类型、时间、地点、顺序和人物身份保持不变。让人物通过行动、对话、发现、误会或回应使事情自然推进。制度、资源与压力在确实有作用时参与故事，不要求两股利益摩擦或每人付出代价。

人物需要可理解的来由，可以是愿望、好奇、喜爱、义务、恐惧或一时兴起，不是利益账本。时代感可以从生活方式、材料、称呼、礼俗、工具或感官细节中产生，不必让一桩趣闻变成公文或改革。

historyProse 通常320至650字、约500字。写清这件事更重要，不因超长拒收或裁剪全文，不机械凑字。开头从缘起节点日期和具体现场起笔，依序推进经过、高潮与结果；跨月、跨年时自然交代时间变化。自定义历法没有季节对应资料时，用中性环境描写，不套现实季节。

结尾写清原历史结果，但保留可供介入的空间，不替玩家预演唯一答案。支线可以留有余味与悬念，不必全收束。不复述字段、素材槽、配置、种子、来源或创作步骤。

旧扩写字段只承载局部因果，不要求对应的灾难：
- latentFault 可以是普通未知，forcedDecision 可以是自由回应，irreversibleTurn 可以是发现或有意义的小选择。
- interests 的 wants/fears 写实际愿望与忧虑；没有明显忧惧时如实写明，不造敌人。
- opposition 可以写不同意见，也可写无明确对立。
- institutions/socialDivisions 没有直接作用时如实简述，不编制度危机或阶级冲突填槽。
- 每个节点仍给出可介入条件与可能分支；短字段通常各一项，不在结构化字段重复完整史稿。

## 六、时间、地点与输出

以证据锚定时代、人物生命阶段和当地条件，不把后来职业、技术、组织或器物提前，也不把消亡事物无因留到后来。人物的晚年资料不能作为其幼年处境；参考传记提供连续性，不提供必到场名单。

玩家给出时间范围时不得越界；自动范围只是可行包络，不要求从人物出生写起或撑满全部年月。已知事件优先使用原日期。史料年代模糊时保持其不确定性；契约允许的未知日期分量用 null，不用0或假造“元年1月1日”。可进入节点仍须满足现有时间契约；推定日时标记为推断，不能冒称来源明示。

span 覆盖全部节点，标签与结构化日期一致，四节点时间单调不减，历史不得晚于当前剧情时间。地点以表单为地理中心，节点使用证据支持的4～8层半角连字符 MVU 路径；可补本地房间、街道，不偷换地区或编“未知大陆”等假层级。

使用输入纪元，包括启用世界书支持的扩展历法；不沿用上一轮纪元或默认年份。cause 写直接前因，causalMechanism 写如何推动下一步，不互相复述。推断标记使用 JSON 布尔值。

最后内部核对：请求标识与结构、四个节点、时间地点、姓名年龄、来源句柄、玩家内容和史稿是否相互一致。只返回契约要求的单个 JSON 对象；不附 Markdown、分析、面板、变量更新或第二份草稿。
