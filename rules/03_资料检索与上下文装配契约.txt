# 一、目标

本契约规定宗族谱系、墟境生成、寻根溯源和蝴蝶效应结算四种独立API请求如何读取、筛选、去重和装配资料。

检索层只提供史料，不负责创作，不修改世界书、聊天、MVU、记忆插件或墟境状态。

# 二、请求边界

每次检索必须绑定:

- `taskType`: `genealogy|ruin|biography|butterfly`
- `requestId`
- `characterKey`: 当前角色卡稳定标识
- `chatId`: `SillyTavern.getCurrentChatId()`的当前值
- `triggerMessageId`: 发起请求的玩家楼层；界面按钮请求可为 `null`
- `requestedAt`

切换角色卡或聊天后，原检索结果不得继续用于新会话。

# 三、统一输出

检索层返回 `ContextBundle`:

```json
{
  "schema": "eyon.context.v1",
  "taskType": "ruin",
  "requestId": "唯一ID",
  "scope": {
    "characterKey": "角色卡标识",
    "chatId": "聊天标识",
    "triggerMessageId": null
  },
  "currentWorld": {
    "time": "",
    "location": ""
  },
  "worldbookContext": [],
  "recentContext": [],
  "characterContext": [],
  "genealogyContext": [],
  "biographyRefs": [],
  "butterflyRefs": [],
  "sourceIndex": [],
  "warnings": []
}
```

所有正文片段、世界书条目和本地资料都必须拥有唯一 `sourceId`，生成结果只能通过 `sourceId` 引用来源。

# 四、权威来源

当前有效 Canon 与本聊天已确认改写先定义受影响部分，世界书定义未改写的基线；失效/回滚记录不恢复为当前事实。其余资料保留以下来源次序与可靠度：

1. 当前角色卡绑定且已启用的世界书明确设定。
2. 当前聊天中未隐藏、当前采用消息页已经确认的正文事实。
3. 当前聊天MVU变量。
4. 蝴蝶效应实际归档日志。
5. 已保存传记中的明确记录。
6. 宗族谱系中的明确资料。
7. 带有 `inference` 标记的本地补全资料。

脚本不得自行决定冲突真相，只负责保留来源、可靠度和冲突标记。

# 五、世界书检索

## 5.1 可读取范围

根据设置读取:

- 当前角色卡绑定世界书。
- 当前聊天世界书。
- 当前已启用的全局世界书。

按请求对象筛选已启用条目；伊雍核心/命定系统的规则文本不因其核心身份就当成历史史料。事实型内容与指令型内容按用途区分。

使用 `getWorldbook()`只读获取条目。不得调用替换、创建、删除或重新绑定接口。

## 5.2 条目筛选

只保留满足至少一项的条目:

- 名称、关键词或正文命中目标人物、地点、家族、组织、器具或别名。
- 与请求时间范围重叠。
- 与目标地点存在明确上下级、相邻、交通或管辖关系。
- 被另一条已命中资料明确引用。
- 对当前纪元、种族、制度或地理边界具有直接约束。

不得把整本世界书无差别发送给API。

## 5.3 规则与史料分离

以下内容属于运行规则，不进入 `worldbookContext`:

- 伊雍对白格式和美化标签。
- MVU更新规则、JSON Patch示例和EJS触发器。
- API密钥、设置、调试信息。
- 与当前生成模块无关的完整规则文本。

脚本嵌入规则由提示词装配器单独加载，不伪装成史料来源。

# 六、正文检索

## 6.1 默认范围

使用:

```text
getChatMessages("0-{{lastMessageId}}", {
  hide_state: "unhidden",
  include_swipes: false
})
```

只读取当前采用的消息页。默认不读取隐藏楼层，也不读取未采用的重roll页。

隐藏助手隐藏的正文不会被脚本悄悄重新加入API上下文。玩家需要使用旧史料时，应通过世界书、传记书库或明确选择的资料导入。

## 6.2 记忆插件隔离

- 只读取真实聊天消息，不读取酒馆最终提示词或记忆插件注入结果。
- 不调用接口枚举、覆盖、排序或删除其他插件的注入。
- 不把API草稿、占位槽、内部自省或后台错误写入聊天。
- 记忆插件生成的真实可见消息可以作为普通正文；仅存在于提示词注入中的内容不可读取。

## 6.3 清洗

发送给API前:

- 删除 `<UpdateVariable>`、JSON Patch和纯变量输出。
- 删除仅用于显示的重复HTML外壳，保留其可读文本。
- 保留人物对白、事件、地点、时间、关系和已确认结果。
- 同一事实重复出现时保留最近且来源最明确的一条，同时记录其他来源ID。
- 不改写原意，不使用模型对正文进行预总结。

# 七、MVU检索

当前世界与人物MVU从 `Mvu.getMvuData({type:"message",message_id:-1})` 的 `stat_data` 只读获取；
冻结或指定楼层资料按实际message_id读取。聊天级工作台存储另用 `getVariables({type:"chat"})`，
两者不得互相冒充，也不得以其他存档缓存替代当前楼MVU。

允许读取:

- `世界.时间`
- `世界.地点`
- `关系列表`中的人物资料
- `墟境系统.运行状态`
- `墟境系统.虚嗣指南快照`
- 与目标对象直接相关的任务或关系字段

禁止读取或发送:

- 与请求无关人物的完整背包、技能、装备和数值。
- 旧 `事件.伊雍`。
- API设置或密钥。

人物摘要按模块选择相关字段（不是按字符裁断正文或角色原文）:

- `genealogy`: 姓名、别名、种族、身份、职业、背景、已知关系、生卒信息。
- `ruin`: 玩家选中人物的姓名、种族、身份、职业、关系、生卒和相关背景。
- `biography`: 目标对象的性格、喜爱、外貌、身份、职业、关系、背景与相关历史；战斗数值只在玩家方向需要时加入。
- `butterfly`: 只读取本轮干涉涉及人物的身份、关系、背景和与因果传播直接相关的字段。

# 八、本地资料检索

## 8.1 传记

只选择与人物、地点、时间、组织、器具或玩家方向直接相关的阶段。

- `ruin`: 选择与当前方向、演员及时间地点有关的完整阶段和事实锚。
- `biography`: 选择与新传记对象、事件或时间有关的完整旧阶段，不机械规定每期两段。
- `genealogy`: 只读取明确亲属、生卒、婚姻、收养、监护和继承记录。
- `butterfly`: 选择能解释本轮因果传播或现世落点的完整相关阶段。

正式来源由统一检索的receipt.selected/selectedPassages确定，以上是相关性原则，不是额外数量门。
旧候选预选数量不冒充最终配额；装配器保持已选完整资料与来源，不再次硬切字符或只截首尾。

## 8.2 族谱

- `ruin`: 只发送已选参与人物之间有关的关系。
- `biography`: 只发送目标对象与玩家方向需要的直接关系。
- `genealogy`: 不读取旧族谱作为唯一事实源；旧缓存只用于比较和增量刷新。
- `butterfly`: 只发送本轮涉及人物之间能够承载因果传播的关系。

## 8.3 蝴蝶效应

优先使用当前聊天本地有效蝴蝶记录及 Canon 状态；旧世界书归档仅作精确标记和同聊天过滤的兼容资料，不重新开启镜像写入。

- 规则模板不得进入 `butterflyRefs`。
- 只选择影响当前人物、地点、组织、时间或玩家方向的日志。
- 日志属于已发生的当前世界线事实，不能被候选历史反向覆盖。

# 九、模块装配

## 9.1 宗族谱系

装配:

- 共享伊雍脚本上下文。
- 宗族谱系生成规则。
- 中心MVU人物。
- 相关世界书。
- 相关未隐藏正文。
- 必要的传记亲属记录。

不装配:

- 墟境生成规则。
- 寻根溯源生成规则。
- 无关蝴蝶效应全文。

## 9.2 墟境生成

装配:

- 共享伊雍脚本上下文。
- 已确认的时期主基调与文风参考；旧骰表字段仅作兼容输入。
- 墟境历史期生成规则。
- 界面时间、地点、`selectedCharacters`和`supplementaryDirection`。
- 相关世界书、未隐藏正文、MVU摘要、族谱关系、传记阶段和蝴蝶效应结果。

不装配:

- 正文交接模板。
- MVU更新规则全文。
- 其他候选的原始API输出。

## 9.3 寻根溯源

装配:

- 共享伊雍脚本上下文。
- 寻根溯源生成规则。
- 玩家完整原始指令。
- 目标对象资料。
- 相关世界书、未隐藏正文、MVU、族谱、旧传记与蝴蝶效应。
- 脚本已生成的时期计划。

不装配:

- RootTrace正文交接模板。
- 墟境候选生成规则。

## 9.4 蝴蝶效应结算

装配:

- 共享伊雍脚本上下文。
- 蝴蝶效应生成规则。
- 脚本在清空活动字段前冻结的 `ButterflyRequest`。
- 本轮已确认的九项创作参考；旧波及编号与范围只作兼容回显，不决定新故事规模。
- 本轮未隐藏正文中与玩家关键干涉直接相关的事实。
- 与本轮人物、地点、组织、器具和现实落点相关的世界书资料。
- 必要的MVU人物摘要、族谱关系、传记阶段和既成蝴蝶效应。

不装配:

- 当前清空后的活动墟境字段。
- 旧 `事件.伊雍`。
- 上一轮次的进入、当前或离开锚点。
- 墟境候选生成规则、寻根溯源规则或正文交接模板。
- 与本轮无关的完整聊天、整本传记、整棵族谱或全部蝴蝶效应全文。

冻结锚点、`runId`、已确认参考和兼容编号属于此次事务输入。检索层不得用后续MVU、正文或世界书替换；同楼正文重roll复用已生成的蝴蝶全文，删除玩家遣返楼后才由按钮重新准备。

# 十、预算与裁剪

这是开发侧选源说明，不给模型发布裁剪命令。当前采用相关完整资料单元与原文引用；不承诺运行时已实现逐模型精确预算，不因正文字符数硬切。

默认分配顺序:

1. 模块规则和玩家硬要求，禁止裁剪。
2. 世界书明确事实。
3. 当前目标MVU资料。
4. 最近且未隐藏的正文。
5. 蝴蝶效应、传记和族谱引用。
6. 低可靠度推断。

超出预算时:

- 先去重，再按相关度删除完整资料单元。
- 不从句子中间截断。
- 不裁掉来源ID、时间、地点和否定条件。
- 不用另一次AI调用压缩资料。
- 在 `warnings` 中记录被省略的来源类型和数量。

# 十一、来源哈希与缓存

`sourceHash` 至少包含:

- `characterKey`
- `chatId`
- 当前消息数量与最后消息ID
- 当前世界时间地点
- 目标MVU人物摘要
- 命中的世界书条目UID及内容哈希
- 相关本地资料ID及更新时间
- 玩家表单与原始指令
- 蝴蝶效应请求的冻结锚点、`runId`、已确认参考、兼容编号和完整行动哈希

同一 `sourceHash + taskType` 可以复用检索结果，但不能复用模型原始回答。

聊天、世界书、MVU、表单或本地资料变化后，旧 `sourceHash` 立即失效。

# 十二、安全与失败

- 任何API密钥不得进入 `ContextBundle`。
- 读取单一来源失败时记录明确警告；核心来源缺失时停止请求。
- 地点为空的墟境请求直接返回 `LOCATION_REQUIRED`，不启动检索。
- 目标为空的寻根溯源请求直接返回 `TARGET_REQUIRED`。
- 蝴蝶效应冻结快照缺少任意锚点时返回 `ANCHOR_SNAPSHOT_REQUIRED`。
- 蝴蝶效应没有合法 `runId` 或玩家干涉记录时返回 `INVALID_SETTLEMENT_SOURCE`。
- 切换聊天、删除触发楼层或取消请求后，检索结果作废。
- 检索失败不得修改MVU、世界时间、世界书、聊天或本地成品库。
