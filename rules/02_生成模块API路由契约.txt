# 一、适用模块

本契约只管理四个按需调用的生成模块：

- `genealogy`：宗族谱系。
- `ruin`：墟境生成。
- `biography`：寻根溯源。
- `butterfly`：蝴蝶效应结算。

四个模块彼此独立。它们可以全部跟随酒馆插头，也可以分别使用独立API。界面可以把同一份独立API配置应用到全部模块，但运行时仍按模块保存，任何一个模块的修改都不得覆盖其他模块。

# 二、唯一设置结构

脚本变量中的正式结构为：

```json
{
  "schemaVersion": 1,
  "generation": {
    "genealogy": { "mode": "follow_tavern" },
    "ruin": { "mode": "follow_tavern" },
    "biography": { "mode": "follow_tavern" },
    "butterfly": { "mode": "follow_tavern" }
  }
}
```

单个模块只允许以下两种配置。

跟随酒馆：

```json
{
  "mode": "follow_tavern"
}
```

独立API：

```json
{
  "mode": "custom",
  "custom": {
    "apiurl": "https://example.com/v1",
    "key": "",
    "model": "model-name",
    "source": "openai",
    "maxTokens": 4096,
    "temperature": 0.8
  }
}
```

禁止在界面层另外发明 `external`、`baseUrl`、`apiKey`、`inherit` 等别名后直接写入脚本变量。界面展示名称可以本地化，但提交给运行时前必须转换为上述唯一结构。

# 三、酒馆插头路由

使用 `follow_tavern` 时：

1. 通过酒馆助手的 `generateRaw` 发起请求。
2. 调用瞬间使用酒馆插头当前有效的连接、鉴权与模型。
3. 不复制、不覆盖、不持久化酒馆插头配置。
4. 不修改正文模型预设、采样参数或聊天历史。
5. 请求必须静默、非流式，并且不创建聊天楼。
6. 只发送当前模块的系统提示词和经过筛选的当前资料。

# 四、独立API路由

使用 `custom` 时：

1. 仍通过酒馆助手的 `generateRaw` 发起请求，并传入 `custom_api`。
2. `apiurl`、`key`、`model`、`source`、`maxTokens`、`temperature` 由当前模块独立保存。
3. API密钥只保存在脚本私有设置中。
4. API密钥不得进入世界书、正文、MVU、本地资料导出、状态事件或调试日志。
5. 每个请求必须是无历史的独立调用。
6. 玩家可使用“应用到全部模块”复制配置；复制完成后四个模块仍保存各自的完整配置。

# 五、按需装配规则

脚本调用模块时只装配该模块所需规则：

- `genealogy` 只读取宗族谱系规则与共享世界观上下文。
- `ruin` 只读取墟境生成规则、骰表结果与共享世界观上下文。
- `biography` 只读取寻根溯源规则、正文资料与允许引用的传记。
- `butterfly` 只读取蝴蝶效应规则、冻结锚点、骰点结果与相关史料。

未被调用的规则不得进入请求，不消耗上下文Token。

# 六、隔离与失败

每个请求必须拥有独立的：

- `requestId`
- `taskType`
- 输出Schema
- 当前角色卡与聊天命名空间
- 缓存键
- 生命周期校验

禁止复用生成模型聊天历史。禁止把一个模块的原始输出自动附加到另一个模块请求；只有经过脚本筛选和校验的结构化引用可以跨模块使用。

当前路由不可用时：

- 显示明确错误。
- 不得自动切换到另一种路由。
- 不得写入MVU、切换墟境状态或发送残缺正文。
- 玩家修改设置只影响下一次调用，不中断已经开始的请求。

# 七、界面

API来源只在“设置 > API调用”中配置。其他页面不得重复出现端口、密钥和模型控件。

界面必须通过工作台公开方法进行设置：

- `setGenerationSettings(taskType, settings)`：只修改一个模块。
- `applyGenerationSettingsToAll(settings)`：把同一份已校验配置复制到四个模块。

界面不得直接深层修改脚本变量，不得直接调用 `replaceVariables`，也不得把设置写入聊天变量或世界书。

# 八、蝴蝶效应边界

`butterfly` 请求可以与遣返正文并行，但不得阻塞时间控制模块完成遣返。

- API调用前必须已经产生不可变冻结快照。
- API返回后只能进入校验与归档队列。
- API失败不得切换墟境状态、恢复活动字段或回滚世界时地。
- 重试必须使用原路由、原模型、原冻结快照、原骰点与原 `runId`。
