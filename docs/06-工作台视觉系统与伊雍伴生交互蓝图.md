# 工作台视觉系统与伊雍伴生交互蓝图

> 状态：**IMPLEMENTED IN INTERNAL COMPONENT / REAL-HOST DRIVER REVIEW PENDING**
> 日期：2026-09-28
> 当前原型：[`prototype/eyon-companion.html`](../prototype/eyon-companion.html)

## 1. 目标

把现有 48×48 圆形「伊」字入口替换为 `56×56 CSS px` 的伊雍像素伴生角色，并让原本独立悬浮的任务提示成为与角色绑定的轻量气泡。角色承担入口、状态与陪伴感；气泡只承担需要阅读的任务信息，不长期占据聊天界面。

## 2. 冻结边界

- 运行时拖动与点击热区保持 `56×56 CSS px`；动作画面允许以 `64×64 CSS px` 透明画框向四周各溢出少量像素，但不得扩大布局占位或覆盖正文。
- 伊雍是唯一拖动句柄；气泡与角色共用位置根，不独立拖动、不保存第二套坐标。
- 空闲状态不显示气泡。运行、重试、恢复、完成、异常、通知、取消等已有状态需要说明时才出现。
- 动画读取现有 `taskType / phase`，不得制造第二套业务状态机。
- 完整动作切片验证十套“短开场＋稳定微循环”，不直接替换正式入口。
- 角色发丝从黑色连续渐变为白色，蛇首是发尾本身，不画成漂浮的独立蛇。
- 动作采用“微型舞台”而非统一正面站姿：允许转身、蹲坐、短距离奔跑、一次跳跃和夸张情绪特效；书架、地图桌、传送门等背景必须留在单格透明画框内，不得变成独立常驻层。
- 气泡使用透明主题底、单层低对比描边、圆角与最小尾尖；禁止厚重装饰框、永久模糊光晕和多重套卡。
- 尊重 `prefers-reduced-motion`；静止帧必须仍能传达当前状态。

## 4. 状态映射

正式接线时使用已有任务状态，不改业务流程：

| taskType / phase | 角色动作 | 气泡 |
|---|---|---|
| idle / 无活动任务 | 待机 | 隐藏 |
| biography + running/retrying | 阅读整理 | 任务名、当前步骤、可选等待信息 |
| genealogy + running/retrying | 展开族谱卷与亲缘枝线 | 同一气泡组件，不另造面板 |
| ruin + running/retrying | 查看地图与罗盘 | 同一气泡组件，不另造面板 |
| ruin + `status === entering_ruin` | 开启并稳定历史切口 | 提示即将进入所选节点 |
| butterfly + running/retrying | 掌心光蝶与分岔余波 | 同一气泡组件，不另造面板 |
| system + running/retrying | 校准黄铜齿轮 | 同一气泡组件，不另造面板 |
| 工作台开合 UI 事件 | 展开史册与控制页 | 仅作入口反馈，不伪装成后台任务 |
| success / recovered | 线索合拢后跳起庆祝，最终抱卷确认 | 短暂出现，可自动收起 |
| error | 坐地嚎啕、泪瀑与水洼的标志性一次演出 | 保留错误摘要与合法重试入口 |
| cancelled | 回待机 | 短暂确认后隐藏 |

只有业务本身允许取消时才显示停止动作；视觉层不得伪造可取消能力。

墟境的两个动作必须按可靠状态分流：普通 `taskType === ruin` 运行态使用“看地图”，只有明确的 `status === entering_ruin` 使用“开传送门”。禁止通过 `detail.includes(...)` 等自然语言猜测动作；展示文案可以变化，状态路由不能随文案漂移。

## 5. 动作连续性契约

连续性由统一的帧职责、播放阶段与动作切换共同保证：

- 四帧统一定义为：第1帧动作起点，第2帧同一动作的直接中间帧，第3帧完成后的稳定姿势A，第4帧稳定姿势B。第2帧不得是无关摆拍；身体重心、朝向、手臂路径和道具位置必须能顺着读成 `1→2→3`。
- 状态首次进入时只正向播放 `1→2→3` 一次；收到 `eyon-intro` 的 `animationend` 后，视觉层切入 `3→4→3` 的非匀速微循环。取书后只翻页，哭泣后只抽噎，传送门中只蹬腿，不得重新取书、倒吸眼泪或倒着退出传送门。
- 第3、4帧共用身体锚点和场景几何，只允许眨眼、呼吸、肩膀抽动、腿部轻蹬、页面或指针移动等局部变化；禁止把整张角色贴图上下漂浮冒充身体动画。
- 状态切换时冻结旧动作当时的实际图集位移，用约 `190ms` 的旧层淡出/微放大与新层淡入/轻落地完成桥接；过渡后立即清理旧层样式，不保留第二个业务动画计时器。
- 原型中重复点击同一状态可重播开场；正式接线后以任务实例键仲裁，同一任务的进度刷新只更新气泡，不重播开场，新任务实例才从第1帧开始。
- `prefers-reduced-motion` 下不播放开场和微循环，直接展示各动作的第3帧，因此信息不能只存在于中间帧。
- 正式运行时仍只读取现有 `taskType / phase / status`；`intro / loop` 是纯视觉播放阶段，不构成新的业务状态机。

## 6. 交互与宿主边界

- 角色保持宿主级单例，工作台开合、聊天切换与宿主重建不得复制入口。
- 点击角色切换工作台；拖动超过阈值后本次 pointer 序列不触发点击。
- 气泡根据角色所在屏幕半区自动左右翻转，并限制在可视区域内。
- 工作台打开时角色仍可留在界面边缘作为关闭/返回入口；是否采用停靠轨道属于后续成长项。
- 位置只保存角色根坐标；窄屏、缩放和视口变化后重新钳制。
- 所有动态文字使用 `textContent`，模型文本不得通过 `innerHTML` 进入气泡。

## 7. 资源与性能门

- 首选透明索引 PNG 图集；不使用 GIF。
- 每格源帧为 96×96，运行时动作画框显示 64×64、点击热区 56×56；图集总目标 ≤200 KB，硬上限 300 KB。
- 同时只播放当前动作行，隐藏状态不运行额外计时器。
- CSS 帧动画仅改变图集位移；不在每帧触发布局、滤镜堆叠或 JavaScript 重绘。
- 非模糊环境提供实色半透明回退。

## 8. 验收门

### 视觉门（当前）

- 56px 下能识别紫眸、黑白渐变发尾蛇首、白短外套与黑色哥特裙。
- 十组动画的 `1→2→3` 没有跳形、换脸、换装、基线漂移；任务类型、成功与异常不再只靠气泡文案区分。
- 开场只播放一次，随后第3、4帧形成局部微循环；不同动作之间有短交叉过渡，不出现硬切、整段重播或倒放剧情。
- “生成墟境”一眼可读为看地图，“进入墟境”一眼可读为打开传送门，两者不得复用同一动作。
- 气泡清楚但不抢正文，空闲时完全消失，拖动时始终绑定。
- 桌面和窄屏都不把角色或气泡挤出可视区。

### 正式接线门（已实施）

- 替换 loader 与源码入口，不保留第二个圆形启动器。
- 复用现有宿主状态事件与取消能力；不改变任务执行、通知和恢复语义。
- build/typecheck/现有测试通过，产物资源预算通过。
- 交给真实 SillyTavern 验证单例、拖动、聊天切换、工作台开合、任务全阶段、320px 窄屏与减少动态效果。

## 9. 当前未声称通过的边界

- 十组动作、透明气泡、单例入口、状态投影、视口钳制与持久化拖动已接入正式源码与内测 loader。
- 旧的独立「伊」字启动球已从 loader 移除；伊雍小人是唯一工作台入口，拖动小人本体即移动根节点。
- 尚未取得真实 SillyTavern 的 computed style、生命周期或移动端证据。
- 自动化与离线原型不能替代驾驶员对真实拖动、工作台开合、长任务切阶段和窄屏边界的接受。
