# 一、目标

本契约规定悬浮球和完整面板如何只读显示:

- 当前流程状态。
- 进入墟境前的现实时地。
- 进入时墟境时地。
- 当前墟境时地。
- 离开时墟境时地。
- 最近完成的归档。
- 当前聊天的蝴蝶效应锚定日志。
- 当前聊天尚未完成的蝴蝶效应结算状态。

面板不参与状态判定、时间同步、归档生成或世界书写入。

# 二、唯一来源

## 2.1 MVU

- `墟境系统.运行状态`
- `墟境系统.虚嗣指南快照`
- `世界.时间`
- `世界.地点`

禁止使用:

- `事件.伊雍`
- 旧消息楼层变量
- 本地候选草稿
- API生成结果
- 面板上一次渲染缓存

这里的“禁止API生成结果”是指禁止用API结果判断或恢复墟境状态。蝴蝶效应内容只有经过校验、提交并成为当前聊天正式归档后，才允许进入档案列表。

## 2.2 蝴蝶效应世界书

读取当前聊天对应的伊雍蝴蝶效应归档世界书。

实际日志必须满足:

`entry.extra.source === "eyon_butterfly_anchor"`

规则模板、骰表、任务规则和普通世界书条目不得进入档案列表。

# 四、原子时地对

时间和地点必须作为一个原子对读取。

有效时地对要求:

- 时间和地点来自同一个对象层。
- 两者同时非空。
- 两者属于同一 `runId` 或 `archiveRunId`。

禁止:

- 使用快照时间搭配运行状态地点。
- 使用当前墟境时间搭配归档墟境地点。
- 使用上一个轮次的进入点搭配本轮当前点。
- 单独显示无法确认配对的时间或地点。

只有一项存在时，本组显示“数据尚未完整同步”，不得跨源补齐。

# 五、状态读取

## 5.1 主状态

优先读取:

`墟境系统.虚嗣指南快照.flowState`

同时核对:

`墟境系统.运行状态.墟境流程状态`

允许值:

- `idle`
- `exploring`
- `anchored`
- `returning`

两者不一致时:

- 不自行判断谁正确。
- 显示快照状态。
- 添加 `STATE_MISMATCH` 警告。
- 不因不一致写回任何变量。

未知值统一显示“状态同步中”，不得猜测为 `idle`。

## 5.2 轮次

- 活动轮次优先 `虚嗣指南快照.runId`，回退 `运行状态.墟境轮次`。
- 归档轮次优先 `虚嗣指南快照.archiveRunId`，回退 `运行状态.归档轮次`。
- 快照与运行状态轮次不一致时，不跨轮次拼接字段。

# 六、活动框体读取

## 6.1 现实锚点

在 `exploring|anchored|returning` 中依次尝试完整时地对:

1. `虚嗣指南快照.lockedRealTime + lockedRealLocation`
2. `运行状态.本轮现实时间 + 本轮现实地点`
3. `运行状态.墟境进入前时间 + 墟境进入前地点`

不得使用 `lastRealityTime` 覆盖已经存在的锁定现实锚点。

在 `idle` 中:

- “当前现实”直接读取 `世界.时间 + 世界.地点`。
- 活动“现实锚点”框体为空。

## 6.2 墟境进入点

仅在 `exploring|anchored|returning` 中依次尝试:

1. `虚嗣指南快照.entryRuinTime + entryRuinLocation`
2. `运行状态.本轮墟境进入时间 + 本轮墟境进入地点`

进入点一旦建立，只负责显示，不随 `ruinCurrent` 推进。

## 6.3 墟境当前点

仅在 `exploring|anchored|returning` 中依次尝试:

1. `虚嗣指南快照.ruinTime + ruinLocation`
2. `运行状态.墟境当前时间 + 墟境当前地点`

此框允许随MVU每楼推进。

面板不得把它写入现实锚点，也不得用进入点覆盖当前点。

## 6.4 墟境离开点

在活动轮次中依次尝试:

1. `虚嗣指南快照.exitRuinTime + exitRuinLocation`
2. `运行状态.本轮墟境离开时间 + 本轮墟境离开地点`

在尚未遣返时，该值可能与当前点相同或为空。面板只忠实显示，不据此判断玩家已经遣返。

# 七、归档框体

归档字段独立于活动字段。

优先从同一个 `虚嗣指南快照.archiveRunId` 读取:

- `archiveRealTime + archiveRealLocation`
- `archiveEntryRuinTime + archiveEntryRuinLocation`
- `archiveExitRuinTime + archiveExitRuinLocation`

快照归档不完整时，整体回退到同一个 `运行状态.归档轮次`:

- `归档现实时间 + 归档现实地点`
- `归档墟境进入时间 + 归档墟境进入地点`
- `归档墟境离开时间 + 归档墟境离开地点`

禁止逐字段混合快照归档与运行状态归档。

活动轮次开始后，旧归档仍可在“最近归档”区域查看，但不得填入新轮次的活动框体。

# 八、idle显示

`idle` 时:

- 显示当前现实世界时地。
- 活动轮次为空。
- 现实锚点、墟境进入、当前和离开框体显示为空态。
- 最近归档单独保留。
- 蝴蝶效应档案继续可读。

不得因为最近归档仍存在而把状态显示为 `returning` 或 `exploring`。

# 九、蝴蝶效应档案读取

## 9.1 世界书定位

优先复用现有蝴蝶效应归档模块提供的当前聊天世界书解析器。

不得在面板另写一套可能漂移的命名规则。合并成单脚本后，归档写入器与面板读取器必须调用同一个 `resolveArchiveWorldbookName(chatId)`。

世界书是当前聊天归档的注入镜像，本地IndexedDB是结构化原稿来源。面板正文入口读取世界书镜像；结算状态读取当前聊天本地请求仓库。两者都必须以同一 `characterKey + chatId` 过滤。

## 9.2 条目筛选

读取 `getWorldbook(worldbookName)` 后:

1. 过滤 `extra.source === "eyon_butterfly_anchor"`。
2. 过滤 `extra.chat_id !== currentChatId`。
3. 过滤无正文条目。
4. 按 `extra.message_id` 从小到大排序。
5. 使用 `uid` 作为世界书条目稳定标识。
6. 使用 `extra.run_id` 关联墟境轮次。

模板条目即使标题包含“蝴蝶效应”，只要没有来源标记，也不得显示。

## 9.3 面板字段

每条档案保存到视图模型:

```json
{
  "uid": 0,
  "title": "《蝴蝶效应锚定日志1》",
  "content": "世界书原始正文",
  "keywords": [],
  "messageId": 0,
  "runId": "",
  "enabled": true
}
```

列表摘要可以从已有结构化表格中提取:

- 波及范围。
- 现世落点。
- 可感知证据。
- 墟境行动记录。
- 历史演变。

解析摘要失败时仍保留完整正文入口，不修改世界书内容。

## 9.4 数量

面板档案数量以过滤后的实际世界书条目数为准。

不得读取已被清空或不稳定的MVU“锚定总录”计数来代替。

## 9.5 待结算记录

从当前聊天本地请求仓库只读筛选:

```text
taskType === "butterfly"
status === "pending_settlement"
characterKey === currentCharacterKey
chatId === currentChatId
```

只显示:

- 对应 `runId`。
- 遣返触发楼层。
- 失败原因摘要。
- 冻结快照是否完整。
- “重试历史结算”按钮。

不得在面板展示冻结快照全文、API原始响应、提示词或内部错误堆栈。

点击重试只调用现有蝴蝶效应归档模块，不得由只读面板自行拼装请求。

# 十、刷新时机

以下事件触发只读刷新:

- 面板首次打开。
- 当前聊天变化。
- MVU变量更新结束。
- 蝴蝶效应归档队列完成。
- 世界书内容更新。
- AI消息删除、编辑或重roll后归档模块完成校准。
- 当前聊天蝴蝶效应请求进入或离开 `pending_settlement`。

刷新必须防抖，并使用递增 `readRevision`。

旧刷新晚于新刷新返回时必须丢弃，不能覆盖当前聊天面板。

禁止持续高频轮询世界书。

# 十一、加载与错误

## 11.1 加载

- 状态框体和档案列表分别加载。
- 世界书读取较慢时不阻塞当前时地显示。
- 加载过程中保留骨架，不显示上一个聊天的数据。

## 11.2 空态

- 没有活动墟境: “当前未处于墟境探索”。
- 没有归档: “尚无已完成墟境归档”。
- 没有蝴蝶效应条目: “尚无蝴蝶效应锚定日志”。
- 有待结算记录: 单独显示“历史结算待重试”，不得把它计入已归档数量。

## 11.3 错误

- 世界书不存在: 显示空档案，不自动创建。
- 世界书读取失败: 显示可重试错误，不影响MVU状态框。
- MVU根变量不存在: 显示“墟境状态尚未初始化”，不读取旧路径。
- 字段冲突: 显示警告，不自动修复。

# 十二、界面框体

完整状态页推荐顺序:

1. 流程状态与活动轮次。
2. 当前现实或进入前现实锚点。
3. 墟境进入点。
4. 墟境当前点。
5. 墟境离开点。
6. 最近归档。
7. 蝴蝶效应档案。
8. 待结算提示，仅在存在时显示。

每个时地框体固定显示:

- 标题。
- 时间。
- 地点。
- 数据状态。

移动端按同一顺序单列排列。不得通过缩小字体把多个长地点强塞在一行。

# 十三、只读保证

面板加载、刷新与选择档案的只读过程禁止调用:

- `replaceVariables`
- `updateVariablesWith`
- `replaceWorldbook`
- `updateWorldbookWith`
- `createWorldbookEntries`
- `deleteWorldbookEntries`
- `setChatMessages`

允许的写操作只来自现有时间控制模块、蝴蝶效应归档模块，以及玩家明确确认的“删除档案”命令。
删除档案只清理当前聊天对应的本地档案、待结算快照与世界书镜像；不得删除正文楼层，不得触发 Canon 回滚。
世界书或镜像条目已经不存在时，删除命令必须幂等成功，不得因镜像缺失阻止本地档案清理。

# 十四、禁止行为

- 禁止从面板缓存恢复 `exploring`。
- 禁止根据存在归档日志推断当前正在墟境。
- 禁止把蝴蝶效应模板显示成真实日志。
- 禁止跨聊天合并蝴蝶效应条目。
- 禁止跨轮次拼接时地字段。
- 禁止在世界书读取失败时退回旧 `事件.伊雍`。
- 禁止面板刷新触发API生成、正文生成或变量解析。
- 禁止把 `pending_settlement` 显示成已完成日志。
- 禁止因为后台结算仍在运行而阻塞当前现实状态显示。
