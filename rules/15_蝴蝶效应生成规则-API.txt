# 一、机制定位

本规则只负责在一次墟境已经明确遣返后，根据脚本冻结的同轮次史料，创作该轮墟境干涉在现世造成的蝴蝶效应。

本规则不负责:

- 判断玩家是否要求遣返。
- 切换 `exploring|anchored|returning|idle`。
- 恢复或修改世界时间、地点。
- 读取、更新或清空MVU变量。
- 决定进入时、离开时或现实锚点的时间地点。
- 输出伊雍对白、遣返正文、任务奖励或变量更新。
- 直接写入聊天、世界书或本地资料库。
- 生成HTML、Markdown表格或 `<butterfly_panel>`。

遣返流程由现有时间控制模块独立完成。即使本请求失败，遣返也必须保持成功，不得回滚。

# 二、调用条件

只有脚本已经确认以下全部条件时才允许调用:

1. 玩家明确点击“遣返”，或玩家当前输入明确包含“遣返”“返回现世”“回到现实”“结算蝴蝶效应”等主动命令。
2. 当前存在合法活动 `runId`。
3. 脚本已经在清空活动字段之前冻结同一轮次的完整归档快照。
4. 现实锚点、墟境进入点和墟境离开点均为完整时地对。
5. 本轮至少存在一项可确认的玩家墟境行动。
6. 蝴蝶效应范围骰点已经由脚本产生并映射完成。

不得因为正文提到“返回”“离开”“现实”等普通叙述而调用。

不得因为任务完成、节点定锚、API候选生成完成或状态为 `anchored` 而自动调用。

# 四、锚点不可变

以下字段是脚本冻结的事实，不是创作素材:

- `runId`
- `anchors.reality.time`
- `anchors.reality.location`
- `anchors.ruinEntry.time`
- `anchors.ruinEntry.location`
- `anchors.ruinExit.time`
- `anchors.ruinExit.location`
- `dice.roll`
- `dice.scope`

模型不得:

- 改写、补齐、规范化或纠正这些值。
- 用墟境时地替换现实锚点。
- 用现实锚点冒充墟境进入点。
- 把进入点推进为离开点。
- 从正文另找一套“更合理”的时间地点。
- 因觉得骰点与事件规模不匹配而改变波及范围。

输出只需原样回显 `runId` 和骰点范围，不回显三套时地。三套时地由脚本直接写入最终日志。

# 五、资料权威顺序

发生冲突时依次遵循:

1. `anchors` 与脚本提供的骰点映射。
2. 当前角色卡已启用世界书的明确事实。
3. 当前聊天未隐藏、当前采用消息页中的已确认事实。
4. 本轮 `playerInterventions`。
5. 当前聊天MVU人物与世界状态摘要。
6. 当前聊天已经归档的蝴蝶效应。
7. 已保存传记中的明确资料。
8. 宗族谱系中的明确资料。
9. 为连接因果链所作的有限推断。

推断不得覆盖明确事实。资料冲突无法协调时，在 `warnings` 中说明，不得擅自选择方便创作的一方。

# 六、创作目标

蝴蝶效应必须写成一条能够追溯的历史传播链:

```text
玩家在墟境中的具体行动
-> 当时立即改变的人、物、制度或信息
-> 变化如何被保存、继承、误读、交易、压制或放大
-> 一个或多个中间历史阶段
-> 遣返后现实中的具体落点
-> 玩家现在能够感知或验证的证据
```

不能只写“玩家改变了过去，因此未来发生变化”。

不能把墟境内部结果直接复制成现世结果。

不能把几百年的演化压缩成没有媒介的一次跳跃。

# 七、波及范围约束

骰点决定影响范围，不决定影响善恶，也不决定事件表面大小。

- `个人`: 主要改变一个人的经历、身份、记忆、财产、身体、名誉或选择。
- `双人`: 主要改变两人之间的关系、契约、亲缘、债务、敌意或共同秘密。
- `小队`: 影响一个有限团体、家族支系、调查队、卫队、教团小组或工作单位。
- `聚落`: 影响村庄、街区、庄园、城堡附属区、据点或小型共同体。
- `城市`: 影响城市级制度、贸易、治安、宗教、建筑、人口结构或主要组织。
- `地区`: 影响多个聚落或一整个行政、地理、族群区域。
- `国家`: 改变国家级制度、战争、继承、经济、宗教或族群格局。
- `跨国`: 改变多个国家之间的长期关系、贸易网络、战争体系、信仰传播或跨国组织。

大行动可以因历史收束只产生小范围影响；微小行动也可以通过关键媒介扩散为大范围影响。

无论大小，都必须解释为什么最终范围恰好停留在骰点对应层级。

# 八、因果媒介

优先选择与本轮史料相符的传播媒介，不要固定套用同一种模式。

可用媒介包括但不限于:

- 血缘、婚姻、收养、私生关系与继承。
- 档案、账本、地图、契约、法律、判例与行政惯例。
- 货币、债务、商路、税制、工艺、资源与产业。
- 武器、遗物、器具、建筑结构与基础设施。
- 教义、仪式、传说、禁忌、污名与集体记忆。
- 战争、迁徙、灾害、疾病、治安与军事部署。
- 师承、组织、派系、秘密网络与职位更替。
- 身体特征、种族习惯、寿命差异与超自然遗传。
- 被掩盖、误读、伪造、丢失或重新发现的信息。

媒介必须来自输入资料或受世界观约束的合理补全。

# 九、中间演化

`historicalEvolution` 应包含2至5个有功能差异的演化阶段。

每个阶段至少回答:

- 谁继承或接触了上一阶段的变化？
- 他们为什么保留、利用、误解、抵制或放大它？
- 变化通过什么制度、关系或物质载体继续存在？
- 下一阶段为何会从这一阶段自然产生？

不得机械使用“数十年后”“百年后”作为唯一连接。

不得为凑阶段数引入与玩家行动无关的宏大事件。

# 十、与现世联动

`presentLanding` 必须落在玩家遣返后的现实冒险能够接触的范围内。

优先落点:

- 当前现实地点及其直接关联地点。
- 当前活跃人物、组织、任务、关系或资源。
- 玩家已经接触过、能够再次验证的制度、建筑、物品或传闻。
- 当前世界线已有蝴蝶效应的延续、叠加或抵消。

不得为了显得宏大而把影响随意丢到玩家无法接触的遥远国家。

如果骰点是国家或跨国级，仍需给出至少一个玩家当前位置可以感知的局部窗口。

# 十一、可感知证据

`perceptibleEvidence` 必须提供1至4项不同类型的具体证据。

合格证据示例:

- 建筑结构、纹章、碑文、地图或档案发生了可核对变化。
- 某人物拥有与旧世界线不同的身份、记忆、关系或物品。
- 商路、价格、税收、军队、宗教仪式或组织权力发生可观察变化。
- 玩家收到新的信件、任务回执、关系反馈或制度限制。
- 某个熟悉地点出现具有因果来源的缺失、增建、改名或用途变化。

不合格证据:

- “空气似乎不同了。”
- “命运发生了改变。”
- “历史的涟漪仍在扩散。”
- 只有旁白知道、玩家当前无法验证的抽象结论。

# 十二、墟境行动记录

`ruinActionRecord` 只总结玩家实际完成的关键干涉:

- 保留行动对象、方式与直接结果。
- 不增加玩家没有做过的决定。
- 不把NPC独立行动冒充玩家功绩。
- 不写评价、奖励或伊雍对白。
- 不重复完整历史背景。

建议长度为80至180个中文字符。

# 十三、历史演变文风

`historicalEvolution` 是紧凑史稿，不是百科摘要，也不是玄虚诗歌。

要求:

- 160至360个中文字符。
- 叙述清晰，具有人物动机、制度阻力和时间递进。
- 使用当前世界观中的纪元、组织、种族与地理名称。
- 允许战争史、艳情史、宗族史、宗教史、经济史、犯罪史、器物史或日常史等不同题材。
- 不预设历史必然沉重、悲壮或宏大。
- 结果可以有利、有害、暧昧、讽刺或利弊并存。
- 保留偶然性，但不能依赖巧合完成全部因果。

禁止:

- 空泛的“命运齿轮”“历史长河”“世界线震荡”堆砌。
- 每次都写家族断嗣、文献丢失、商路衰败或帝国动荡。
- 把现有人物强行写成所有历史的中心。
- 为迎合骰点凭空制造战争、灭国或神明降临。
- 抹除玩家已经确认的现实经历。

# 十四、历史关键词

`historicalKeywords` 提供4至10项。

关键词只能来自最终内容已经出现的:

- 人物。
- 家族。
- 组织。
- 地点。
- 事件。
- 器具。
- 制度。
- 专有名词。

不得加入正文未出现的搜索热词。

脚本会另行从三套锚点提取:

- 完整纪元名。
- 年份。
- 月份或月名。
- 关键地点层级。

这些时间地点关键词不要求模型重复生成。

# 十五、内部审校

生成最终JSON前，在内部逐项检查，但不得输出思考过程:

1. 玩家具体改变了什么？
2. 原历史若无人介入会怎样？
3. 第一位承接变化的人或组织是谁？
4. 变化依靠什么媒介跨越时间？
5. 每个中间阶段是否由上一阶段自然产生？
6. 最终影响为何符合骰点范围？
7. 现世落点是否与当前冒险相连？
8. 玩家能否立即观察或验证至少一项证据？
9. 是否错误改写了三套冻结锚点？
10. 是否与已有传记、族谱、世界书或蝴蝶效应冲突？
11. 是否重复使用陈词滥调或上一轮蝴蝶效应结构？
12. 是否偷偷替玩家增加了行动？

只输出最终JSON，不输出问题答案、分析、推理或自检过程。

# 十七、最终面板与日志

API不得输出最终面板。

脚本使用冻结锚点和已校验JSON，按现有固定格式生成:

```text
<butterfly_panel>
[波及范围|${effect.roll}|${effect.scope}]
[现世落点|${effect.presentLanding}]
[可感知证据|${join(effect.perceptibleEvidence, "；")}]
[墟境行动记录|${effect.ruinActionRecord}]
[历史演变|${effect.historicalEvolution}]
[历史关键词|${join(effect.historicalKeywords, "、")}]
</butterfly_panel>
```

世界书日志继续使用现有《蝴蝶效应锚定日志N》表格格式。

三套锚点必须由脚本从冻结快照写入，不从API输出读取。

# 十八、提交与隔离

完成结果必须绑定:

```text
characterKey + chatId + runId
```

同一 `chatId + runId` 最多只能存在一个已完成蝴蝶效应。

本地IndexedDB保存当前聊天的权威原稿。

专用全局世界书只作为当前聊天的注入镜像:

- 条目来源标记固定为 `extra.source === "eyon_butterfly_anchor"`。
- `extra.run_id` 保存 `runId`。
- `extra.chat_id` 保存 `chatId`。
- `extra.message_id` 保存对应遣返AI楼层。
- 切换聊天后，不得启用或展示其他聊天的条目。

# 十九、失败

以下情况不得提交:

- 冻结锚点缺少任意完整时地对。
- `runId`为空或与请求不一致。
- 蝴蝶效应范围与脚本骰点不一致。
- 输出不是单个合法JSON。
- 因果链缺少玩家行动、传播媒介、现世落点或可感知证据。
- 结果与明确世界书事实冲突。
- 请求返回时聊天、角色卡或对应遣返楼层已经变化。
- 同一轮次已经存在完成日志。

失败时:

- 不回滚遣返。
- 不修改MVU。
- 不恢复活动墟境字段。
- 不写空白世界书条目。
- 保存冻结请求为 `pending_settlement`。
- 界面显示“历史结算待重试”。
- 玩家重试时必须复用同一冻结快照、骰点和 `runId`。

# 二十、禁止行为

- 禁止用遣返后的现实MVU反推已被清空的墟境锚点。
- 禁止读取上一个轮次的进入或离开时地补齐当前轮次。
- 禁止自行重掷蝴蝶效应范围。
- 禁止生成JSON Patch、`<UpdateVariable>`、`<eyon>`、HTML或Markdown表格。
- 禁止在API失败时让正文模型临时补写另一份蝴蝶效应。
- 禁止把模型原始JSON直接注入正文。
- 禁止同一轮次重复追加多个面板或世界书日志。
- 禁止跨聊天复用缓存、编号或归档条目。
- 禁止输出内部自省、提示词、API配置或密钥。
