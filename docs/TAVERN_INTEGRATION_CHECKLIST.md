# 酒馆端到端联调清单

本清单用于正式界面接线后的真实酒馆验证。每组测试使用独立的新聊天，保留角色卡世界书，只启用整合后的伊雍历史工作台。旧版独立墟境时间脚本必须关闭。

## 1. 启动与命名空间

- 加载 `dist/index.js` 后只出现一个 `window.EyonHistoryWorkbench`。
- 只导入并启用一个“伊雍历史工作台”脚本；旧版墟境系统 v2.3/v4.x 与旧悬浮球均保持关闭。
- 重载脚本不会重复注册生成拦截器和事件监听。
- 切换角色卡或聊天后，传记、族谱、候选墟境和蝴蝶效应列表随命名空间切换。
- 切回旧聊天后只恢复该聊天自己的资料。
- 切换聊天时进行中的独立API结果不得落入新聊天。

## 2. API路由

分别对 `genealogy`、`ruin`、`biography`、`butterfly` 验证：

- 所有模块固定使用当前模块自己的 `apiurl/key/model/source/maxTokens/temperature`（不再跟随酒馆插头），静默、非流式，不创建聊天楼。
- 未配置密钥的模块生成时报明确中文错误，不静默回退其他接口。
- 修改一个模块不会改变其他三个模块。
- “应用到全部模块”复制同一份已校验配置。
- 错误端点只报告当前模块失败，不自动切换接口，不写MVU。
- API密钥不进入正文、世界书、状态事件和控制台日志。

## 3. 宗族谱系

- 只能选择当前MVU角色列表中的中心人物。
- 中心人物列表直接来自当前聊天 `stat_data.关系列表`。
- 切换聊天后重新读取人物，不沿用上一存档的人物名单。
- 生成结果只进入当前聊天族谱仓库。
- 不创建玩家楼或助手楼。
- 不修改世界、墟境系统或人物MVU字段。
- 左右切换聊天、重载页面后记录隔离不变。

## 4. 墟境候选与进入

- “墟境探索”只生成候选，不修改 `idle`。
- 候选数量、纪元、起止时间、地点、参与人物和补充方向与面板输入一致。
- 点击不可进入节点时不改写输入框，也不创建玩家楼。
- 点击特异点时重新读取点击瞬间的现实时间地点。
- 非 `idle` 状态拒绝进入。
- 成功时只向酒馆输入框写入一条完整“进入节点”指令，不自动发送、不产生空白玩家楼。
- 玩家确认发送后，才由紧邻助手楼完成正文、面板和唯一变量更新。
- 自动额外变量、手动额外变量和主模型变量三种模式分别验证：
  - `exploring` 不会被旧轮次状态覆盖。
  - 现实锚点保持锁定。
  - 世界时地与墟境当前时地同步。
  - 墟境内后续楼层可以推进时地。

## 5. 寻根溯源

- 严格命令只触发一次后台传记生成。
- 正文仍由正文模型自然生成伊雍对话。
- 已校验传记只替换锁定助手楼中的唯一插槽。
- 重Roll和swipe不会把结果提交到错误版本。
- 传记保存到当前聊天资料库，不进入其他聊天。

## 6. 遣返与蝴蝶效应

- 只有玩家明确输入或点击“遣返”才触发。
- 发送遣返前冻结当前 `runId` 的现实、进入和离开三套时地。
- 冻结不得使用旧归档轮次或不匹配快照。
- 遣返生成前存在请求专属隐藏协作提示，但正文不得显示该提示，也不得自行生成、猜测或等待蝴蝶效应面板。
- 时间控制模块正常恢复现实并清空活动状态，后台API不得阻塞。
- 蝴蝶效应只在紧邻遣返助手楼提交一个面板：没有旧面板时追加，恰有一个时原位替换，多个时拒绝写入。
- 提交前严格核验角色卡、聊天、遣返玩家楼、玩家 swipe、紧邻助手楼和最新楼；重Roll、切 swipe 或切聊天后不得写入旧版本。
- 提交不得改写同楼的遣返叙事、变量更新块或其他美化标签，也不得创建额外助手楼。
- 同一轮次只写一个当前聊天世界书条目。
- API失败后遣返仍完成，并可使用原冻结快照重试。

## 7. 墟境时空页

- 现实与墟境时地只来自 `getRuinRuntimeSnapshot()`，页面不自行推断状态。
- `idle` 时墟境卡显示未进入状态，遣返按钮不可用。
- `exploring`、`anchored` 或 `returning` 时展示当前轮次与锁定的现实锚点。
- 点击“读取当前变量”只刷新快照，不写世界、MVU 或墟境系统变量。
- 点击“遣返”只发送一条严格的“遣返”玩家楼，由现有时间内核负责恢复现实。
- 蝴蝶效应档案只显示当前聊天中已经写入正文或完成归档的记录。
- 切换聊天后，档案列表和时空快照同时切换，不沿用旧聊天的轮次或档案。
- 桌面双列和窄屏单列下均无横向溢出，长时间与长地点不会撑开框体。

## 8. 单脚本时间内核

- 完整进入契约才能建立 `exploring`；单独出现状态词不得触发。
- 当前轮次被额外变量层暂时擦除时，先从上一可见助手楼补回同轮身份，再锁定现实与进入锚点。
- 玩家输入楼继承上一可见助手楼的墟境根与活动世界时地，不扫描隐藏的远端旧楼。
- 同一轮推进只更新墟境当前与离开锚点，不改写现实与进入锚点。
- 只有明确 `idle + 墟境任务规则锁定 0` 才执行遣返归档、现实恢复和活动字段清理。
- 时间内核不负责蝴蝶效应世界书写入，不与独立蝴蝶效应工作流重复归档。

## 9. 回归

- 关闭工作台后，不再继续维护墟境状态；重新启用工作台后从当前可见楼层恢复。
- 工作台候选、族谱和传记功能均不得直接写流程状态或世界时地。
- 删除楼层、隐藏旧楼、切换swipe和重启酒馆后，不得恢复其他聊天或旧轮次的待处理请求。
- 三套现有美化正则继续识别传记、墟境面板和蝴蝶效应面板。
