# 唯一数据源

- 运行数据根: `墟境系统.运行状态`
- 展示快照根: `墟境系统.虚嗣指南快照`
- 世界当前时间: `世界.时间`
- 世界当前地点: `世界.地点`
- 禁用旧路径: `事件.伊雍`

# 所有权

- 现有时间控制/MVU模块是状态写入与世界时地同步的唯一权威。
- 历史生成API、宗族谱系API、传记书库和候选节点界面全部只读。
- 新界面不得根据文本语义自行推断或修复 `idle/exploring/returning`。
- 本契约不改变已经稳定运行的进入锚点、离开锚点、归档和清空流程。

运行状态:

- `墟境流程状态`
- `墟境任务规则锁定`
- `墟境轮次`
- `墟境当前时间`
- `墟境当前地点`
- `本轮墟境进入时间`
- `本轮墟境进入地点`
- `本轮墟境离开时间`
- `本轮墟境离开地点`
- `本轮现实时间`
- `本轮现实地点`
- `归档轮次`
- `归档现实时间`
- `归档现实地点`
- `归档墟境进入时间`
- `归档墟境进入地点`
- `归档墟境离开时间`
- `归档墟境离开地点`

界面优先显示 `虚嗣指南快照` 中经时间脚本整理的对应值；快照字段缺失时，才回退到 `运行状态`，不得跨楼搜索旧墟境。

# 状态显示

- `idle`: 未探索。候选生成器可用；当前墟境区域为空。
- `exploring`: 墟境探索中。显示轮次与当前墟境时地。
- `anchored`: 已定锚，等待玩家后续选择。
- `returning`: 遣返结算中，不允许生成新的进入指令。

# 轮次隔离

- 候选生成请求使用独立 `requestId`，不得拿它替代 `墟境轮次`。
- UI缓存键必须包含聊天标识与 `requestId`。
- 进入后才把选中候选与当前 `墟境轮次` 建立关联。
- `墟境轮次` 变化时，旧候选只可查看，不可直接再次进入。
- 状态回到 `idle` 后，清除“当前选中节点”，但保留传记书库和族谱缓存。

# 写入例外

本历史系统自身不直接写MVU。进入与遣返经脚本注入层(常驻注入, depth 0 / system)与唯一玩家楼触发:

- 进入: 脚本把「进入节点 + 单楼进入契约 + 已选历史阶段的唯一 RuinTrace」注入上下文,并以玩家原话(或默认语)建立唯一玩家楼触发正文;缘起、经过、高潮与结果均可进入，内部 `anomaly` 仅作旧存档兼容；注入层在目标助手楼渲染后清理。
- 玩家生成时可以填写地点简称；进入契约中的目标地点必须是 `${大陆名+方位}-${势力/区域}-${子级势力}-${聚落/地标}-${区位}-${详细位置}` 形式的 4～8 层路径。`墟境当前地点`、`本轮墟境进入地点` 与 `世界.地点` 必须逐字复制同一目标地点，不得分别概括。
- 遣返: 玩家主动选择时发送 `遣返` 玩家楼。

`墟境探索`的候选生成只发生在后台和界面，不发送候选确认楼，不改变流程状态。

随后由正文模型和现有MVU规则产生变量更新。
