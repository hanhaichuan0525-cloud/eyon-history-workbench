# 伊雍历史工作台安装说明

## 环境

- SillyTavern 与酒馆助手（Tavern Helper）；
- 对应版本的《命定之诗》角色卡与世界书；
- 若使用独立生成接口，请在本地设置页填写接口信息。密钥不会随备份导出。

## 安装方式 A：β1 自动更新脚本（推荐，当前工作台 β1.5）

1. 停用旧原生扩展、旧内嵌整合脚本；不要重复启用两个工作台。
2. 在酒馆助手脚本管理中导入 `release/酒馆助手脚本-伊雍历史工作台-β1.json` 并启用。
3. 完整刷新酒馆，进入角色卡；单击伊雍悬浮球打开工作台，核对界面为 β1.5（数字更新协议 0.13.3）。
4. 四份正文正则仍需单独导入或启用，它们不会由此加载器自动更新。

已导入 β1 的用户，工作台代码在脚本下次重新执行时自动读取远端版本，无需每次重新导入；保持页面打开不即时热更新。CDN/网络失败会回退旧的已验证缓存，故以界面版本为准。加载器自身的宿主解析、弹层尺寸与后台恢复修复不能靠下载 bundle 覆盖，仍应重新导入最新 β1 JSON 一次。离线内嵌包不自动更新。

远端清单与代码来自此 GitHub 仓库经 jsDelivr 分发。SHA-256 只检查文件与清单一致，不是签名认证，也不能防止仓库或分发渠道本身被篡改；请仅使用信任的仓库。

## 安装方式 B：SillyTavern 扩展版（历史候选，非推荐通道）

1. 在扩展管理页选择“安装扩展”，粘贴 `https://github.com/hanhaichuan0525-cloud/eyon-history-workbench`。
2. 必须保留 Git 仓库安装形态；下载 ZIP 或只复制 `dist/` 不会提供可靠的更新路径。
3. 保持 `extensions.autoUpdate` 开启。酒馆会按自身更新周期管理扩展；需要立即检查时可在扩展管理页手动更新。
4. 启用扩展并重载页面，确认工作台能打开。扩展版会使用仓库中的 `dist/index.js` 与 `dist/workbench.js`，设置落在 SillyTavern 扩展命名空间，资料仍按角色卡与聊天隔离。
5. 不要同时启用下方 JSON 脚本版；两者会重复注册生命周期监听器。

扩展版的“自动更新”不是每次启动强制联网拉取；断网时继续使用当前版本，更新失败也保留旧版本。当前 0.11.0 只完成静态契约与本地构建验收，尚未在真实酒馆扩展管理器中安装验收。

## 安装方式 C：离线内嵌脚本（当前 0.13.3）

1. 关闭旧版“伊雍墟境系统”脚本、旧悬浮球和同名旧版正则，避免重复监听。
2. 在酒馆助手脚本管理中导入 `酒馆助手脚本-伊雍历史工作台-v0.13.3.json`。这是固定代码包，不自动更新。
3. 在 SillyTavern 正则扩展中依次导入发布包 `regex/` 下的四个 JSON 文件并启用。
4. 重新载入当前聊天；页面应只出现一个伊雍像素伴生体。单击她即可打开工作台。
5. 首次使用前打开设置页，确认当前聊天、角色卡、世界书与 MVU 状态均能读取。

## 最短冒烟测试

1. 生成一篇短传记，确认标题跨度与每个时期标题都显示年份。
2. 生成宗族谱系，确认节点与连线正常，右键菜单贴近目标节点。
3. 生成一个墟境，分别点选四阶段中的任意节点，确认进入时间与选中节点一致，地点写回为完整 MVU 路径。
4. 在墟境内生成任务，编辑并确认；重抽正文时任务文本应保持不变。
5. 明确遣返，确认现实锚点恢复、蝴蝶效应在后台完成且归档面板能把 `<user>` 显示为当前玩家名。

## 校验下载

发布页提供 `SHA256SUMS.txt`。PowerShell 可执行：

```powershell
Get-FileHash -Algorithm SHA256 -LiteralPath '.\酒馆助手脚本-伊雍历史工作台-β1.json'
```

将结果与清单中的对应条目比较。资源许可见 [`ASSET_LICENSE.md`](../ASSET_LICENSE.md)，第三方声明见 [`THIRD_PARTY_NOTICES.md`](../THIRD_PARTY_NOTICES.md)。
