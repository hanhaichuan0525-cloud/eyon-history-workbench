## 1. 这份索引解决什么

项目经历多次转手后，历史蓝图、迁移审计、实施记录与现行合同同时留在 `docs/`，导致“旧方案仍像待办”“已实现能力仍写成未实施”“同一职责存在两种设计”。本索引把权威链收束为总设计、主蓝图、按需提取的独立子系统蓝图和一份进度账本；关键决策与迁移审计保留在归档，已被完整吸收的旧任务书退出阅读面并进入可恢复隔离备份，不再增加完成分母。

## 2. 权威顺序

判断“现在实际上有什么”时：

1. 当前源码与可重复测试证据；
2. `NEXT.md` 最新日期段；
3. 本索引中的当前状态摘要；
4. 历史交接与归档记录。

判断“下一步应该实现什么”时：

1. 驾驶员最近明确拍板的合同；
2. 当前活动蓝图；
3. 统一总设计的根原则；
4. `NEXT.md` 的下一道门；
5. 历史蓝图只能解释来路，不能覆盖现行合同。

任何文档都不能替代真实酒馆验收，也不能自行标记 `driver-accepted`。

## 4. 状态词

- `ACTIVE`：现行权威，可作为后续工作合同。
- `FOUNDATIONAL`：长期根原则，不能当作逐项实施清单。
- `IMPLEMENTED`：能力已进入源码，但仍可能缺真实宿主验收。
- `SUPERSEDED`：目标或实现方式已被新合同取代，不得继续施工。
- `HISTORICAL`：只用于迁移、审计和恢复历史语境。
- `CHECKPOINT CANDIDATE`：已有自动化或包证据，但未得到驾驶员真实宿主接受。
