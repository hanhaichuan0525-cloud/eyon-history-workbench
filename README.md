# Eyon History Workbench

伊雍历史工作台是为《命定之诗》角色卡设计的历史探索系统。

当前计划包含：

- 墟境时空与状态查看
- MVU 人物查看与本地自定义分组
- 宗族谱系生成
- 墟境历史与因果节点生成
- 寻根溯源与传记书库
- 独立蝴蝶效应结算
- 按角色卡与聊天隔离的本地资料库
- 远程版本检测、缓存与回退

## 当前阶段

仓库已经进入正式宿主组装阶段：

- `rules/` 保存已经确认的脚本嵌入契约。
- `src/core/` 负责严格命令识别、传记请求占位槽和聊天命名空间。
- `src/renderers/` 负责输出能被现有酒馆美化正则识别的固定原文。
- `src/adapters/` 定义酒馆、生成接口和世界书归档边界。
- `src/prompts/`、`src/schemas/` 与 `src/validators/` 负责后台提示词、严格结果结构和语义校验。
- `src/workflows/biography.ts` 已实现寻根溯源的第一条完整事务链。
- `src/workflows/ruin.ts` 已实现候选墟境的独立 API 生成、严格校验与存储；`ruinEntry.ts` 负责把玩家选中的特异点、点击时现实锚点和 `RuinTrace` 合并成唯一进入玩家楼。
- `src/storage/` 按角色卡与聊天隔离传记和候选墟境；候选生成不会写入世界时间、MVU 或墟境运行状态。
- `WorkbenchLifecycle` 统一路由严格文本命令；聊天、楼层正文、swipe 或生命周期代际变化会使旧请求失效。
- `src/entry.ts` 已组装正式酒馆入口、脚本设置、当前绑定世界书/MVU 只读资料源、生命周期事件与工作台公开接口。
- `dist/index.js` 是可直接由酒馆助手加载的 ESM 构建；`manifest.json` 记录入口、版本与 SHA-256。
- `prototype/` 继续作为交互与视觉规格，不直接充当正式运行代码。

稳定的墟境时间控制模块不在本仓库中重写；历史工作台只通过受限适配层读取其状态。

## 设计边界

- 世界书继续负责伊雍人设、正文格式和角色卡核心。
- 现有时间模块继续负责墟境状态、时间与地点。
- 独立 API 负责宗族谱系、墟境历史、寻根溯源和蝴蝶效应内容生成。
- 工作台负责检索、调度、校验、存储、渲染和受控注入。
- 伊雍对话框由正文模型依据世界书自然生成；脚本不代写台词，只替换唯一的传记插槽。
- 候选墟境不占聊天楼；玩家点击特异点后只发送一个“进入节点”玩家楼，紧邻助手楼同时完成剧情衔接、正式面板和变量进入。
- 不读取或修改记忆插件的私有数据。
- 不把 API 密钥、聊天全文或完整 MVU 对象提交到仓库。

```bash

pnpm test
pnpm typecheck
pnpm test:regex
pnpm build
```

当前测试覆盖严格命令、固定原文、传记与候选墟境结果校验、插槽替换、精确楼层锁、聊天切换保护、重复请求合并、存储隔离、墟境根变量读取、绑定世界书筛选与串行玩家楼发送；测试不连接酒馆、不修改 MVU，也不调用远程 API。

## 正式入口

加载 `dist/index.js` 后，脚本会公开 `window.EyonHistoryWorkbench`。当前正式接口包括：

- 读取和更新生成 API 设置；
- 保存墟境生成面板草稿；
- 从面板生成候选墟境；
- 按当前角色卡与聊天读取本地候选和传记；
- 将选定特异点组装为唯一“进入节点”玩家楼并触发正文。

工作台状态通过 `eyon-history-workbench:status` 事件发送，界面层可在后续阶段直接订阅。当前版本不抢先挂载未完成的原型 UI。

角色卡世界书属于角色卡发行物，不同步到本仓库。脚本只在运行时通过受限适配器读取当前启用的世界书资料。

本仓库目前为私有开发仓库。
