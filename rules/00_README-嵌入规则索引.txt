# 伊雍脚本嵌入规则

本目录供脚本使用 `?raw` 导入。旧世界书文件不从这里读取，也不应被本目录覆盖。

编号表示依赖与装配顺序，不表示每次 API 请求都要注入全部文件。`00` 仅为索引，不参与模型注入；脚本应按模块读取所需子集，并保持同一子集内的编号顺序。

## 编号与装配顺序

1. `01_命定系统-伊雍-脚本上下文.txt`
   - 调用者: 宗族谱系、墟境生成、寻根溯源与蝴蝶效应结算所选API。
   - 用途: 提供伊雍机制的术语、世界观边界和内容原则。
   - 不负责: 伊雍对白、美化标签、FP结算、变量更新。

2. `02_生成模块API路由契约.txt`
   - 调用者: 脚本API调度层与设置界面。
   - 用途: 统一管理宗族谱系、墟境生成、寻根溯源与蝴蝶效应结算四个生成模块的路由。
   - 原则: 每次调用无历史、按需装配规则，不静默切换接口。

3. `03_资料检索与上下文装配契约.txt`
   - 调用者: 四个生成模块的资料检索层。
   - 用途: 筛选世界书、未隐藏正文、MVU、传记、族谱与蝴蝶效应史料，并按模块预算装配。
   - 原则: 不读取记忆插件注入，不把隐藏楼层悄悄送回模型，不无差别发送整本世界书。

4. `04_本地资料库与命名空间契约.txt`
   - 调用者: 脚本持久化层。
   - 用途: 隔离传记、族谱、墟境候选、蝴蝶效应原稿、待结算快照、草稿、请求记录、设置与密钥。
   - 原则: 默认按角色卡和聊天双重隔离；MVU与世界书核心不在本地复制，蝴蝶效应以当前聊天的本地结构化记录为权威原稿，并向专用世界书写入可注入镜像。

5. `05_生成结果校验与失败恢复契约.txt`
   - 调用者: API响应解析、校验、修复与提交层。
   - 用途: 统一四种Schema、语义校验、请求过期、取消、有限重试和错误显示。
   - 原则: 不信任模型自检，不静默切换接口，不提交残缺或过期结果。

6. `06_墟境系统变量规则-脚本契约.txt`
   - 调用者: 脚本状态读取层、悬浮球界面。
   - 用途: 规定只读路径、状态显示和与现有时间控制模块的边界。
   - 原则: 新的历史生成/API模块不得写入墟境变量。

7. `07_蝴蝶效应与墟境状态面板读取契约.txt`
   - 调用者: 悬浮球和完整状态面板的只读适配层。
   - 用途: 把同轮次现实锚点、墟境进入、当前、离开、归档和实际世界书日志整理成稳定视图模型。
   - 原则: 时地成对、轮次隔离，只读世界书中带 `eyon_butterfly_anchor` 来源标记的真实日志。

8. `08_伊雍骰子判定表-脚本数据.txt`
   - 调用者: 脚本本地随机模块。
   - 用途: 将骰点映射为阶段数、叙事素材、候选数和蝴蝶效应范围。
   - 原则: 骰点由脚本产生，模型只接收命中结果，不自行重掷。

9. `09_宗族谱系生成规则-API.txt`
   - 调用者: 宗族谱系所选API。
   - 用途: 以当前选中的MVU人物为固定中心，整理世界书、正文和MVU已经提供的亲属关系与生卒时间。
   - 原则: 允许受世界观约束的谱系补全，不制造史料冲突，不在树内切换谱系中心。

10. `10_宗族谱系界面与联动契约.txt`
    - 调用者: 人物查看器、族谱界面和墟境生成表单。
    - 用途: 规定代数控制、节点展示、左键基础信息及右键加入墟境参与人物。
    - 原则: 只有MVU角色列表中的人物具有完整查看和注入功能；族谱只作为墟境与传记的参考资料。

11. `11_墟境历史期生成规则-API.txt`
    - 调用者: 墟境生成所选API。
    - 用途: 根据脚本提供的地点、时间、资料与骰表结果，生成候选墟境JSON。
    - 不负责: 输出正文面板、进入节点、修改MVU、同步世界时间。

12. `12_墟境任务规则-脚本交接.txt`
    - 调用者: 脚本提示词组装器。
    - 用途: 把候选节点送入正文文本框，或发送明确的“进入节点”指令。
    - 原则: “生成面板”和“进入节点”是两次独立发送。

13. `13_寻根溯源生成规则-API.txt`
    - 调用者: 寻根溯源所选API。
    - 用途: 结合玩家原始指令、世界书、正文、MVU、族谱与旧传记，创作完整传记JSON和RootTrace成品。
    - 原则: 玩家指定的对象、时间与主要方向必须被实际落实，不能被骰表或旧传记覆盖。

14. `14_寻根溯源规则-脚本提示.txt`
   - 调用者: 脚本正文组装层。
   - 用途: 让正文模型依据世界书只生成伊雍固定格式开场；流式结束后，脚本把请求专属占位槽替换为API原始RootTrace。
   - 原则: 脚本不生成伊雍，正文模型不复写传记。

15. `15_蝴蝶效应生成规则-API.txt`
   - 调用者: 遣返结算所选API。
   - 用途: 根据脚本在清空前冻结的同轮次锚点、玩家行动、骰点和相关史料，生成蝴蝶效应结构化JSON。
   - 原则: API只创作现世落点、证据和历史演变；时间控制模块独立完成遣返，脚本统一渲染旧版面板并归档。

## 权威来源

- 当前世界时间、地点与墟境状态: 现有时间控制/MVU模块。
- 伊雍人设、对白格式、命定契约、FP、现有美化触发: 世界书核心。
- 候选墟境与宗族谱系的资料生成: 额外API。
- 伊雍开场、`[RuinTrace]`转写与进入后的叙事: 正文模型。
- `[RootTrace]`传记成品: 独立API生成，脚本在正文流式结束后原样写入同一个AI楼层。
- 传记全文持久化: 脚本传记书库，不回写世界书正文。
- 蝴蝶效应内容: 独立API根据冻结快照生成，脚本校验并渲染固定格式。
- 蝴蝶效应权威原稿: 按当前聊天保存的本地IndexedDB记录。
- 蝴蝶效应注入镜像: 当前聊天对应的专用全局归档世界书，只启用带来源标记的本聊天实际锚定条目。
- 生成草稿与缓存: 本地资料库，不得覆盖世界书、聊天或MVU。

## 禁止事项

- 禁止嵌入 `getwi`、`matchChatMessages` 或其他世界书EJS触发器。
- 禁止使用宽泛词语猜测玩家是否进入或遣返。
- 禁止API输出JSON Patch、`<UpdateVariable>`、`<eyon>` 或美化HTML。
- 禁止生成模块接管现有时间控制逻辑。
- 禁止把旧 `事件.伊雍` 作为任何新模块的数据源。
- 禁止把候选墟境误当成已经进入的墟境。
- 禁止寻根溯源追加历史结晶商店、商品面板或 `<item_info>`。
- 禁止正文模型与独立API同时各自生成一份蝴蝶效应面板。
- 禁止蝴蝶效应API修改或推断现实、进入、离开三套冻结锚点。
- 禁止蝴蝶效应API失败导致遣返回滚、恢复 `exploring` 或读取上一轮次补档。
- 禁止族谱无约束杜撰亲属、制造史料冲突剧情或生成独立任务；资料缺失时只允许按族谱规则进行带来源标记的约束补全。
- 禁止使用隐藏楼层、未采用重roll页或记忆插件注入作为默认生成资料。
- 禁止把API密钥写入导出包、日志、世界书、聊天、MVU或成品资料库。
- 禁止面板根据缓存、候选或归档日志自行恢复墟境状态。
