# Eyon History Workbench

伊雍历史工作台是为《命定之诗》角色卡设计的历史探索系统。

当前计划包含：

- 墟境时空与状态查看
- MVU 人物查看与本地自定义分组
- 宗族谱系生成
- 墟境历史与因果节点生成
- 寻根溯源与传记书库
- 独立蝴蝶效应结算
- 按角色卡与聊天隔离的本地资料库
- 远程版本检测、缓存与回退

## 当前阶段

仓库已经进入第一条完整工作流实现阶段：

- `rules/` 保存已经确认的脚本嵌入契约。
- `src/core/` 负责严格命令识别、请求占位槽和聊天命名空间。
- `src/renderers/` 负责输出能被现有酒馆美化正则识别的固定原文。
- `src/adapters/` 定义酒馆、生成接口和世界书归档边界。
- `src/prompts/`、`src/schemas/` 与 `src/validators/` 负责后台提示词、严格结果结构和语义校验。
- `src/workflows/biography.ts` 已实现寻根溯源的第一条完整事务链。
- `src/storage/` 按角色卡与聊天隔离传记记录，并区分“已校验”和“已注入”状态。
- `prototype/` 继续作为交互与视觉规格，不直接充当正式运行代码。

稳定的墟境时间控制模块不在本仓库中重写；历史工作台只通过受限适配层读取其状态。

## 设计边界

- 世界书继续负责伊雍人设、正文格式和角色卡核心。
- 现有时间模块继续负责墟境状态、时间与地点。
- 独立 API 负责宗族谱系、墟境历史、寻根溯源和蝴蝶效应内容生成。
- 工作台负责检索、调度、校验、存储、渲染和受控注入。
- 伊雍对话框由正文模型依据世界书自然生成；脚本不代写台词，只替换唯一的传记插槽。
- 不读取或修改记忆插件的私有数据。
- 不把 API 密钥、聊天全文或完整 MVU 对象提交到仓库。

运行时采用“生成前准备，正文楼渲染后提交”的两阶段楼层事务。详见
[`docs/RUNTIME.md`](docs/RUNTIME.md)。

## 本地验证

需要 Node.js 22.18 或更高版本：

```bash
pnpm install
pnpm test
pnpm typecheck
pnpm test:regex
```

当前测试覆盖严格命令、固定原文、传记结果校验、插槽替换、聊天切换保护和存储隔离；不连接酒馆、不修改 MVU，也不调用远程 API。

角色卡世界书属于角色卡发行物，不同步到本仓库。脚本只在运行时通过受限适配器读取当前启用的世界书资料。

本仓库目前为私有开发仓库。
