# 一、最终职责

- 世界书核心: 生成伊雍人设、语气、mood和固定美化标签。
- 正文模型: 依据世界书核心流式输出伊雍的传记开场。
- 独立API: 生成完整传记JSON和唯一权威 `rootTrace`。
- 脚本: 调度请求、保存API成品、放置占位槽、替换消息、重新渲染并写入传记书库。

脚本禁止生成、补写、改写或模仿伊雍对白。
正文模型禁止重新创作、复述或润色API传记。

# 二、触发

只有脚本严格识别到玩家明确的寻根溯源命令后才执行，例如:

- `对维奥莱塔进行寻根溯源`
- `对维奥莱塔进行寻根溯源，主要方向是她24岁到28岁的猎艳史`
- `为黄昏判决寻根溯源`
- `寻根溯源：金谷城南门`

普通的“调查、探查、追溯、查考、查看”不得触发。

# 三、后台准备

正文生成开始前，脚本必须已经:

1. 生成唯一 `requestId`。
2. 完成独立API调用。
3. 校验 `biography.schema`。
4. 校验 `biography.rootTrace` 同时含有 `[RootTrace]` 和 `[/RootTrace]`。
5. 把API原始 `rootTrace` 保存在本次请求的内存状态中。
6. 创建唯一占位槽:
   `[EYON_ROOTTRACE_SLOT::{{requestId}}]`

完整 `rootTrace` 不注入正文模型，不加入世界书扫描，也不写入后台草稿消息。

# 四、正文请求

脚本使用正常 `generate()`，保留当前角色卡、世界书、酒馆预设、聊天历史和记忆插件。

只通过本次请求的 `injects` 注入以下简短控制信息:

【伊雍寻根溯源协作请求】
玩家已经要求对“{{biography.target.name}}”进行寻根溯源。
玩家原始指令：{{biography.playerDirective.raw}}
主要方向：{{biography.playerDirective.primaryDirection}}
时间跨度：{{biography.span.label}}

传记史稿已经由圣卷后台完成。
请只依据当前世界书中的伊雍核心、人设、语气、mood与固定格式，生成伊雍对此次传记的简短开场。
伊雍正文必须使用世界书规定的 `<eyon name="伊雍" mood="...">「对白」</eyon>` 与 `<eyon_court/>` 格式。
禁止自行生成、复述、概括、改写或评论传记正文。
伊雍开场结束后，必须单独原样输出以下占位槽，并立即结束:
[EYON_ROOTTRACE_SLOT::{{requestId}}]

注入配置:

- `role: "system"`
- `position: "in_chat"`
- `depth: 0`
- `should_scan: false`
- 仅对本次请求有效。

# 五、流式输出

- 正文模型只流式输出伊雍开场和占位槽。
- 脚本不得在流式生成过程中修改消息。
- 后台API成品不会随正文模型逐字流式输出。
- 必须等待正文生成完整结束，确认当前AI消息ID后再进行替换。

# 六、占位替换

正文生成结束后:

1. 读取本次生成对应的AI消息，不使用“最新楼层”猜测。
2. 查找完全匹配的 `[EYON_ROOTTRACE_SLOT::{{requestId}}]`。
3. 用内存中保存的API原始 `rootTrace` 原样替换该占位槽。
4. 不对 `rootTrace` 进行Markdown转义、格式化、清洗、压缩或重排。
5. 更新同一个AI消息。
6. 触发该消息重新渲染，使现有传记美化生效。
7. 从更新后的最终消息中解析 `[RootTrace]...[/RootTrace]` 并写入传记书库。

最终AI楼层结构:

<eyon name="伊雍" mood="世界书决定">「世界书核心生成的开场」</eyon>
<eyon_court/>
[RootTrace]
API原始传记
[/RootTrace]

# 七、异常兜底

## 7.1 占位槽缺失

若正文模型未输出占位槽:

1. 若消息中已经存在模型自行生成的 `[RootTrace]...[/RootTrace]`，用API原始 `rootTrace` 替换该区段。
2. 若不存在RootTrace，在最后一个 `<eyon_court/>` 后追加API原始 `rootTrace`。
3. 若连 `<eyon_court/>` 也不存在，在消息末尾追加API原始 `rootTrace`，并记录格式警告。

兜底只允许插入API原稿，禁止脚本补写伊雍标签或对白。

## 7.2 重复占位槽

- 只在第一个匹配位置插入 `rootTrace`。
- 删除同一 `requestId` 的其余重复占位槽。
- 不处理其他请求ID的占位槽。

## 7.3 取消与失败

- API失败或 `rootTrace` 不合法时，不启动正文生成。
- 玩家取消正文生成时，不向残缺AI消息追加传记。
- 保留待处理API成品，允许玩家重新执行正文交接。
- 不生成空AI楼层。
- 不修改MVU、世界时间、墟境状态或传记书库。

# 八、记忆插件隔离

- 不读取、覆盖、删除或重新排列记忆插件的注入。
- 不覆盖 `chat_history`、世界书、角色卡或酒馆预设。
- 不使用常驻 `injectPrompts` 保存传记。
- 控制注入使用 `should_scan: false`。
- API草稿、结构化JSON和内部自省过程永不进入聊天。
- 只有组装完成的最终AI楼层成为真实聊天内容，供后续正文与记忆系统正常读取。

# 九、会话与重试隔离

- 待处理传记以 `chatId + userMessageId + requestId` 为唯一键。
- 重roll生成新 `requestId`，旧请求不得替换新消息。
- 切换聊天后，未完成请求暂停，不得写入新聊天。
- 删除触发楼层后，对应待处理请求失效。
- 消息替换完成后立即清除临时占位状态，但保留传记书库记录。

# 十、禁止输出

- 禁止历史结晶商店。
- 禁止商品播报、购买选项或 `<item_info>`。
- 禁止变量更新、JSON Patch或后台JSON。
- 禁止脚本生成伊雍正文。
- 禁止正文模型生成第二份传记。
