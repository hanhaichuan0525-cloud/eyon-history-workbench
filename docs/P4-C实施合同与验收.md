## 1. 一句话目标

P4-C 只解决一件事：

> 当同一件事出现两个版本时，区分它们是“资料空白下可以并存的两种解释”，还是“两个有效来源真的互相矛盾”；保留差异，但不擅自替玩家和 Canon 选赢家。

它不是新的 Canon，不负责重写历史，不负责判断哪篇作品写得更好，也不负责把所有文本差异都结构化。

## 2. A0 工程门

### 2.1 本阶段输入

- 当前聊天、当前分支、当前 Canon revision 下，经过 P2 当前状态过滤的 `GeneratedContinuityAnchor`；
- P4-A/P4-A2 已经生成的低权连续性短锚及其有效 `sourceRefs`；
- 当前 P1/P2 Canon 视图，仅用于排除已经被高权事实否定的视图；
- 新提交传记最终正文与旧锚之间由脚本宽松召回的有界事件对；
- P4-B 当前谱系局部视图只可作为人物/关系背景，不成为 P4-C 的强事实来源。

### 2.2 本阶段输出

- 脚本验证后的 `parallelView` 或 `sourceConflict` 低权关系；
- 由当前 revision 动态派生的、最多两视图的有界关系投影；
- 工作台与导出中的只读诊断；
- 在既有连续性预算内，供后续传记和墟境读取的自然语言提示。

### 2.3 红线

- 不修改 Canon、世界书、MVU、P3 因果单位或既有传记正文；
- 不自动选择赢家，不使用“最后写入者获胜”；
- 不恢复语义编译器，不做全文逐句抽取，不建立通用自然语言事实数据库；
- 只在确有候选事件对时允许每个候选批次至多一次独立轻量语义裁判；不得把裁判字段塞回普通正文 JSON；
- 不把模型的 `parallelView/sourceConflict` 自报当作事实；
- 不因关系字段畸形、缺失或错误而 repair、重试或阻断正文；
- 不跨聊天、跨分支、跨 revision 读取或合并；
- 不做模糊姓名归并，不允许模型创造内部 ID；
- 不修改四模块普通正文合同，不进入 P4-D 缓存；
- 本阶段 `runtimePersistentBlueprintBudget = 0`，不得新增长期子蓝图或新的完成分母。

### 2.4 阶段退出条件

只有同时满足以下条件，P4-C 才能交给驾驶员验收：

1. 两个相容解释可并存，不被合成一个事实；
2. 两个有来源的明确矛盾可见、可导出，但不阻断生成；
3. 文风、镜头、措辞差异不会误建关系；
4. 普通模型每个关系簇最多看到两个视图；
5. Canon 后续明确裁定或回滚后，当前投影可确定性退出或恢复；
6. 坏句柄只丢单条关系，正文、锚与其他关系继续保留；
7. 无候选时零新增调用；每个有候选的正文批次至多一次独立自然语言裁判，并且没有把裁判变成正文结构化硬门。

## 3. 术语与权力边界

### 3.1 `parallelView`

满足以下语义：

- 两个锚指向同一事件或同一连续性问题；
- 两个版本存在实际内容差异；
- 当前 Canon 没有排除任何一个版本；
- 暂无高权证据要求唯一答案；
- 差异不是单纯文风、台词、镜头或情绪。

例：世界书只写“梅薇娜把《白日尽头》赠给玲山”，未写年份；两篇传记分别把赠书安排在 484 年与 485 年，且当前 Canon 对年份没有裁定。两者可以记录为 `parallelView`。

### 3.2 `sourceConflict`

满足以下语义：

- 两个当前锚指向同一事件的同一事实维度；
- 双方各自至少能解析到有效来源；
- 有效来源集合中至少存在两个不同来源身份；
- 双方主张不能同时成立；
- 当前 Canon 尚未把其中一方直接判为过时或失效。

例：两个仍有效的来源分别明确写“赠书发生于 484 年”和“赠书发生于 485 年”，且该赠书被限定为唯一一次。这是 `sourceConflict`，但 P4-C 仍不裁定谁对。

### 3.3 不属于 P4-C 的差异

以下内容不得创建关系：

- 同一事件换了修辞、镜头、节奏或对话；
- 一篇详写、一篇略写，但没有事实冲突；
- 两个完全不同的事件恰好用了相似措辞；
- 只有一个来源，另一个版本只是模型随手发挥，却试图伪装成 `sourceConflict`；
- 当前 Canon 已经明确否定其中一方；
- 仅名字近似，无法确定是同一人物、地点、物品或事件。

## 4. 第一版关系记录

P4-C 区分“脚本宽松召回”、“独立轻量语义裁决”和“脚本记录”。召回只决定哪些事件对值得比较；裁判只判断是否同一事件及差异维度；脚本才能校验并创建内部关系。

### 4.1 语义事件对裁决

脚本先从本轮最终正文与已投递的 `C` 句柄中，依据共同人物、地点和具名物品宽松召回最多 6 组事件对。这些对只是“请复核”，不是关系证明。若至少有一对，工作流单独发起一次轻量裁判；输入是两边自然语言正文，输出是每对一行的中文短句，例如：

```text
P1：同一事件；主要差异：时间；理由：两段描述同一次移交，但年份不同。
P2：不同事件；理由：一段是绘图，另一段是移交。
P3：无法确认；理由：现有文字不足以证明是同一次发生。
```

冻结约束：

- 召回必须有界：最多 6 对、每个当前事件最多 2 对；
- 裁判整次失败、某行缺失、`differentEvent` 或 `uncertain` 都等于“不建关系”，不是错误；
- 只有 `sameEvent` 且带合法 `dimension` 才能进入脚本校验；
- 模型不决定 `parallelView/sourceConflict`，不选赢家；关系种类由脚本按双边来源情况确定；
- 共用人物、地点、物品或词句只能让事件对被看见，不能单独证明是同一事件；
- 相邻、因果相连、同地发生或使用同一物品的不同行动，必须判为 `differentEvent`；
- “理由”只供诊断，最长 160 字，不具备事实权力；
- 模型不得填写 `relationId`、`anchorId`、`bindingId`、关系种类、branch 或 revision；
- 未投递的 P 编号、未知维度和无法识别的行逐条丢弃；
- 顶层正文合格与否不依赖裁判；裁判全部损坏也不触发正文 repair。

### 4.2 脚本持有的关系记录

脚本验证 `sameEvent` 裁决后才可生成内部记录，概念形态为：

```ts
type ContinuityViewRelation = {
  schema: 'eyon.continuity.relation.v1';
  relationId: string;
  namespace: string;
  branchId: string;
  canonRevision: number;
  kind: 'parallelView' | 'sourceConflict';
  dimension: ContinuityEventPairVerdict['dimension'];
  memberAnchorIds: readonly [string, string];
  sourceRefs: string[];
  producerArtifactId: string;
  producerUnitRef: string;
  createdAt: string;
};
```

冻结约束：

- `relationId` 由脚本根据作用域、关系种类、维度和两个成员锚确定性生成；
- 成员顺序标准化，同一对锚不能因先后颠倒重复建关系；
- 记录没有 `winner`、`preferred`、`truthScore` 或自动裁决字段；
- 原始记录可留作审计，是否进入当前视图每次按现行 P1/P2/P4 状态重新派生；
- 关系记录低于当前 Canon、玩家本轮明确指令和有效世界书证据。

## 5. 候选验证顺序

脚本按以下固定顺序验证，每一步失败只丢当前裁决：

1. `pair` 必须是本段实际投递给全文复核的事件对，且 verdict 必须为 `sameEvent`；
2. 该对冻结的 `currentEventRef` 必须能映射到本轮已经通过正文校验并准备提交的 `final-prose` 连续性锚；
3. 该对冻结的 `otherHandle` 必须来自本轮冻结投递的当前 `C` 句柄表；
4. 两个成员不能是同一锚，且都属于同一 namespace、branch 与 canonRevision；
5. 两个成员都必须通过既有 P2 当前状态与来源产物存在性检查；
6. 两个成员至少共享一个已确定的实体落点：人物、地点、具名物品或已有稳定事件身份之一；
7. 不使用模糊字符串相似度补齐实体，不因“看起来像”而合并；
8. 当前 Canon 若已明确排除一个成员，不建立关系，由既有 P2 状态负责其退出；
9. 两边都有有效 sourceRefs 且合并后至少有两个不同来源身份时，脚本记为 `sourceConflict`；否则记为 `parallelView`；
10. 同一新锚、同一维度、同一另一成员重复声明时只保留一条确定性记录。

模型负责阅读两段完整语义并判断是否同一事件；脚本只负责宽松召回、权限校验、来源分类和稳定落库，不用词段相似度代替语义判断。

## 6. 当前投影与有界组装

### 6.1 当前性

关系的当前投影同时要求：

- 关系记录作用域等于当前聊天 namespace、branch 和 revision；
- 两个成员锚仍存在；
- 两个成员锚当前均可被 P4 消费；
- 对应生产产物仍存在；
- 当前 Canon 没有使其中一方退出。

任何一项不满足，只让当前关系退出；不得删除原始产物，不得改写旧稿。

### 6.2 两视图上限

- 每个关系簇向普通模型最多投递两个当前视图；
- 三个以上候选可以留在诊断中，但不自动排列组合；
- 不做 A/B、A/C、B/C 的笛卡尔展开；
- 若同一簇超过两个当前成员，沿用既有确定性相关性与稳定 ID 顺序选两个，其余只显示“另有 N 个诊断候选”；
- 不因为玩家未选赢家而阻断后续生成。

### 6.3 不增加提示词总预算

P4-C 注释必须装入 P4-A 已有连续性视图预算：

- 总体仍为最多 6 个连续性锚、总计 1600 字；
- 关系标题和两条短说明占用同一预算，不另加一块无限文本；
- 每个关系簇只显示种类、维度和两条自然语言视图；
- 模型只看短句柄，不看内部关系 ID、锚 ID 或 binding ID；
- 没有可用关系时，保持原 P4-A 连续性视图，不输出空壳章节。

## 7. 生产者与消费者边界

### 7.1 第一版生产者

- 只有新提交传记中，经过既有整篇语义复核并成功形成 P4-A2 `final-prose` 锚的段落，才能把本轮冻结事件对中的 `sameEvent` 裁决落成关系；
- 不新增独立模型请求；
- 旧传记不回填；
- 墟境、蝴蝶、谱系与普通聊天正文不生产 P4-C 关系；
- P4-B 的 generated 亲属不因为进入谱系而自动成为冲突来源。

### 7.2 第一版消费者

- 后续传记规划与扩写；
- 墟境候选提纲与史稿扩写；
- 工作台只读诊断与导出。

以下不消费 P4-C 关系：

- 蝴蝶效应 Canon 提交；
- P3 因果支撑、重基线与 reconcile；
- MVU 或世界书写回；
- 普通聊天记忆；
- 谱系硬关系生成与事实锁。

### 7.3 玩家明确选择

玩家可以在自然语言任务中明确要求采用某个当前兼容版本。此选择只影响本轮创作：

- 不写回 Canon；
- 不删除另一视图；
- 不产生全局赢家；
- 若所选版本已经被当前 Canon 排除，则按现有证据冲突规则拒绝偷渡。

第一版不新增“设为真相”按钮，不设计人工裁决数据库。

## 8. 生命周期、删除与回滚

- 删除关系生产传记：该产物附属关系退出当前投影；其他作品原文保留；
- 删除另一成员锚的来源传记：关系因缺成员退出；
- Canon revision 前进：旧 revision 关系不跨版本复用；新 revision 只按当前成员重新投影；
- 删除遣返楼并回滚：父 revision 中原本可用的成员和关系确定性恢复，不重新调用模型；
- 世界书或当前 Canon 后续明确裁定：不兼容成员依既有 P2 状态退出，关系自然失去双成员条件；
- 切换聊天或分支：零复用；
- 旧存档没有关系字段：正常读取，视为没有 P4-C 关系，不做迁移回填；
- 存储损坏：忽略损坏记录并继续生成，诊断记录有界错误。

## 9. 失败降级矩阵

| 故障 | 第一版处理 | 禁止行为 |
|---|---|---|
| 模型不返回关系字段 | 正常提交正文与锚 | 不 repair、不重试 |
| 单条候选 JSON 畸形 | 丢弃单条 | 不废弃整段正文 |
| 未知 C 句柄 | 丢弃单条并诊断 | 不猜目标 |
| 跨 branch/revision | 丢弃单条 | 不跨域迁移 |
| `sourceConflict` 缺有效来源 | 丢弃单条 | 不自动伪装成来源冲突 |
| 只有文风差异 | 不建关系 | 不制造 parallelView |
| 当前 Canon 已裁定 | 由 P2 过滤不兼容成员 | 不让低权关系反压 Canon |
| 关系组装失败 | 返回原 P4-A 视图或空关系区 | 不阻断传记/墟境 |
| 三个以上视图 | 普通模型取确定性两个，其余诊断 | 不做组合爆炸 |
| 导出或 UI 诊断失败 | 生成主链继续 | 不回滚正文提交 |

## 10. 诊断、界面与导出

第一版只增加克制的只读观察面：

- 当前 `parallelView` 数量；
- 当前 `sourceConflict` 数量；
- 每条关系的种类、维度、两个自然语言视图、来源可用性和退出原因；
- 被丢弃候选的有界原因计数；
- 超过两视图时的诊断候选数量。

界面不得：

- 展示要求用户理解的内部 ID；
- 把“并行解释”渲染成红色错误；
- 提供会修改 Canon 的赢家按钮；
- 显示模型 note 作为事实结论；
- 为了关系视图重做整个工作台布局。

导出可以保留内部 ID 供诊断，但必须明确这些关系是低权派生记录，不是 CanonFact。

## 12. 实施顺序

后续获准时，严格分四步，不跨步宣称完成：

1. **C1 关系外壳**：候选预处理、内部记录、短句柄验证和 fail-open 单测；
2. **C2 当前投影**：同分支/同 revision/P2 current 双成员过滤、删除与回滚测试；
3. **C3 有界消费**：两视图上限、1600 字共享预算、传记/墟境注入和只读诊断；
4. **C4 交付门**：聚焦测试、全量测试、typecheck、正则契约、生产 build、组件打包，再交真实酒馆验收。

任一步发现真实阻断，只能开一条不持久的局部问题支线；解决后返回当前步骤，不扩成新的 P4 子阶段。

## 21. internal.112 非结构化裁判修订

### 21.1 为什么修订

internal.110—111 仍把 `continuityClaim`、`continuityEventVerdicts` 等软字段塞在普通传记正文 JSON 里。真实模型会漏填、错填或在正文不变时丢回执，形成反复出现的“结构化困境”。这些字段既不是正文，也不该由正文生成模型负责记账。

### 21.2 冻结实现

- 普通传记 passage schema 删除 `continuityClaim`、`continuityRelations`、`continuityEventVerdicts`；旧模型偶然返回这些未知字段时静默丢弃；
- 每个 `eventUsage=occurs` 的最终合格段落，由脚本使用冻结事件摘要、时间范围和已校验人物/机构/地点/物品索引构造可独立理解的低权锚，完整正文摘录仍按既有机制附着；

- 只有“同一事件 + 合法实质差异”进入既有脚本权限校验，模型不决定关系种类、不选赢家、不填写内部 ID；
- 裁判失败、空响应、少行、无法确认或不同事件均不 repair、不重试正文、不阻断传记；无候选时完全不调用裁判；
