## 二、测试方法与结果（可复现）

### 剧本 1（RC-02 死亡回滚，档案级）——✅ 通过

方法：
1. 生成一篇含「某人已故」信息的传记（如千爻的姐姐千月 470 年死讯）；
2. 生成在她死后年份的内容（墟境/传记）→ 期待死者只以遗物/遗产/纪念出现（缺席叙事）；
3. **工作台删除该传记档案 + 清掉聊天里相关楼**（档案级回滚）；
4. 再生成 → 期待死者正常回归（复活）。

实测：三篇 480 年墟境全部「遗物/遗产/追忆」叙事（零活人出场）；删档案+删依赖楼后千月以活人正常重逢——通过。

### 剧本 2（RC-06 事实遮蔽，档案替换法）——✅ 通过

方法：
1. 新传记钉入事实 A（千爻 478 首抵索伦蒂斯），删除旧档案（476 版），清旧语境；
2. 用「反事实窗口」探查（千爻 477 年的生活）→ 期待「未抵达/启程前」；
3. 观查 476 是否降格为「档案笔误」而非正史。

实测：三篇 477 年墟境全是「故乡最后一年/次年春启程」，476 只以文书笔误身份出现（模型世界观完全跟随现存档案）——通过。

### 剧本 3（RC-07 同视图 + 分支隔离）——✅ 通过

方法：
1. 同视图：同一聊天内，传记↔墟境↔二传对同一组事实（出生 460/首抵 478/姐姐线/年龄）口径一致；
2. 隔离：新开聊天生成同一方向 → 不携带 A 档案细节（无 478 锚、无 A 专属物件），时间线自由自洽；
3. 切回 A → 原档案与产物原封不动。

实测：同视图口径零冲突；B 聊天完全干净（无瓷片/盐果/白鲸等 A 专属物，自定 488 首抵索伦蒂斯）；A 恢复如初——通过。

## 三、关键边界结论（后人不许重蹈）

1. **口头更正（聊天层）不能推翻参考层史料**——玩家自然动作是「删旧楼→重写新档案」；实测已归档，**无需机制**。
2. **档案层无自动仲裁**：新旧传记是「两本书」，代际覆盖靠显式删除/替换；**自动遮蔽只发生在 canon/delta 层**（蝴蝶/正式提交链）——两者分工是设计，不是缺陷。
3. **上下文即世界**：聊天历史中的旧文本是模型的强依据——任何「反转事实」类实验，第一步 = 换新聊天或清掉依赖楼。
4. **「书签点不开」真因 = HTML id 撞名**（美化书签 id 用标题、同名传记共存导致 label for 失效），与消息体积/截断无关；教训：先查 id 唯一性，再谈体积。已根治：脚本 BookId（requestId 尾 8）＋美化 id=「标题-书签键」。
5. **空洞报错家族已全部收尾**：TASK_ALIGNMENT(74)→NODE_ID(77)→字数软下限(79v5)→幻觉ID消毒(79v4)→Zod 原始输出包装(79v8)——现在所有模型可见报错都带中文修复指引；**新增报错必须延续此规范**。
6. **年龄智能处理已闭环**：catalog 智能提取（实际N岁优先/外貌心理修饰剔除/歧义不猜）＋prompt 2.1 条款（双轨以实际为准/长寿命外貌恒定）＋`extractTargetBornYear` 出生回填 TARGET_AGE_ANCHOR。
7. **美化分发**：单文件内嵌（约 491K 字符，CSS 紧凑无压缩空间）；拆分全局 CSS 会破坏零配置分发，已恢复内嵌原版并升级 BookId 兼容版。
