# 伊雍历史工作台安装说明

## 环境

- SillyTavern 与酒馆助手（Tavern Helper）；
- 对应版本的《命定之诗》角色卡与世界书；
- 若使用独立生成接口，请在本地设置页填写接口信息。密钥不会随备份导出。

## 安装方式 A：β1 自动更新脚本（推荐，当前工作台 β1.9.1）

1. 停用旧原生扩展、旧内嵌整合脚本；不要重复启用两个工作台。
2. 在酒馆助手脚本管理中导入 `release/酒馆助手脚本-伊雍历史工作台-β1.json` 并启用。
3. 完整刷新酒馆，进入角色卡；单击伊雍悬浮球打开工作台，核对界面为 β1.9.1，并在设置中核对内部版本 0.14.35。
4. 四份正文正则仍需单独导入或启用，它们不会由此加载器自动更新。

已导入β1的用户，工作台代码在脚本下次重新执行时自动读取远端版本；保持页面打开不即时热更新。β1.9.1沿用β1.5发布时的loader 0.3.1代码、固定URL、ID与缓存协议，电脑和手机均无需重新导入。CDN/网络失败会回退旧的已验证缓存，以界面版本为准。仅导入离线内嵌包不会自动更新。若曾手改或使用更早的不同加载器，应先核对其固定清单地址与加载器版本，不能把所有历史脚本都视为同一通道。

β1.8升级到β1.9还需手动用 `release/命定系统-伊雍-β1.9-核心规则.txt` 替换原伊雍核心条目内容，并替换原蝴蝶面板正则，保留原条目/正则身份，不新增重复项。已使用0.14.22核心和0.14.23蝴蝶正则的本地测试者无需重复替换；自动加载器不会改玩家世界书或正则。

β1.9升级到β1.9.1无需再换核心；请手动替换原对话框正则为 `release/regex/regex-伊雍-对话框美化（as）.json`，不要新增重复项。本次修复应用于新生成请求，不自动重写已有传记、蝴蝶归档或冻结轮次。

远端清单与代码来自此 GitHub 仓库经 jsDelivr 分发。SHA-256 只检查文件与清单一致，不是签名认证，也不能防止仓库或分发渠道本身被篡改；请仅使用信任的仓库。

## 安装方式 B：离线内嵌脚本（0.14.35 / β1.9.1）

1. 关闭旧版“伊雍墟境系统”脚本、旧悬浮球和同名旧版正则，避免重复监听。
2. 在酒馆助手脚本管理中导入 `酒馆助手脚本-伊雍历史工作台-v0.14.35.json`。这是固定代码包，不自动更新；工作台内显示β1.9.1，内部版本0.14.35。此次维护更新不再改变核心或四份正则。
3. 在 SillyTavern 正则扩展中依次导入发布包 `regex/` 下的四个 JSON 文件并启用。
4. 重新载入当前聊天；页面应只出现一个伊雍像素伴生体。单击她即可打开工作台。
5. 首次使用前打开设置页，确认当前聊天、角色卡、世界书与 MVU 状态均能读取。

## 最短冒烟测试

1. 生成一篇短传记，确认标题跨度与每个时期标题都显示年份。
2. 生成宗族谱系，确认节点与连线正常，右键菜单贴近目标节点。
3. 生成一个墟境，分别点选四阶段中的任意节点，确认进入时间与选中节点一致，地点写回为完整 MVU 路径。
4. 在墟境内生成任务，编辑并确认；重抽正文时任务文本应保持不变。
5. 在蝴蝶控制台确认方案、点击“遣返现世”，确认只发送一个玩家楼并自动续写，MVU现实时地恢复；重roll同楼复用蝴蝶原文，删除玩家遣返楼后重新点击才重做结算。

## 校验下载

发布页提供 `SHA256SUMS.txt`。PowerShell 可执行：

```powershell
Get-FileHash -Algorithm SHA256 -LiteralPath '.\酒馆助手脚本-伊雍历史工作台-β1.json'
```

将结果与清单中的对应条目比较。资源许可见 [`ASSET_LICENSE.md`](../ASSET_LICENSE.md)，第三方声明见 [`THIRD_PARTY_NOTICES.md`](../THIRD_PARTY_NOTICES.md)。
