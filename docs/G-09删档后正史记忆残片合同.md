# G-09 删除可见档案后的正史记忆残片 · 实施合同与验收

> 合同状态：**FROZEN / IMPLEMENTED / AUTOMATED / DRIVER ACCEPTED（2026-09-27）**
> 实施版本：internal.118
> 权威关系：Canon 状态决定残片是否可用；残片本身不能修改 Canon

## 1. 目标

时间线中的“删除档案”继续只删除可浏览的 ButterflyRecord，不等于回滚正史；若该档案对应的干涉仍在当前 Canon 中有效，正文仍应得到一份有界、可读的来龙去脉，避免只看见结果却失去原因。

## 2. 冻结语义

- 删除档案不回滚 Canon、不删除正文楼层、不恢复旧历史；
- 不暗藏整份已删除档案，不保留面板、历史演变全文或模型结果副本；
- 只保存紧凑记忆残片：分支、revision、action/delta 引用、标题、时空锚、既成行动、软触发词与删除时间；
- “仍有效结果”每次从当前 Canon delta 的 active operations 重新投影，不从删除时的旧叙述硬拷贝；
- Canon 回滚、取代、孤立或局部重基线后，残片跟随当前 operation 状态收缩或退出；
- 同 runId 的可见档案存在时优先使用可见档案，避免双重注入；
- 残片按聊天 namespace 隔离，进入资料导出与完整性检查；
- 记忆仓故障不得阻断普通正文，亦不得改变 Canon。

## 3. 存储与生命周期

- IndexedDB 版本升至 8，新增 `canonMemoryTombstones` 仓；
- 删除入口在同一数据库事务中删除可见档案/待结算快照并写入残片；
- 只有具备有效 action、delta 且至少一个 operation 当前 active 时才建立残片；
- 正文生成前、切聊天、删楼、AI 楼渲染后、手动刷新与删档后都会重新计算；
- “清理生成缓存”不删除残片，因为它不是生成缓存；
- 若用户确实要撤销正史，必须走既有 Canon 回滚流程，而不是删除档案。

## 4. 验收

1. 对一条 active 蝴蝶档案执行删除：时间线不再显示该档案；
2. 诊断页显示“源 A 紧凑残片 1 条”，实际注入仍含既成行动与当前有效结果；
3. 注入不得出现已删除档案的历史演变全文；
4. 删除对应遣返楼或完成 Canon 回滚：残片变为过滤状态，正文不再注入；
5. 新干涉只取代部分 operation 时，残片只叙述仍 active 的结果；
6. 切换聊天后残片不串线；
7. 导出资料包含残片计数与记录；
8. 删除一个未形成有效 Canon 的旧档案时，不制造残片。

## 5. 边界

G-09不提供“恢复已删除档案”功能，也不替用户猜测删除是否意味着撤销历史。它只修复“删档但正史仍有效”这一已确认语义下的正文因果可读性。正式发布与驾驶员接受仍是独立闸门。

## 6. internal.118 实施回执

- IndexedDB 升至 v8，并新增与可见蝴蝶档案分离的 `canonMemoryTombstones` 仓；
- 只有已经形成当前有效、可回滚 Canon 干涉的档案，在删除时才原子写入紧凑残片；未提交、无 delta、失效或未形成活动 operation 的档案不会留下残片；
- 残片不保存蝴蝶面板、历史演变或整份归档正文，只保存定位当前 action/delta 所需引用与有界行动摘要；
- 正文注入时重新读取当前 Action 与 active rebase operation，部分取代时自动缩为仍有效结果，回滚、完全取代、孤立或 revision 失效后退出；
- 时间线不提供残片浏览或恢复入口，数据完整性检查与导出只读暴露计数和记录；
- 自动化覆盖 active 删除保留、已删正文不泄漏、回滚退出与原子删除；全量 `687/687`、typecheck、三份本地正则契约与生产 build 通过；
