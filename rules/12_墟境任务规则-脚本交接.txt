# 墟境探索：工作台、正文与时间内核的分工

本文件是开发侧流程说明，不整体发送给创作 API。候选、任务草案与蝴蝶效应由独立 API 创作；正文负责当楼叙事及既有 MVU 更新；时间内核校验授权、轮次和冻结时地。界面、候选缓存或档案不能自行决定玩家处于现实还是墟境。

## 一、三个子模块与阶段

点击侧栏“墟境探索”才展开墟境生成、墟境任务、蝴蝶效应。未进入只开放生成；探索中锁住生成和再次进入，开放本轮任务与蝴蝶控制台。浏览、编辑或确认参考不建聊天楼，不改变世界时地。

生成采用提纲批次→逐篇扩写。地点与内容方向决定史稿主体，时期与讲述/节奏/情绪是详细创作参考，不抽旧背景/冲突/导火索骰表。缘起、经过、高潮、结果四节点都可进入，shift 起止可相同。

## 二、选定并进入：一条玩家楼

点击“进入此节点”之前校验同卡/聊天候选、节点、ready 状态、可介入条件、当前 idle 和完整现实锚点；发送前再次核对命名空间。失败不发送半截命令、不建楼、不改变量，连续双击不得重复发送。

正常玩家楼保留玩家原话或默认进入语。脚本把完整【历史工作台·单楼进入契约】和唯一 RuinTrace 放进绑定本楼的隐藏协作通道，不把内部资料塞满输入框。契约来自点击瞬间现实锚点、所选节点时地、现场投影与脚本指定轮次；不沿用候选生成时的现实快照。

紧邻助手楼自然承接原现场并抵达所选节点，只表现该时刻可感知、可介入的局势；不从整篇缘起重演，不提前演完后续阶段。入境不自动建立任务。回复末尾按现有规则输出唯一完整变量更新；时间内核核验契约与楼层，锁定本轮现实时地、建立进入/当前时地与 exploring。

RuinTrace 从同一份已校验史稿确定性序列化，不由模型重新创作：
```text
[RuinTrace]
Title:: {{candidate.title}}
Type:: {{中文时期}}
Span:: {{candidate.span.label}}
History:: {{candidate.historyProse全文}}
Shift:: {{中文起止时期}}
NodeTime:: {{node.time.label}}
[/RuinTrace]
```
字段名、顺序、双半角冒号与标签保留；完整史稿不按字符切短。入境协作通道与最终可见面板各司其职，不再创建额外候选确认楼或第二份 RuinTrace。绑定助手楼完成或失败时清理注入；换卡、换聊天、旧楼/旧轮请求失效，不能残留到其他存档。

## 三、墟境任务：方向变成可执行目标

仅在本轮 exploring/anchored 时使用，入境不自动生成任务。玩家选择演绎权限与任务规模，API 只创作一项草案：
- 原意锁定保留动作、对象与目的；情境补全让现场顺序和完成条件更清楚；自由演绎可增加有依据的反应与波折。
- 即时互动是一两个当场动作；短程目标在当前或相邻场景；阶段任务可跨多个紧密相关场景。
- 把趣味放在具体动作、人物回应、可观察条件与相关道具上，不给轻量方向附加使命，不代替玩家行动或预判成功。

流程：输入→独立 API 草案→审阅修改名称/详情/目标→确认后只填入“确认墟境任务：任务名”→玩家补写行动并亲自发送→封缄本楼任务→紧邻助手叙事/MVU→脚本替换唯一请求占位槽为 task_info。

stat_data.任务列表仍是唯一任务事实源，面板展示同一记录，不形成脚本/正文双写。有非终态墟境任务时不得再生成一项；终态后仍在本轮才可建立下一项。字段与任务名前缀沿用现有协议，不新增状态体系。首次终态追加唯一 task_result；同楼返程时先处理任务终态卡，再追加蝴蝶面板。

奖励由脚本确定 FP、货币数值与结算形式，模型只创作符合当前条件的相关道具。每份新草案读取启用的经济资料，优先明确地方实体币，无法归属时使用世界书明确的通用实体币或通用价值结算；不得伪造币名、模糊“当地通货”或把 Z 冒充实体币。封缄后保留原币制与金额。没有可信结算依据才报错，不把所有地域歧义当必失败。

确认任务只进入 staged，不自动发送。玩家楼绑定 chatId/runId/楼层/任务哈希；助手重抽逐字复用同一封缄任务，不重调 API，删除确认玩家楼才恢复编辑。聊天/轮次变化隔离迟到结果。

## 四、蝴蝶控制台：先准备，后创建返程楼

正文“遣返吧”等只表达意愿，不再发起新的返程。伊雍引导玩家到工作台确认本轮参考方案、点击“遣返现世”；已确认偏好也不等于按钮授权。只有本楼真实脚本协作请求才允许正文返程。

按钮流程：
1. 核对本轮活动状态和已确认的九项参考。冻结同卡/聊天/runId、现实/进入/离开三锚、完整行动、带回决定、相关史料与方案版本。
2. 后台创作并校验蝴蝶效应，保存完整准备结果。此时尚未建立玩家返程楼，也未恢复现实时地。收集/生成失败或取消只结束准备，保留可重试依据和探索状态，不让玩家空等。
3. 准备成功后创建唯一正常玩家楼。输入框非空则保留其完整文字，即使没有“遣返”也有效；为空使用默认返程文字。隐含事务授权由脚本写入并回读核验，不靠玩家文本标题判断授权。
4. 核对命名空间、runId、消息正文/当前 swipe 与来源；登记授权成功才触发一次正文生成。登记失败保留玩家楼并提示重试，不跳过安全门。
5. 隐藏【伊雍遣返正文协作请求】携带冻结时地、实际行动与已生成蝴蝶全文，正文完成返程和唯一 MVU 更新，不再生成第二份蝴蝶面板。
6. 时间内核按同楼授权恢复冻结现实时间地点，不把墟境时间叠加到现实，也不把 presentLanding 当传送地点。核验作用域及迟到写回，归档本轮并清空活动状态。

偏好确认/冻结/准备与现实恢复是不同阶段。不能沿用旧文档“先返程再并行生成”的顺序，不能在准备失败时宣称遣返已完成。此说明只同步现有实现，不更改内核。

## 五、追加、Canon 与原文召回

绑定的助手楼完成后，用已校验 JSON 确定性渲染一个 butterfly_panel；只追加/替换该面板，不改玩家正文、伊雍对白或变量更新。核对当前聊天、轮次与目标消息后，保存本地结构化原稿并幂等提交 Canon。

专用世界书镜像写入已退役。原文归档在本地，现行 Canon 与关键词召回在当前聊天的受控注入通道提供事实和完整传记/蝴蝶原文；换卡/聊天/卸载清理通道。不根据档案数量重建墟境状态。

已准备结果、正文追加与 Canon 提交失败分别显示当前阶段，重试只补未完成步骤，不无故重生成。旧 message_committed/mirror_pending 状态沿用兼容值，后者现在表示待 Canon/归档收尾，不表示继续写世界书镜像。

## 六、重抽与删除

同一有效玩家返程楼重 roll 正文，复用已冻结请求与完整蝴蝶结果，重新绑定面板/Canon 而不新增 API 调用或重读当前表单。删除玩家返程楼撤销相应有效关联；下一次在控制台点击按钮重新冻结并生成。

准备期间行动、方案或聊天改变，不给迟到结果签发新授权。角色/聊天/run/swipe/消息正文等守卫保持有效，不能为容错移除。历史赎出连续性承接成功契约与明确带回，原历史离去后的旧人生不自动重演。

## 七、失败边界

生成 API 不输出返程叙事、伊雍对白、面板或变量更新。正文不自行补写另一份蝴蝶效应，面板不恢复时空状态。冻结缺锚、来源不足、API/协议错误与事务登记失败分别报告，不把软偏好不符当新拒收门，不截断完整史稿。真正已完成返程后的归档错误只重试归档，不把玩家退回墟境。
