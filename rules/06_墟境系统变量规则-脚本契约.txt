# 唯一数据源

- 运行数据根: `墟境系统.运行状态`
- 展示快照根: `墟境系统.虚嗣指南快照`
- 世界当前时间: `世界.时间`
- 世界当前地点: `世界.地点`
- 禁用旧路径: `事件.伊雍`

# 所有权

- 现有时间控制/MVU模块是状态写入与世界时地同步的唯一权威。
- 历史生成API、宗族谱系API、传记书库和候选节点界面全部只读。
- 新界面不得根据文本语义自行推断或修复 `idle/exploring/returning`。
- 本契约不改变已经稳定运行的进入锚点、离开锚点、归档和清空流程。

# 状态显示

- `idle`: 未探索。候选生成器可用；当前墟境区域为空。
- `exploring`: 墟境探索中。显示轮次与当前墟境时地。
- `anchored`: 已定锚，等待玩家后续选择。
- `returning`: 遣返结算中，不允许生成新的进入指令。

# 轮次隔离

- 候选生成请求使用独立 `requestId`，不得拿它替代 `墟境轮次`。
- UI缓存键必须包含聊天标识与 `requestId`。
- 进入后才把选中候选与当前 `墟境轮次` 建立关联。
- `墟境轮次` 变化时，旧候选只可查看，不可直接再次进入。
- 状态回到 `idle` 后，清除“当前选中节点”，但保留传记书库和族谱缓存。

# 写入例外

本历史系统自身不直接写MVU。进入与遣返经脚本注入层(常驻注入, depth 0 / system)与唯一玩家楼触发:

- 进入: 脚本把「进入节点 + 单楼进入契约 + 已选历史阶段的唯一 RuinTrace」注入上下文,并以玩家原话(或默认语)建立唯一玩家楼触发正文;缘起、经过、高潮与结果均可进入，内部 `anomaly` 仅作旧存档兼容；注入层在目标助手楼渲染后清理。
- 玩家生成时可以填写地点简称；进入契约中的目标地点必须是 `${大陆名+方位}-${势力/区域}-${子级势力}-${聚落/地标}-${区位}-${详细位置}` 形式的 4～8 层路径。`墟境当前地点`、`本轮墟境进入地点` 与 `世界.地点` 必须逐字复制同一目标地点，不得分别概括。
- 遣返: 只能在「墟境探索 → 蝴蝶效应」确认本轮参考方案后，点击「遣返现世」。脚本先完成冻结与后台准备，成功后保留输入框原话（为空用默认返程语）建立唯一玩家返程楼并签发同卡/聊天/轮次/楼层授权；准备失败不创建返程楼。聊天口头遣返不是授权，正文只由伊雍引导去工作台，不清空活动状态或恢复现实时地。已冻结失败的显式重试与旧成功归档保持兼容。

`墟境探索`的候选生成**只能由历史工作台界面发起**（墟境探查栏「按历史波动生成候选」）；聊天文本里的任何提及都不触发，伊雍只负责把玩家引导去工作台。候选生成只发生在界面，不发送候选确认楼，不改变流程状态。

随后由正文模型和现有MVU规则产生变量更新。

# 生成阶段的宗族出场边界（0.13）

- 本地谱系可被查询不等于其中人物自动成为演员；「自动关联宗族人物」默认关闭，开启后也必须有本人在目标地点的活动依据。
- 手选单个 MVU 或谱系人物保留独立使用通路，不受自动关联开关限制，不连带其他亲属。
- 方向明确要求本人经历，或「探讨玲山父亲的发家史」等亲属事件时，召回已存姓名与亲缘边中的真实主体；父亲的史不要求女儿在场，也不以女儿出生年限制父亲的早年历史。
- 「参考某人的性格/人设」只作参照；亲属关系、收藏、后嗣现居地与种族不能证明祖辈实际在场。明确要求跨境访问时可补合理行程，但不得重写原籍或效忠。
- 亲属不唯一时提示补充姓名或手选，不任意挑选，也不另加一次后台模型调用。
- `shift.from/to` 表示事件起末状态，二者可以相同，也可以与主导 `periodType` 相同；稳定持续、动荡延续都是合法历史，不为凑转变硬造变化。缺失端点仍不得被静默填充成主导期。
