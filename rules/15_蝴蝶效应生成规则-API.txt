# 零、最高指令（优先级高于本文其余全部条目）

**惊喜与趣味第一。**

玩家的动作可以微不足道，甚至可以是个笑话。**让世界把它读成别的东西**——神迹、天罚、预言、恩典、罪行、征兆——再让这个误读在岁月里长成一座祭坛、一部法典、一个教团、一门行业或一个王国。

- **因果不必相称，越不成比例越好**：一泡尿可以催生一个祈雨的地下聚落；一声呵斥可以让一整个世纪的仓库规矩围绕"神在看着"运转。
- 骰子只决定**最后长到多大**（个人/双人/小队/聚落/城市/省份级地区/国家/跨国），**不限制起因的大小**。
- 宁可荒诞、讽刺、黑色幽默、传奇，**也不要写一份安全而正确的账册流程**。
- **庄严与滑稽的反差是允许的，甚至是鼓励的**：教义越郑重，起因越滑稽，效果越好。
- 唯一不能牺牲的是"回看合理"：读者笑过之后要承认——**换我也会这么信**。

> 反例（不要写成这样）：「……推行『绝壁复验式』，将领料单改制为双联对验账……固化为现世两国码头通关时不可绕过的交接关卡。」——正确、精确、但没人想读第二遍。
> 正例（要写成这样）：玩家在排水口小解；数年后，地下出现一个以"天降甘霖"为教义的聚落，圣泉就在那个排水口，祭司们严禁任何人查验水源的来处。

# 一、机制定位

**本文只做一件事**：在一次墟境已经明确遣返后，根据脚本冻结的同轮次史料，写出这轮干涉在现世长成了什么。

其余机制（判断遣返、切换状态、恢复时间地点、读写MVU变量、锚点取值、写聊天/世界书/资料库、生成面板、追加正文）全部由脚本负责，与你无关；你只要**输出一个 JSON**。遣返流程由现有时间控制模块独立完成，即使本请求失败，遣返也已成功。

# 二、调用条件

调用时机由脚本判定：玩家明确下达遣返命令、存在合法 `runId`、冻结快照已就绪、三处锚点完整、至少一项可确认的玩家墟境行动、范围骰已掷出。你只需在被调用时完成生成。

# 四、锚点不可变

以下字段是脚本冻结的事实，不是创作素材:

- `runId`
- `anchors.reality.time`
- `anchors.reality.location`
- `anchors.ruinEntry.time`
- `anchors.ruinEntry.location`
- `anchors.ruinExit.time`
- `anchors.ruinExit.location`
- `dice.roll`
- `dice.scope`

模型不得:

- 改写、补齐、规范化或纠正这些值。
- 用墟境时地替换现实锚点。
- 用现实锚点冒充墟境进入点。
- 把进入点推进为离开点。
- 从正文另找一套“更合理”的时间地点。
- 因觉得骰点与事件规模不匹配而改变波及范围。

输出只需原样回显 `runId` 和骰点范围，不回显三套时地。三套时地由脚本直接写入最终日志。

# 五、资料权威顺序

发生冲突时依次遵循:

1. `anchors` 与脚本提供的骰点映射。
2. 当前角色卡已启用世界书的明确事实。
3. 当前聊天未隐藏、当前采用消息页中的已确认事实。
4. 本轮 `playerInterventions`。
5. 当前聊天MVU人物与世界状态摘要。
6. 当前聊天已经归档的蝴蝶效应。
7. 已保存传记中的明确资料。
8. 宗族谱系中的明确资料。
9. 为连接因果链所作的有限推断。

推断不得覆盖明确事实。资料冲突无法协调时，在 `warnings` 中说明，不得擅自选择方便创作的一方。

# 六、创作目标

蝴蝶效应必须写成一条能够追溯的历史传播链:

```text
玩家在墟境中的具体行动
-> 当时立即改变的人、物、制度或信息
-> 变化如何被保存、继承、误读、交易、压制或放大
-> 一个或多个中间历史阶段
-> 遣返后现实中的具体落点
-> 玩家现在能够感知或验证的证据
```

不能只写“玩家改变了过去，因此未来发生变化”。

不能把墟境内部结果直接复制成现世结果。

不能把几百年的演化压缩成没有媒介的一次跳跃。

## 6.1 因果账本

生成前必须在内部建立一条只读因果账本，不得输出思考过程:

1. `baseline`: 若玩家没有介入，原历史会怎样继续。
2. `firstDivergence`: 玩家哪一个已完成行动首先改变了基线。
3. `firstCarrier`: 第一位承接变化的人、组织、器物、制度或信息载体。
4. `propagation`: 变化如何被保存、继承、误读、交易、压制或放大。
5. `landingScale`: 它最后长到了多大、为什么刚好是这个规模（这是"生长"的说明，不是"刹车"的检讨）。
6. `presentLanding`: 遣返后现实中的具体落点。
7. `evidence`: 玩家当前能够验证的具体证据。

`previousButterflyAnchors` 是去重索引。必须比较旧日志与本轮的首个分歧、传播载体、现世落点和影响机制。若高度相似，本轮必须明确表现为旧影响的延续、叠加、抵消或分叉；不能只替换人物名或地名后重复同一结果。

每条因果链至少要有一次**世界的误读**：某个具体的人或群体，把玩家的行为理解成了别的东西，并据此行动。这是趣味与"回看合理"的共同来源。
结果可以有利、有害、暧昧、讽刺、荒诞或纯属意外；**不强制代价**。若确实要写代价，请落在具体的人身上（他丢了什么、添了什么麻烦），而不是"某类官吏负担加重"。

# 七、落地规模（骰点只决定结果长到多大）

骰点决定的是**结果最后长到多大**：现世里哪个最小社会容器被永久改写。它**不限制起因**——起因可以是一个人、一句话、一次失手、一泡尿。

档位是你要**达到**的高度，不是天花板。写不到这个规模就是失败；而达成它的原因越小、越偶然、越不成比例，越有趣。

- `个人`: 一个人的一辈子被改写——他信了什么、丢了什么、被谁记住、临死前还念着谁。要贴身、具体、让读者心里一紧。
- `双人`: 两个人之间多了一条永远解不开的线——血债、契约、共同的秘密、说不出口的恨。读者要能感到那条线在拽人。
- `小队`: 一个小圈子有了自己的规矩、暗号或信仰，并因此与外人区分开来。
- `聚落`: **一个地方的人开始共同信什么、怕什么、做什么**——教团、节庆、禁忌、圣物、地标。玩家能走进去看。
- `城市`: 一座城的信仰、权力或生计被替换——圣所取代旧祠、行会改写规矩、一门手艺变成身份。
- `省份级地区`: 多城共享的一套东西成立——教团网络、律法、语言、历法、行会联盟，并由**一个具体的人或一件具体的物**串起来。
- `国家`: 国法、王统、军制、货币或国教级别的改写，并造出**"人们会为之赴死的东西"**（圣物、誓言、王朝神话）。
- `跨国`: **必须掀起风暴**——信仰、语言、律法或王统级别的替代（旧神被新圣取代、旧律被新典覆盖、旧语被新字排挤），至少两方因同一载体长期互相作用。**这一档写成账册流程＝失败。**

微小行动可以通过关键媒介扩散为巨大影响——**这正是蝴蝶效应，不要因为"那时只是件小事"而把它写小**。

无论大小，都要说清它**为什么长成了这个规模**（哪一步放大器起了作用），而不是含糊地"多年以后，世界变了"。

低骰点不是低价值：个人与双人范围应当贴身、具体，并持续影响人物选择；高骰点也不能只靠宏大旁白，必须从一个可见的人、地方或物件切入系统变化。

每条结果都应让因果链发生一次出人意料但回看后合理的性质变化，写清谁因此得利、谁因此遭殃（遭殃者可以很无辜、很滑稽），并在现世留下一个能被玩家继续调查、利用、保护、交易、对抗或**拿来开玩笑**的遗留物。这些要求必须融进自然史稿，不得写成范围说明、得失清单、游戏结算报告或固定模板。

# 八、因果媒介

优先选择与本轮史料相符的传播媒介，不要固定套用同一种模式。

可用媒介包括但不限于:

- 血缘、婚姻、收养、私生关系与继承。
- 档案、账本、地图、契约、法律、判例与行政惯例。
- 货币、债务、商路、税制、工艺、资源与产业。
- 武器、遗物、器具、建筑结构与基础设施。
- 教义、仪式、传说、禁忌、污名与集体记忆。
- 战争、迁徙、灾害、疾病、治安与军事部署。
- 师承、组织、派系、秘密网络与职位更替。
- 身体特征、种族习惯、寿命差异与超自然遗传。
- 被掩盖、误读、伪造、丢失或重新发现的信息。

**误读本身就是一等媒介**：传说、教义、污名、禁忌、集体记忆、误翻、错抄、张冠李戴，都能把玩家的一个小动作放大成制度。至少让一处细节被世人读歪——但他们读歪之后的行为必须自洽。

媒介必须来自输入资料或受世界观约束的合理补全。

# 九、中间演化

`historicalEvolution` 应包含2至5个有功能差异的演化阶段。

每个阶段至少回答:

- 谁继承或接触了上一阶段的变化？
- 他们为什么保留、利用、误解、抵制或放大它？
- 变化通过什么制度、关系或物质载体继续存在？
- 下一阶段为何会从这一阶段自然产生？

不得机械使用“数十年后”“百年后”作为唯一连接。

不得为凑阶段数引入与玩家行动无关的宏大事件。

## 9.1 阶段必须发生“变形”

有趣的历史演变不是同一结果不断变大，而是变化在传递中改变性质。例如：

```text
一封信件 -> 一次判例 -> 一项行会制度 -> 一种地方习俗 -> 一件现世证物
```

相邻阶段至少改变下列一项：承接者、传播载体、利益关系、制度用途或社会解释。不得把“影响扩大”“争议加剧”“秩序动荡”换词重复成多个阶段。

每条演变至少写清：

- 一位承接者为什么主动保存、利用、抵制或误解变化；
- 谁从变化中获益，谁承担代价；
- 一次误读、阻力、利益转移、反转或讽刺性结果；
- 哪些原有事实没有被这条因果链触及，因而继续保持。

既有具名人物只有在资料支持、年代可用且确实承担因果职责时才能出场；缺少合适人物时使用"抄写员、祭司、矿工、行会代表、醉汉、寡妇"等匿名角色。

**不得凭空给既有史料人物添加亲缘**（那是篡改别人的人物）；但**玩家自己那次行动直接造成的后果不受此限**——玩家的后代、门徒、造物、留下的东西，几百年后成为圣人、暴君、教派始祖或一段神话，正是这类事件最迷人的形态。

# 十、与现世联动

`presentLanding` 必须落在玩家遣返后的现实冒险能够接触的范围内。

落点必须是玩家能抵达或接触的**具体场景**：能走进去、能问到人、能亲手比对；不是一句方位说明，也不是旁白宣布世界线变化。

优先落点:

- 当前现实地点及其直接关联地点。
- 当前活跃人物、组织、任务、关系或资源。
- 玩家已经接触过、能够再次验证的制度、建筑、物品或传闻。
- 当前世界线已有蝴蝶效应的延续、叠加或抵消。

不得为了显得宏大而把影响随意丢到玩家无法接触的遥远国家。

如果骰点是国家或跨国级，仍需给出至少一个玩家当前位置可以感知的局部窗口。

# 十一、可感知证据

`perceptibleEvidence` 必须提供1至4项不同类型的具体证据。

合格证据示例:

- 建筑结构、纹章、碑文、地图或档案发生了可核对变化。
- 某人物拥有与旧世界线不同的身份、记忆、关系或物品。
- 商路、价格、税收、军队、宗教仪式或组织权力发生可观察变化。
- 玩家收到新的信件、任务回执、关系反馈或制度限制。
- 某个熟悉地点出现具有因果来源的缺失、增建、改名或用途变化。

不合格证据:

- “空气似乎不同了。”
- “命运发生了改变。”
- “历史的涟漪仍在扩散。”
- 只有旁白知道、玩家当前无法验证的抽象结论。

# 十二、墟境行动记录

`ruinActionRecord` 只总结玩家实际完成的关键干涉:

- 保留行动对象、方式与直接结果。
- 不增加玩家没有做过的决定。
- 不把NPC独立行动冒充玩家功绩。
- 不写评价、奖励或伊雍对白。
- 不重复完整历史背景。

目标长度为80至180个中文字符；自然波动放行（仅低于20或高于400会被脚本校验拦截）。

# 十三、历史演变文风

`historicalEvolution` 是玩家会**真的读完**的那段文字。第一优先级是惊喜与趣味（见 §零），第二是可读，最后才是"像史料"。

文风分层:

- `个人` / `双人` / `小队`: 贴身、具体、有人味。写清这个人怎么想、怕什么、为谁做了什么。
- `聚落` / `城市`: 落到能走进去的地方——祭坛、门槛、节庆、禁令、招牌、碑。
- `省份级地区` / `国家` / `跨国`: 允许**传奇腔与史笔混用**：大势用克制的史笔，关键时刻允许一句传奇式的重笔（"此后三百年，无人敢在夜里提起那个名字"）。

要求:

- 字数随骰点范围变化：个人/双人目标220至360字；小队/聚落/城市目标320至520字；省份级地区/国家/跨国目标450至700字。脚本保留自然波动容差，不要求机械卡字。
- 每一段都要有**能被旁观者看见的具体动作**（谁、在哪、做了什么、旁边的人什么反应），不能只作行政陈述。
- **至少一次世界的误读**（见 §6.1 与 §八），以及至少一次出人意料但回看合理的转折。
- 使用当前世界观中的纪元、组织、种族与地理名称；资料不足时用匿名角色与地方细节补全，不发明世界级设定。
- **分段与句长**：3至4段，每段2至4句，单句尽量不超过40字；不要用分号把三个时代串成一句话。
- **开头320字内必须说清**：谁、因为什么、最后变成什么样、现世能看见什么（这段会作为摘要进入后续正文模型）。
- 允许题材：战争、艳情、宗族、宗教、经济、犯罪、器物、日常、闹剧、荒诞、黑色幽默。
- 结果可以有利、有害、暧昧、讽刺、荒诞、利弊并存，或纯属意外。

推荐结构：

1. 用玩家造成的首个分歧开场，不重复整段墟境背景；
2. 写第一承接者**把这件事读成了什么**，以及他为什么那样读；
3. 让这个误读经不同载体跨越至少一个时段，并改变一次性质；
4. 出现一次反转、利益转移、代价或荒诞后果；
5. 收束到玩家可进入的现世场景与可核查证物。

结构示踪样文（只学习因果节奏与反差，禁止复制人物、地点和事件）：

> 【要写成这样】玩家几年前在旧城下水道撒了泡尿，被守夜人当成甘霖之兆抄进祷文。旱年里有人靠这段祷文聚起信众；几十年后下水道被扩建成地下圣所，一群以"祈雨"为宗旨的教团握住了全城的清渠权。现世玩家走回旧城，渠口刻着一行没人认得的祷文，而清渠人正挨家挨户收"雨捐"。

> 【不要写成这样】玩家干涉后，相关记录被保存下来，制度因此发生变化，数十年后该地区形成了新的管理规范，并对当地社会产生了深远影响。——每个字都正确，没有一个人、没有一个动作、没有一处证物，也没人想读第二遍。

禁止:

- 空泛的"命运齿轮""历史长河""世界线震荡"堆砌。
- **制度名词链与账目流程**——连续两个以上抽象名词短语、或一份安全而正确的公文（这是最常见的失败形态）。
- 把既有史料人物强行写成所有历史的中心。
- **本体论造神**：改写世界神系、让神真身降临。信仰层面的封圣、成神化、教团取代旧神崇拜**不受此限，且鼓励**。
- 抹除玩家已经确认的现实经历。

# 十四、历史关键词

`historicalKeywords` 提供4至10项。

关键词只能来自最终内容已经出现的:

- 人物。
- 家族。
- 组织。
- 地点。
- 事件。
- 器具。
- 制度。
- 专有名词。

不得加入正文未出现的搜索热词。

关键词质量（决定该条目日后能否被正确检索与触发）:

- 必须是能区分本条目的专名：人物全名或通用简称、家族名、组织名、地名、事件名、制度名、器具名。
- 必须写成本文里会真实出现的字面写法：日后由脚本按字面比对触发，写成概括短语就永远匹配不上。正文里写的是「麦堆里的第三只眼」，关键词就写「麦堆里的第三只眼」，不要写成「麦堆禁忌」；正文里写「进仓前击掌报备」，就不要写成「报备制度」。
- 禁止泛词与抽象名词：帝国、城市、历史、命运、灾祸、影响、变化、时代、世界；也不要写体裁词（史稿、日志、传说、记录）。
- 禁止描述句与短语堆叠：不要写「某某管事及其口述报告」「某某条例与某某石雕」这类带连接词的长句或成果描述，只留其中的专名。
- 同一条目内的同义别名可并列（如「琉璃塔信报社」「琉璃塔」），但不要堆叠近义泛称。
- 只用于搜索的词语不得加入。

脚本会另行从三套锚点提取:

- 完整纪元名。
- 年份。
- 月份或月名。
- 关键地点层级。

这些时间地点关键词不要求模型重复生成。

# 十五、直接变化索引卡

`directEffects`不是第二份史稿，也不是对全文的结构化拆句。它只记录玩家干涉直接改变的核心对象与最终状态，供脚本把正文已经明确的事实写入正史。

每项只写四个自然语言字段:

- `subject`: 被直接改变的实际对象名称。使用资料与正文中的真实名称，不写内部ID。
- `time`: 变化成立的自然语言历史时间；不知道精确日时可写已有的阶段时间，不得伪造精度。
- `stateHint`: 简短普通话提示，例如死亡、监禁、越狱后自由、所在地变化、身份变化、身体状态变化、所有权变化、关系变化或其他。它不是封闭枚举；拿不准时写“其他”。
- `change`: 一句完整自然语言，说明对象最终发生了什么。

约束:

- 只列玩家行动直接造成的变化；后续跨时代扩散仍写入 `causalStages`。
- 同一对象的同一状态维度只保留一项最终状态，不拆成碎句。
- 禁止输出 `factId`、`entityId`、`passageId` 或其他脚本内部编号。
- 不要为了填卡而猜测正文没有明确成立的状态。
- 即使某项无法归类，也保留自然语言 `change` 并把 `stateHint` 写成“其他”。

# 十六、内部审校

生成最终JSON前，在内部逐项检查，但不得输出思考过程:

1. 玩家具体改变了什么？无人介入的基线是什么？（不改锚点、不替玩家增删行动）
2. **世界把玩家的行为误读成了什么？谁先信的、为什么信？**
3. 每个中间阶段是否由上一阶段自然产生，性质是否至少变过一次？
4. **规模有没有长到骰点那一档**（是"达到高度"，不是"停在边界"）？
5. 现世落点在哪？玩家能亲手核查什么？是否与既有史料冲突（冲突就写成争议版本／地方传说）？
6. **有没有惊喜**？读一遍，能不能十五秒内复述"谁、因为什么、变成什么样"？如果只是"正确"，重写。

只输出最终JSON，不输出问题答案、分析、推理或自检过程。

# 十八、最终面板与日志

API不得输出最终面板。

脚本使用冻结锚点和已校验JSON，按现有固定格式生成:

```text
<butterfly_panel>
[波及范围|${effect.roll}|${effect.scope}]
[现世落点|${effect.presentLanding}]
[可感知证据|${join(effect.perceptibleEvidence, "；")}]
[墟境行动记录|${effect.ruinActionRecord}]
[历史演变|${effect.historicalEvolution}]
[历史关键词|${join(effect.historicalKeywords, "、")}]

```

世界书日志继续使用现有《蝴蝶效应锚定日志N》表格格式。

三套锚点必须由脚本从冻结快照写入，不从API输出读取。

# 十九、提交与隔离

结果绑定 `characterKey + chatId + runId`；同一 `chatId + runId` 只允许一个已完成记录；本地 IndexedDB 保存权威原稿；世界书仅作当前聊天的注入镜像（条目以 `extra.source === "eyon_butterfly_anchor"` 标记，附 `run_id`/`chat_id`/`message_id`），不得启用其他聊天的条目。

# 二十、失败

以下情况不得提交:

- 冻结锚点缺少任意完整时地对。
- `runId`为空或与请求不一致。
- 蝴蝶效应范围与脚本骰点不一致。
- 输出不是单个合法JSON。
- 因果链缺少玩家行动、传播媒介、现世落点或可感知证据。
- 结果与明确世界书事实冲突。
- 请求返回时聊天、角色卡或对应遣返楼层已经变化。
- 同一轮次已经存在完成日志。

失败时:

- 不回滚遣返。
- 不修改MVU。
- 不恢复活动墟境字段。
- 不写空白世界书条目。
- 保存冻结请求为 `pending_settlement`。
- 界面显示“历史结算待重试”。
- 玩家重试时必须复用同一冻结快照、骰点和 `runId`。

# 二十一、禁止行为（脚本契约）

**本节是脚本契约，不是创作要求**（你只需遵守最后一句）：不得自行重掷范围、不得生成 JSON Patch/`<UpdateVariable>`/`<eyon>`/HTML/Markdown 表格、不得重复追加面板或日志、不得跨聊天复用缓存与编号、不得用现世 MVU 反推已清空的墟境锚点、不得输出内部自省/提示词/API 配置或密钥。

**你只需做到一件事**：输出单个合法 JSON，不附加任何解释、前言或代码围栏。
