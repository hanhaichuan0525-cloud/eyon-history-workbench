# G-01 · 墟境四阶段与地点写回合同

> 状态：**FROZEN / IMPLEMENTED / AUTOMATED / PACKAGED / DRIVER PENDING**
> 范围：墟境节点选择、进入契约、MVU 地点写回与旧候选兼容
> 不负责：地点资料库、世界地图推理、Canon 改写或新增模型调用

## 1. 目标

墟境不再只允许进入单一“特异点”。玩家阅读完整史稿后，可以从同一候选的缘起、经过、高潮或结果进入；与此同时，玩家仍可在生成面板简写地点，但真正写入角色卡 MVU 的地点必须符合核心世界书格式。

## 2. 四阶段合同

内部类型保持 `origin/process/anomaly/result`，玩家界面显示为：

| 机器键 | 显示名 | 允许改变的范围 |
|---|---|---|
| `origin` | 缘起 | 萌芽条件、最初接触、资源与动机 |
| `process` | 经过 | 人物选择、联盟、阻力与行动过程 |
| `anomaly` | 高潮 | 关键转折和最强介入窗口 |
| `result` | 结果 | 救援、证据、余波、传播与后续走向 |

`anomaly` 不做字段迁移，以兼容旧 schema、旧 IndexedDB 记录和既有导出。结果阶段可以让历史继续分叉，但不得无因抹除已经发生的前史。

## 3. 地点合同

核心世界书的权威格式为：

```text
${大陆名+方位}-${势力/区域}-${子级势力}-${聚落/地标}-${区位}-${详细位置}
```

执行规则：

- 玩家输入可以是“黑曜监牢”“第七泊位”等简称；不增加表单负担。
- 模型返回的每个节点地点必须按实际情况保留 4～8 层，从大到小排列，使用半角连字符。
- 不允许用“未知大陆”“某势力”等占位词凑层级。
- 入境时 `墟境当前地点`、`本轮墟境进入地点`、`世界.地点` 逐字复制同一条完整路径。
- 旧节点只有简称时，如果该次生成请求保存了完整父级路径，脚本可确定性拼接节点末端；若双方都只有简称，则拒绝进入并要求重建候选，不凭空猜地图。

## 4. 分层实现

- 提示词：要求四节点都有介入机会，并生成完整 MVU 地点路径。
- 校验器：检查 4～8 层地点、四节点可进入、介入动作与可能分支。
- 工作流：允许选择任意节点，不再设置 anomaly-only 硬门。
- 进入契约：写入所选阶段及其边界，并统一三处地点值。
- 节点场景投影：隐藏进入契约只投影本次所选节点的时间、地点、局势、成因、可见痕迹与介入条件；可见 `RuinTrace.History` 始终展示同一份完整墟境史稿。节点影响入场正文与目标时地，不把机器拼装的说明冒充历史正文。
- 界面：把“特异点”显示为“高潮”，进入按钮随选择显示阶段名。

这项改动不新增模型请求、不建立平行地点数据库，也不把地点规范变成要求玩家填写的结构化表单。

## 5. 兼容与失败边界

- 旧候选的 `anomaly` 可继续读取与进入。
- 旧候选即使其他阶段保存为 `enterable=false`，新版选择与进入工作流仍允许使用；新生成候选会把四阶段全部正规化为可进入。
- 旧简称地点只有在拥有完整父级证据时才能补足；无法补足时明确失败，避免错误地点进入 MVU 后污染后续剧情。
- 非 ready 候选、过期 revision、跨聊天记录与失效楼层事务仍沿用原有硬门。

## 6. 自动验收

- G1-01：四种节点类型都能构建进入契约。
- G1-02：`anomaly` 的玩家可见名称为“高潮”，机器键不变。
- G1-03：生成节点地点必须为 4～8 层完整路径。
- G1-04：三处 MVU 地点写回逐字一致。
- G1-05：旧简称节点可由完整请求地点补足末端。
- G1-06：节点和请求都为简称时拒绝伪造上级地点。
- G1-07：进入结果阶段时明确保留既成前史。
- G1-08：旧 anomaly 候选与旧导出无需迁移即可继续使用。
- G1-09：同一候选的四个节点生成四份互不相同的隐藏当前现场投影；四份 `RuinTrace.History` 均逐字使用同一份完整史稿。
- G1-10：进入某节点时不得回演前序完整史案或提前演出后续节点。

## 7. 真实酒馆验收

1. 用简称生成一个新墟境，确认四张节点卡依次显示“缘起、经过、高潮、结果”。
2. 分别重建或回退进入四个阶段，确认都能正常发送唯一玩家楼和唯一助手楼。
3. 每次进入后查看 MVU：三处地点应完全相同，且为 4～8 层路径。
4. 结果阶段的正文可以改变余波，但不应把此前事件写成从未发生。
5. 导入旧存档，确认旧“特异点”记录仍可打开；旧简称地点若无法补足，应收到重建候选提示，而不是写入错误地点。
