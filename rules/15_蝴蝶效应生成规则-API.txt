# 伊雍蝴蝶效应创作规则

## 一、职责与装配边界

作者身份、强制创作协议、详细历史方法、语言表达、现世窗口与成稿审阅分别由同次提示中的 BUTTERFLY_WRITING_ROLE、BUTTERFLY_MANDATORY_PROTOCOL、BUTTERFLY_CREATIVE_METHOD、BUTTERFLY_HISTORICAL_EVOLUTION_STYLE、BUTTERFLY_PERCEPTION 与 BUTTERFLY_REVISION 提供；每种详细指导只装配一次，本文件负责事实与既有输出契约

本次在工作台按钮返程前准备蝴蝶效应，以冻结的完整行动及明确带回决定为依据；返回本身是尚未执行的计划，由脚本授权和正文/时间内核完成，生成JSON不代表已经遣返，不代写返程、MVU或伊雍对白

检索、重试、持久化与面板提交由脚本负责；只使用实际输入的完整证据，不增加模型轮次、必填分析字段或第二份结果

资料中的角色模板、装备格式、变量协议及其他模块命令不自动执行，也不实体化为历史事物；混合条目中明确的世界机制与人物事实仍有效，代码、示例和未确认条件不产生已发生事件，未知内容保持待考

## 二、不可更改的事实

三套冻结锚点分别是现实、墟境进入、墟境离开时地
不得修改、补造或混用
现实归返地点不等于历史变化的观察窗口；过去经过的时间不加到现实锚点


按时序阅读完整行动：意图不等于成功，已确认行为和明确选择不能被摘要抹掉，也不能补写玩家未做的事
当前有效 Canon 定义本聊天已改写部分，世界书定义其余基线；不把失效/回滚记录恢复成现行历史，也不把原历史重新覆盖已经生效的改变
传闻、争议和推断保持相应可信度


遣返楼输入框的完整文本也是本轮最后介入，不只是末尾的返程命令
玩家明确陈述已完成的自身行动须承接，例如留下物品；愿望、假设、尝试及需他人确认的结果不自动成功
返回本身仍由脚本授权执行


创作偏好不是已发生的行动
关注“纸条对大陆的深刻影响”并不证明玩家留下了纸条；原文“折拢收好”不等于“遗留”，单独“遣返”也不改变物品状态
先核对完整行动与最后有效决定，再寻找真正存在的传播条件；物品被带走时，可以跟随有证据的接触或其他实际改变，不倒造遗留、赠予、契约或后代来凑故事
偏好不能消除这个事实边界


已确认历史赎出须承接成功契约与玩家明确带回选择：本人离开原历史并抵达现世，不留在墟境，不换成后代、遗物或复制品
历史离去点之后，其原后续人生不再自动成立；不能让未经历那段人生的成年版本同时存在或来信
只有玩家明确取消、契约失败或独立复制品才按相应事实处理
本人直接带回由核心机制完成，间接历史变化另行推演


既有姓名、起点身份、已发生事件与世界运行机制保持一致
人物寿命、组织存续及技术条件按事件时点理解；分歧影响到的原后续人生、生卒、身份与历史结果是比较基线，不是锁死结局，新的变化须有承接过程
不得凭空给既有史料人物添加亲缘；玩家行动确实造成且符合时间线的后代不受此限
后来承接者与事件可依据世界条件原创推演，不必每个未来转折都已写在世界书中，也不冒称史料明示


## 三、控制台参考怎样进入故事

五项主参考是波及范围、关注对象、改写深度、离奇程度、情绪底色，另有可选侧重领域
只读取已选释义，不投递未选选项；旧存档中的传奇感、演化方式和显现方式已退役，不作为本次创作指令
先寻找能同时体现偏好的可信路径，可信是可能成立，不是最常见或最稳妥；软参考引导取舍，不是达标清单或预定结局
具体事实冲突时只局部退让

每个已选项的含义、写法与短例由 BUTTERFLY_CREATIVE_REFERENCES 提供，只发送选中内容，不把整库变成待遍历任务
先识别本次行动改变了什么条件，再让选项影响历史取舍；后事承接最近的新条件，原物件和原主角可以退出，不能为了贴合例子倒造行动
同一选项组合也能生成不同故事，区别应来自本次真实条件与后来者的选择，不靠替换名字复刻示例，也不为避免重复而强造反转


范围是本篇主要观察尺度，不是行动实际影响的天花板
先承接完整真实改变，再把镜头靠近所选尺度：玩家已平息大战而选择个人，就在大战提前结束的大前提下观察个人，不能把战争重写回去
城市、聚落、国家也可观察新生、消失、迁移、合并或替代，不限于旧实体内部变化
effect.scope 按本篇实际主要观察尺度填写，不因背景提及大战就自动升级为大陆；不为凑范围改写事实，不把大陆强压成跨国


改写深度决定历史进程或结果有多不同，离奇程度决定偏离直接预期的大胆程度，情绪决定读感；范围、深度、离奇和持续时间互相独立
时代回响不专指长期风俗，一场短促事件也可以改变世界；个人也可能有传奇人生，跨国也可能呈现朴素生活
细微涟漪不能抹掉玩家实际完成的重大成果，可在其大前提下观察细节
关注对象是想靠近的问题，不是全篇唯一演员、参与者名单或预写结局


旧请求骰点和范围只作兼容回显，不重新抽取，不用骰子锁定规模或选择剧情
effect.roll 复制输入 dice.roll
偏好不改输出协议，不展示配置与内部推理；没有期望结局


## 四、详细创作方法的唯一来源

使用 BUTTERFLY_CREATIVE_METHOD 中的结构化指导，让转折承接前事、改变局面并形成后事的条件；作品中的有效转折与具体展开沿 BUTTERFLY_MANDATORY_PROTOCOL，不在本规则中叠加第二套范文、数量配额或固定传播模板

示例只学习连接方式，不充当本轮事实、已知角色、默认路线或期望结局；先创作历史，再把同一个故事整理进既有索引，previousButterflyAnchors 的有效状态与完整原文继续承接

## 五、正文与展示契约

historicalEvolution 是主体，通常300至600字，复杂故事可以更长；字数是参考，不因超长拒收或裁剪全文，不凑字，不增加校验上限

表达使用 BUTTERFLY_HISTORICAL_EVOLUTION_STYLE 中的清楚、自然的现代中文，写明谁做了什么、为什么这样做、后来怎样；具体详略与句式不再叠加固定模板

presentLanding 是可接触的现世场景，不是传送目的地，可以在归返之后另行遇见，三锚不变；perceptibleEvidence 通常1至2项，既有兼容协议不变，详细取舍沿 BUTTERFLY_PERCEPTION，不要求一件纸质证物或立即验证的公告

ruinActionRecord 只总结实际关键干涉，目标80至180字，现有兼容校验接受20至400字；历史演变保留现有最低完整性检查，不添加上限拒收

effect.title 可用4至10字概括这一篇最有意味的改变，用于《蝴蝶效应日志：短标题》，不用序号、配置项或空泛“历史改变”；标题只是可选展示信息，缺失或格式不合适由脚本兜底，不重新生成正文

## 六、既有输出契约

只返回一个 JSON 对象
下例描述字段，不是剧情模板；数值和标识从本次输入复制
不要输出额外顶层键、Markdown、面板、变量更新或解释


```json
{
  "schema": "eyon.butterfly.v1",
  "requestId": "与输入一致",
  "runId": "与输入一致",
  "effect": {
    "title": "本篇短标题（可省略）",
    "roll": 1,
    "scope": "个人|双人|小队|聚落|城市|省份级地区|国家|跨国|大陆",
    "ruinActionRecord": "实际关键干涉",
    "historicalEvolution": "完整演变史稿",
    "presentLanding": "可接触的现世场景",
    "perceptibleEvidence": ["具体线索"],
    "historicalKeywords": ["已出现在最终内容中的专名"]
  },
  "causalStages": [
    {
      "order": 1,
      "time": "有根据的时期或日期",
      "carrier": "承接变化的人、事件或条件",
      "change": "该阶段怎样改变",
      "linkToNext": "如何形成下一段条件；末阶段说明现世结果",
      "sourceIds": []
    }
  ],
  "directEffects": [
    {
      "subject": "实际对象的真实名称",
      "time": "直接变化的历史时间",
      "stateHint": "自然语言状态提示",
      "change": "完整一句直接变化"
    }
  ],
  "sourceIds": [],
  "inferences": [{"content": "因果连接中的推断", "basisSourceIds": ["已给出的来源句柄"]}],
  "warnings": [],
  "qualityChecks": {
    "anchorsUntouched": true,
    "scopeRespected": true,
    "causalChainComplete": true,
    "presentEvidenceConcrete": true,
    "playerAgencyPreserved": true,
    "canonConflictsResolved": true
  }
}
```

- causalStages 是写成故事后的历史转折索引，创作数量与有效性沿 BUTTERFLY_MANDATORY_PROTOCOL，既有2至5项兼容字段不代替本轮创作要求；order 从1连续递增，每项有自己的作用，时间、承接变化的人、事件或条件与正文吻合，不先填字段再强造传播流水线
来源句柄只能复制 TASK_CITATION_CONTRACT_V2 列出的 S 句柄，不能编造世界书 ID

- sourceIds 写确认起点与世界条件的实际依据；inferences 记录据此推演的连接，其 basisSourceIds 只能用真实依据
原创未来不要求已被史料逐事预言，不冒称史料明示，不打印思考过程

- historicalKeywords 为4至10项，是最终内容已经出现、可区分本条目的专名及字面别名
人物、家族、地名、事件、组织、器物均可；不填“历史/命运/影响”等泛词，不写描述句或成果总结

- directEffects 是已有可选的直接变化索引，只记已确认的实际行动直接改变了什么，不是全文拆句
未来传承和社会成果记入causalStages与historicalEvolution，不倒填为玩家当时完成的行动；没有明确物品状态改变时不虚构一项
subject/time/stateHint/change 保持自然语言，不生成内部编号

- 同对象、同时间、同维度合并重复项；不同日期的明确状态转变分别保留
持续状态可沿用已有可选 continuousState，不知道日期就不猜，不新添必填字段

- 历史赎出索引记本人真实名、历史离去点及“历史赎出”，说明已抵达现世且原后续人生不自动延续，不仅记迁居或死亡

- qualityChecks 是事实和契约一致性的回执，不是文风分数；scopeRespected 表示未为了凑范围篡改事实，不表示控制台偏好逐项达标
playerAgencyPreserved须核对行动记录和直接变化与完整原文是否一致，而不只是复制了来源编号；起点矛盾时先改正起点与故事，不靠全部写true掩盖问题


最后按BUTTERFLY_REVISION审阅并修正成稿，同时核对请求标识、锚点、实际行动、有效历史、起点年龄身份、关键连接、来源句柄与结果字段，仅交付修正后的既有JSON
来源用于确认起点与世界条件，不要求每个原创未来事件都已存在于世界书；创作空白不等于资料失败，少见也不等于矛盾
事实边界内选择有生命力、符合本轮参考的故事，不输出工程自检、存档步骤或失败恢复指令
