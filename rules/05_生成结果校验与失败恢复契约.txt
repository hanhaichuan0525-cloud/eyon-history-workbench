# 一、目标

本契约规定宗族谱系、墟境生成、寻根溯源和蝴蝶效应结算的请求状态、输出校验、修复、重试、取消与过期处理。

原则:

- 不信任模型自报的 `qualityChecks`。
- 不把可解析等同于正确。
- 不把失败结果写入聊天、MVU、世界书或成品库。
- 不静默切换API路由、模型或任务类型。

# 二、请求状态机

每个请求只能按以下方向变化:

```text
idle
  -> assembling
  -> requesting
  -> parsing
  -> validating
  -> ready
  -> committing
  -> completed
```

异常分支:

```text
assembling|requesting|parsing|validating
  -> repairing
  -> parsing

任意未完成状态
  -> cancelled|stale|failed

butterfly失败且冻结快照仍完整
  -> pending_settlement
```

终态:

- `completed`
- `cancelled`
- `stale`
- `failed`
- `pending_settlement`

`completed|cancelled|stale|failed`不得再次提交成品。

`pending_settlement`只允许由玩家明确重试，并必须复用原冻结快照、骰点、`runId`和路由。

# 三、请求身份

每次请求必须携带:

- `requestId`
- `taskType`
- `characterKey`
- `chatId`
- `triggerMessageId`
- `sourceHash`
- `ruleBundleVersion`
- `route`
- `model`
- `startedAt`
- `runId`: 仅 `butterfly` 必填
- `frozenSnapshotHash`: 仅 `butterfly` 必填

收到响应后必须逐项核对:

- 响应 `requestId` 与当前请求一致。
- 响应Schema与 `taskType` 一致。
- 当前角色卡和聊天未变化。
- 触发楼层仍存在且仍属于原请求。
- `sourceHash` 没有因表单或资料变化失效。

任一不符时标记 `stale`，不得写入当前界面或资料库。

# 四、传输校验

将以下情况归类为传输错误:

- 网络不可达。
- 超时。
- HTTP 429。
- HTTP 5xx。
- 响应体为空。
- 用户取消请求。

自动重试:

- 只允许对网络中断、429或5xx自动重试1次。
- 使用同一路由、同一模型、同一请求内容。
- 重试使用递增等待，不立即连续轰炸端口。
- 用户取消、鉴权失败、模型不存在和4xx参数错误不得自动重试。
- 不得从酒馆插头自动切换到独立API，或反向切换。

# 五、JSON解析

正常输出必须是单个JSON对象。

解析顺序:

1. 直接 `JSON.parse` 原始响应。
2. 若响应仅被一个Markdown代码围栏包裹，移除外围后再解析一次。
3. 禁止使用正则从长篇自然语言中猜取零散JSON片段。
4. 禁止使用 `eval`、`Function` 或宽松JavaScript解析器。

解析失败后进入一次修复流程。修复仍失败则终止。

# 六、基础Schema

脚本必须使用Zod或等价的严格Schema校验。

## 6.1 宗族谱系

必须满足:

- `schema === "eyon.genealogy.v2"`。
- `requestId`一致。
- 中心人物对应输入MVU人物。
- 节点ID和边ID唯一。
- 每条边引用的节点存在。
- 生卒日期纪元合法。
- 不得形成无法解释的父母循环。
- `canInjectToRuin` 只允许对应MVU人物。
- 推断和自动补全节点必须保留来源标记。

## 6.2 墟境候选

必须满足:

- `schema === "eyon.ruin.candidates.v2"`。
- `requestId`一致。
- 候选数量等于骰表 `candidateCount`。
- 每个候选拥有4至8个时间单调不减的节点。
- 至少一个可进入 `anomaly`。
- 非 `anomaly` 节点不得可进入。
- 每个可进入特异点至少两个合理分支。
- `historyProse`、`fusion`和节点描述同一段历史。
- 每组骰表素材只用于对应候选。
- `selectedCharacters`逐项出现在 `selectedCharacterUsage`。
- 参与模式为 `actor` 的人物出现在 `cast`和至少一个节点。
- 纪元、地点和玩家补充方向符合输入。
- 选定候选生成的 `ruinTraceRaw` 同时包含唯一 `[RuinTrace]` 与 `[/RuinTrace]`。
- `ruinTraceRaw` 字段严格按 `Title::`、`Type::`、`Span::`、`History::`、`Shift::`、`NodeTime::` 顺序各出现一次。
- `ruinTraceRaw` 能被现有墟境美化正则完整匹配，且捕获值与选定候选及特异点的结构化字段一致。
- 格式校验失败时只允许从已校验JSON重新序列化，不得重新调用生成API，也不得让正文模型修补格式。

## 6.3 寻根溯源

必须满足:

- `schema === "eyon.biography.v1"`。
- `requestId`一致。
- 对象与玩家原始指令一致。
- 明确时间范围未被越界。
- 时期数量和类型符合 `stagePlan`。
- 相邻时期拥有完整过渡字段。
- `rootTrace`同时包含唯一 `[RootTrace]`与`[/RootTrace]`。
- 所有 `<details>` 正确闭合且默认不带 `open`。
- `rootTrace`与结构化时期内容一致。
- 禁止历史结晶商店、`<item_info>`、变量更新和伊雍对白。

## 6.4 蝴蝶效应

必须满足:

- `schema === "eyon.butterfly.v1"`。
- `requestId`一致。
- `runId`与冻结快照一致。
- `effect.roll`与脚本骰点一致。
- `effect.scope`与脚本骰点映射一致。
- `presentLanding`非空且指向遣返后现实能够接触的具体落点。
- `perceptibleEvidence`包含1至4项非空具体证据。
- `ruinActionRecord`非空，且只总结输入中存在的玩家行动。
- `historicalEvolution`长度与结构符合生成规则。
- `historicalKeywords`包含4至10项非空去重关键词。
- `causalStages`包含2至5项，`order`连续且唯一。
- 每个因果阶段拥有承载者、变化和通往下一阶段的连接。
- 所有来源ID能够在本请求 `sourceIndex` 中找到。
- 不得输出三套锚点替代值、JSON Patch、变量路径、面板标签、HTML或Markdown表格。

# 七、语义校验

Schema通过后仍需执行确定性语义检查。

## 7.1 通用

- 不得出现输入之外的纪元名称。
- 年月日顺序和范围合法。
- 来源ID必须能在 `sourceIndex` 或本地资料库中找到。
- `inference:false` 的内容不得只依赖推断来源。
- 不得出现API密钥、提示词原文、内部自省或JSON Patch。
- 输出不得擅自修改当前世界时间、地点或墟境状态。

## 7.2 玩家意图

- 墟境 `supplementaryDirection` 非空时，候选必须有具体落实字段。
- 墟境选中人物不得只是名单装饰。
- 寻根溯源的对象、硬时间范围和主要方向必须出现在结构化结果中。
- 族谱代数不得超出玩家请求。

## 7.3 时间与人物

- 已知出生之前或死亡之后，普通人物不得被写成亲自在场。
- 长生、复活、时间移动等例外必须有高优先级资料依据。
- 同一人物别名不得被重复创建为多个节点或角色。
- 同名不同人不得自动合并。

## 7.4 蝴蝶效应

- 现实、进入、离开三套时地始终使用冻结快照，API结果无权覆盖。
- 玩家行动记录必须能追溯到本轮正文或冻结行动摘要。
- 因果链必须包含“玩家行动 -> 传播媒介 -> 中间演化 -> 现世落点 -> 可感知证据”。
- 波及范围不得高于或低于骰点映射；大事件允许收束，小行动允许放大，但必须解释传播机制。
- 现世落点不得只是墟境内部结果的复述。
- 至少一项证据必须能在玩家遣返后的当前现实直接观察、接触或验证。
- 不得覆盖既成世界书事实、旧传记、族谱或已归档蝴蝶效应。
- 不得把上一轮次的人物、地点、行动或锚点拼入本轮。
- 若同一 `chatId + runId` 已存在完成日志，本结果判定为重复提交。

# 八、模型自检字段

`qualityChecks` 仅作辅助提示。

脚本必须自行重新计算可以确定的项目。若模型填 `true` 但实际不满足，以脚本校验结果为准。

无法由脚本确定的文学质量不做真假布尔判断，只显示为人工可读警告，例如:

- 候选可能过度相似。
- 史稿可能依赖陈词滥调。
- 人物动机可能过薄。

文学警告不自动修改模型文本。

# 九、修复请求

每个请求最多允许1次格式或结构修复。

修复请求必须:

- 使用原路由和原模型。
- 使用新的 `repairRequestId`，并保留原 `requestId`。
- 不携带聊天历史。
- 只提供原任务Schema、具体校验错误和原始响应。
- 明确要求返回完整替代JSON，而不是补丁。
- 禁止模型重新掷骰、更换玩家方向或新增请求资料。

修复请求不得:

- 切换任务类型。
- 使用另一模块规则。
- 修改MVU。
- 向正文发送任何内容。
- 把两次结果拼接成一个对象。

修复成功后必须从头执行解析和全部校验。

# 十、不可自动修复

以下情况直接失败:

- 玩家地点为空。
- 寻根溯源对象为空或无法确认。
- 世界书硬设定与玩家要求无法协调。
- 请求已过期或聊天已切换。
- 触发楼层被删除。
- 族谱中心人物已从MVU中消失。
- API鉴权失败。
- 返回内容包含明显提示词泄露或密钥。
- 第二次校验仍失败。

# 十一、提交

只有状态为 `ready` 时允许提交。

## 11.1 宗族谱系

提交到本地族谱仓库并更新当前族谱视图。

## 11.2 墟境候选

提交到当前聊天候选仓库并更新因果节点视图。

不得生成正文、进入节点或修改MVU。

## 11.3 寻根溯源

先把已校验 `rootTrace` 保存在请求内存中，再启动正文开场生成。

正文占位替换成功后，才把传记标记为 `completed` 并写入传记书库。

## 11.4 蝴蝶效应

提交顺序固定为:

1. 再次核对当前 `characterKey + chatId + runId`。
2. 核对同轮次尚无完成日志。
3. 使用冻结快照和已校验JSON渲染固定 `<butterfly_panel>`。
4. 将面板追加或替换到绑定的遣返AI楼层；不得改写该楼已有正文。
5. 将结构化原稿写入当前聊天IndexedDB。
6. 使用同一归档器写入当前聊天的世界书镜像。
7. 发出“蝴蝶效应归档队列完成”事件，刷新只读面板。

若正文楼层追加失败:

- 不得先写世界书造成正文与归档不一致。
- 保留为 `pending_settlement`。
- 不重新调用API生成另一份内容。

若IndexedDB或世界书提交失败:

- 已有冻结快照和已校验结果必须保留。
- 重试只执行未完成的提交步骤。
- 不得重复追加面板或创建第二条世界书日志。

# 十二、取消

- 每个活动请求拥有独立 `AbortController`。
- 玩家取消时立即标记 `cancelled`。
- 取消后的迟到响应必须丢弃。
- 取消API后不自动取消玩家正在进行的普通正文生成。
- 切换角色卡、聊天或关闭脚本时取消全部未完成请求。
- 取消不删除此前已经完成的成品。
- `butterfly`已形成冻结快照但尚未完成时，取消API请求后保留为当前聊天的 `pending_settlement`，不得丢弃锚点。

# 十三、失败显示

界面只显示:

- 简短错误标题。
- 可理解的错误原因。
- 当前路由与模型。
- 是否可以重试。
- “查看技术详情”中的错误码和失败字段路径。

界面不得显示:

- API密钥。
- 完整提示词。
- 完整世界书上下文。
- 模型内部思考。
- 未清洗的服务器响应头。

# 十四、错误码

统一错误码:

- `LOCATION_REQUIRED`
- `TARGET_REQUIRED`
- `TARGET_NOT_FOUND`
- `INVALID_REQUEST`
- `AUTH_FAILED`
- `MODEL_UNAVAILABLE`
- `RATE_LIMITED`
- `NETWORK_FAILED`
- `REQUEST_TIMEOUT`
- `REQUEST_CANCELLED`
- `REQUEST_STALE`
- `INVALID_JSON`
- `SCHEMA_MISMATCH`
- `SEMANTIC_INVALID`
- `REPAIR_FAILED`
- `STORAGE_FAILED`
- `MESSAGE_HANDOFF_FAILED`
- `ANCHOR_SNAPSHOT_REQUIRED`
- `INVALID_SETTLEMENT_SOURCE`
- `SETTLEMENT_ALREADY_EXISTS`
- `SETTLEMENT_PENDING`
- `WORLDINFO_MIRROR_FAILED`

# 十五、禁止兜底

- 禁止失败后使用旧候选冒充新结果。
- 禁止使用另一个聊天的缓存。
- 禁止把模型自然语言错误页当作史稿。
- 禁止因传记注入失败而再生成第二份传记。
- 禁止因墟境候选失败而发送空的“墟境探索”正文命令。
- 禁止因族谱失败而创建空白虚构家族。
- 禁止任何失败流程改变真实墟境状态。
- 禁止蝴蝶效应失败后让正文模型临时补写面板。
- 禁止使用遣返后已清空的MVU重建冻结锚点。
- 禁止同一轮次重复追加正文面板或世界书条目。
- 禁止蝴蝶效应API失败导致遣返回滚。
