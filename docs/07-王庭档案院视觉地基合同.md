# 王庭档案院视觉地基合同

> 状态：**PROPOSED / VISUAL FOUNDATION / DRIVER REVIEW PENDING**
> 日期：2026-09-28
> 原型：[`prototype/royal-archive-foundation.html`](../prototype/royal-archive-foundation.html)
> 关系：本合同管理工作台整体视觉地基；伊雍像素伴生体的行为、动作与任务气泡仍由 [`06-工作台视觉系统与伊雍伴生交互蓝图.md`](./06-工作台视觉系统与伊雍伴生交互蓝图.md) 管理。

## 1. 设计命题

工作台不是一组互相争艳的功能面板，而是伊雍独自守护的“虚嗣王庭档案院”：冷静、知性、带有历史与宫廷秩序，同时仍能让人感到一位见证者正在其中书写。

第一优先级永远是信息清楚、操作可辨、正文可读。哥特、王庭、圣经与蛇发元素只承担秩序和记忆点，不能遮盖信息层级。去掉所有装饰后，布局与按钮仍须完整可用。

## 2. 本轮目标、红线与验收

### 目标

1. 建立可复用的颜色、字体、间距、线条、状态与表面令牌。
2. 建立所有现有和未来模块都能继承的公共外壳与模块插槽。
3. 以“传记书库”完成一份高保真原型，验证阅读密度、视觉气质和扩展方式。

### 红线

- 不修改业务、数据、Canon、检索、模型调用、持久化与任务状态。
- 本轮不迁移正式 `src/ui`，不替换已运行的工作台。
- 不新增 UI/动画依赖，不加载远程资源，不引入大图、动图或字体包。
- 不为每个模块另造一套颜色；不以低对比、玻璃雾化和过量装饰伪装“高级”。
- 原型通过不等于真实酒馆通过，也不等于允许打包、安装或发布。

### 驾驶员验收

1. 灰阶观看时，导航、标题、正文、状态与主操作仍有明确先后。
2. 深色外壳、纸张阅读面与强调色属于同一亲缘色系，不出现突兀跳色。
3. 传记内容长时间阅读不疲劳；正文区不被装饰、状态和操作打断。
4. 桌面和窄屏都能明确知道“在哪里、正在看什么、下一步能做什么”。
5. 新模块只需填写统一插槽和少量模块标识，不需重写外壳。

## 3. 视觉语法

### 3.1 气质

- **王庭**：轴线、细金属线、克制的仪式感。
- **档案**：纸面、书脊、签条、来源和版本信息。
- **见证**：清楚呈现“来源—状态—正文—批注”，不让权威感掩盖不确定性。
- **伊雍**：生命感集中在像素伴生体与少量批注中，普通控件保持安静。

### 3.2 色彩比例

- 约 85%：墨黑、夜紫黑、石灰紫、纸白等中性色。
- 约 10%：王室紫及其灰化亲缘色，用于焦点、选中和主操作。
- 约 5%：旧金、蜡酒红等仪式/语义色，只用于少量边线、印记、警示。

模块不得各占一种高饱和颜色。模块身份优先由图形、题签、线纹和内容材料区分。

### 3.3 表面

| 表面 | 用途 | 原则 |
|---|---|---|
| 王庭夜色 | 工作台外壳、导航、工具区 | 深而不死黑，靠边线与明度分层 |
| 圣经纸面 | 正文、档案、长阅读 | 暖灰白、深墨字、较高行距 |
| 石灰紫面 | 次级信息、筛选、检查器 | 低饱和，不与正文争夺注意 |
| 临时浮层 | 菜单、提示、对话框 | 只在任务需要时出现，层级清楚 |

深浅主题是同一房间的昼夜，不允许成为两套无关的品牌。

## 5. 字体与阅读

- 界面文字：系统黑体序列，优先 `Noto Sans SC / Microsoft YaHei`。
- 档案标题与正文：系统宋体序列，优先 `Noto Serif SC / Songti SC / STSong`。
- 伊雍发言与签名提示：系统楷体序列，优先 `Kaiti SC / STKaiti / KaiTi`，宋体回退；只用于短句，不接管长正文和普通控件。
- 拉丁大写只用于小型眉题，不承担关键中文信息。
- 正文建议 15—17px，行高 1.75—1.9；单行目标 34—46 个中文字符。
- 正文标题、纪元、跨度必须明确显示，不以装饰性缩写代替。

## 6. 公共外壳合同

每个模块进入同一固定骨架：

1. **全局导航**：桌面为带文字左栏，窄屏为带文字底栏；不得只靠图标辨认。
2. **模块头**：模块眉题、标题、上下文、状态、一个主操作；次操作不得与主操作同权。
3. **模块工作区**：主内容是视觉中心；筛选/书架在侧，检查器按需出现。
4. **状态槽**：加载、空状态、错误与只读均使用同一位置和语法，不能靠弹窗四处漂移。
5. **伴生体槽**：伊雍由宿主级系统管理，模块只上报语义状态，不自行复制图片与动画。

模块接入只需提供：

```ts
type WorkbenchModulePresentation = {
  id: string;
  eyebrow: string;
  title: string;
  contextLabel: string;
  statusLabel?: string;
  primaryAction?: { label: string; command: string };
  glyph: string;
  lineMotif?: string;
  emptyStateVignette?: string;
};
```

`glyph` 和 `lineMotif` 应来自共享小型矢量图集；`emptyStateVignette` 可选，不得成为模块可用性的前提。

## 7. 组件纪律

- 卡片只用于可独立选择或展开的对象；禁止“卡片里再套卡片”。
- 圆角采用三级语义：控件约 9px、普通卡片约 15px、主阅读面与大型容器约 21px；分隔线和正文列表仍保持平直，避免所有内容都成为药丸。
- 主按钮每一视区原则上只出现一个；危险操作使用明确文字与酒红语义。
- 图标必须伴随可见标签或可访问名称。
- 边线承担大部分结构，阴影只做轻微离层。
- 装饰优先承担信息或结构职责：例如卷宗摘要、纪元刻度、书脊编号与见证标记；纯氛围纹样必须更淡、更少。
- hover、focus、selected、disabled、loading 必须可区分；键盘焦点不能被去掉。
- 代表模块的高保真原型必须保留正式模块的操作与状态合同：不得凭空增加主操作，也不得为了画面简洁而删掉检索、封面/展开、管理菜单、加载、空状态或错误状态。原型数据可以是演示数据，但任何写入与删除都必须明确标注为未接入真实宿主。

## 8. 装饰与资源预算

装饰分两类：

- **结构符号**：内联 SVG 或 CSS 线条，如尖拱、书脊、蛇形分隔线、印章轮廓。
- **生命点缀**：复用伊雍像素图集的小裁切，或单个小型像素场景。

禁止大背景图、GIF、Lottie/Rive、动画库和大型自定义字体。资源缺失时，界面必须自动回落到纯 CSS/SVG 并保持完整。

| 资源 | 软上限 | 硬上限 |
|---|---:|---:|
| 伊雍动作图集 | 200 KB | 300 KB |
| 公共平面装饰图集 | 64 KB | 96 KB |
| 单模块独有资源 | 16 KB | 32 KB |
| 本轮新增装饰合计 | 160 KB | 220 KB |
| 工作台图片资源总计 | 360 KB | 480 KB |

每个模块默认只获准：一个图标、一道线纹、一个可选空状态小景。超额必须单独说明收益和降级方案。

## 9. 响应式与可访问性

- 目标宽度：宽屏三栏；中屏隐藏/下移检查器；窄屏单栏并使用文字底栏。
- 不允许产生横向滚动；触控目标建议不小于 44×44px。
- 内容与交互不能只依赖颜色区分。
- 所有动画支持 `prefers-reduced-motion`；普通界面只保留 120—180ms 的轻过渡。
- 伊雍可以有角色动作，普通按钮、列表和阅读页不得持续漂浮、闪烁或扫描。

## 10. 实施顺序与证据门

1. **本轮**：合同 + 公共外壳 + 历史长河、宗族谱系、墟境探查、传记书库与工作台设置五个高保真独立原型。
2. **驾驶员视觉门**：确认信息层级、配色、阅读与扩展感。
3. **正式迁移门**：只在视觉门通过后，提取正式 tokens/shell，迁移一个真实模块并跑现有测试。
4. **模块扩展门**：逐个迁移其余模块；每个模块只允许增加必要图形资产。
5. **真实酒馆门**：宽屏、窄屏、拖动伴生体、长正文、弹窗和宿主主题组合复验。
6. **打包门**：只有明确授权后才构建与打包；视觉原型本身不得作为发布件。

## 11. 本轮未解决

- 正式工作台 token 与旧 `appearance.ts` 的迁移策略。
- 所有模块的最终空状态插画与线纹。
- 真实酒馆内深浅主题、字体回退与低端设备性能。
- 正式版本号、包、安装与发布。

这些项目不得在原型未通过前顺带实施。

## 12. 五模块原型合同

本轮独立原型按正式模块现有接口逐一重构，不能以通用占位页替代：

| 模块 | 必须保留的真实入口 | 视觉主次 |
|---|---|---|
| 历史长河 | 读取当前变量、现实/墟境双锚点、遣返、蝴蝶档案切换、失败重试、删除边界 | 双锚点在前，运行状态居中，蝴蝶档案采用列表—证据详情主从布局 |
| 宗族谱系 | MVU 人物选择、祖辈/后代/每代人数、重新构建、人物选择、缩放/居中/刷新、右键墟境参考 | 控制与人物档案在侧，树图占据最大面积；夫妻同辈不画连线，代际留出明显纵向间距 |
| 墟境探查 | 纪元、可选日期、必填地点、重点人物/传记、补充方向、候选数、生成/新任务、候选切换、四节点进入 | 左侧约束输入，右侧从候选史稿顺序进入因果节点与节点投影；缘起、经过、高潮、结果同权可进入 |
| 传记书库 | 检索、选书、封面、展开正文、章节、现世续章、总结、右键参考/删除、加载/空/错误 | 书架服务于选择，典籍封面与全文阅读为视觉中心 |
| 工作台设置 | API 调用、外观皮肤、资料检索、数据管理及各自内部操作 | 设置分类固定，行级说明先于控件；危险操作只在数据管理中使用酒红语义 |

原型交互只改变页面内演示状态；任何会调用模型、写入 MVU/Canon、保存密钥、导出或删除资料的动作，都必须停在明确的“原型边界”说明中。

## 13. 本轮细化冻结项

- 蝴蝶效应档案详情采用“因果卷宗”结构：概况徽记、`现实锚点 → 墟境进入 → 墟境离开 → 改写后现世` 的穿越路径、行动/证据双栏、历史演变结论。路径按游玩经历排序，不伪装成年代时间线。
- 失败档案仍显示已冻结的前三个节点；通往“改写后现世”的连线改为断续状态，证据与结论显示待重新归档，不用技术日志占据正文。
- 宗族谱系移除等距方格底纹，改用低对比云海、光晕和少量非周期星点；谱系节点与亲缘连线仍是信息主体。
- 宗族谱系采用关系感知的自适应树图：共同父母的子女与共同育有子女的双亲优先聚成家庭簇，不同父系/直系/母系支系自动增大横向间距；人数增加时扩大内部画布并保留横向滚动，不缩窄人物卡片。
- 亲缘线只由明确的亲子/收养边生成，按家庭分组并在重叠时分配独立轨道；同辈夫妻卡片之间不画直连线，无关家庭不得共享一条横贯整代的母线。每次谱系数据变化、缩放或重建都由同一确定性布局重新计算。
- 伊雍专属字形不嵌字体包，不增加图片资源；本轮依赖系统楷体字栈并保留宋体回退。

## 15. 单一视觉源与出包闭环（internal.130）

- `prototype/royal-archive-foundation.html` 的日常入口不再维护另一套可漂移的静态界面，而是转到 `prototype/workbench-runtime.html`，直接加载正式 `dist/workbench.js`；旧稿仅以 `?static-reference` 作为设计档案保留。
- 正式公共外壳补齐侧栏纹章、SVG 模块图标、模块摘要账册与传记藏书架；五个模块收到同一外观状态，内部根节点与外部壳层不再各自停留在不同明暗主题。
- 内测包固定执行“生产构建 → 六份 manifest 哈希同步 → 正式界面标记校验 → 嵌入同一份 workbench.js”。缺少版本号、`rail-ornament`、`data-ledger` 或 `ARCHIVE SHELF` 任一标记都拒绝出包，防止上一次构建的旧界面进入整合包。
- internal.129 的传记同年跨月年份修复随包保留；本轮没有修改历史业务 schema、Canon、检索、提示词、存储或模型调用。
- 自动化 699/699、类型检查、三份正则、六份 bundle 语法、manifest 哈希、包内版本/视觉标记与生产入口浏览器目检通过；真实 SillyTavern 宽屏、窄屏和宿主主题组合仍待驾驶员安装验收。
