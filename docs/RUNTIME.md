# 运行时与楼层事务

## 原则

历史工作台不自行创建助手楼，不代写伊雍对白，也不解析或覆盖 MVU。

独立 API 只生成结构化史料。伊雍对白、`mood`、`<eyon_court/>` 与正文流式输出仍由当前角色卡世界书、酒馆预设和正文模型自然生成。

## 两阶段提交

### 生成前准备

`manifest.generate_interceptor` 指向 `eyon_history_generateInterceptor`。酒馆在正常生成、重 Roll 或 swipe 前等待该函数完成。

拦截器只读取当前聊天中最新的可见玩家楼。若该楼是严格的寻根溯源命令：

1. 记录角色卡标识、聊天 ID、玩家楼号、文本指纹与 swipe。
2. 装配世界书、MVU 人物、最近正文、族谱、既有传记和蝴蝶效应资料。
3. 调用独立 API，并校验唯一 JSON 与来源引用。
4. 将已校验传记保存为 `validated`。
5. 通过独立的 `setExtensionPrompt` 槽注入本轮正文协作指令。
6. 返回控制权，让酒馆正常生成并流式显示伊雍正文。

脚本不会在此阶段调用 `createChatMessages`。

若该楼是严格的“墟境探索”命令，统一生命周期会从界面状态读取一份完整 `RuinGenerationInput`，然后：

1. 锁定角色卡标识、聊天 ID、玩家楼号、文本指纹、swipe 与生命周期代际。
2. 只读装配世界书、最近正文、MVU人物摘要、族谱、传记和蝴蝶效应摘要。
3. 调用独立 API，并严格核对候选数量、骰表素材映射、来源 ID、时间单调性和可进入特异点。
4. 按 `角色卡标识 + 聊天 ID` 保存候选结果。
5. 不创建助手楼，不修改 `/世界`、`/墟境系统` 或任何 MVU 字段，也不把“生成候选”视作“进入节点”。

玩家在界面选中可进入特异点后，`RuinEntryWorkflow` 会重新读取点击时现实锚点，并核对当前聊天、候选记录、节点可进入性和 `idle` 状态。全部成立时，`buildRuinEntryText` 才把以下内容合并为一条完整的待发送指令：

- 明确的“进入节点”指令。
- 点击时现实时间和地点。
- 目标墟境时地、因果机制、参与人物、物质条件和介入分支。
- 玩家补充方向与稳定资料标识。
- 保持现有美化字段顺序的唯一 `RuinTrace`。

工作台只把这条完整指令写入酒馆输入框，不触发发送、不创建玩家楼或空白消息。玩家确认并发送后，正文模型在紧邻助手楼中承接上一楼剧情，自然描写穿越，并依据现有世界书和MVU规则完成 `exploring`、现实锚点、世界时地及墟境时地更新。工作台不会提前写状态，也不会创建候选确认楼。

输入框适配器只能设置当前酒馆输入框的值并触发响应式 `input` 事件；严禁触发 `change`、Enter、发送按钮或任何提交事件。完整指令必须由玩家亲自发送。

### 正文楼提交

收到 `CHARACTER_MESSAGE_RENDERED` 后，脚本重新核验：

- 角色卡标识和聊天 ID 没有变化。
- 玩家楼仍是同一楼，正文指纹和 swipe 没有变化。
- 新助手楼紧邻该玩家楼，并且仍是当前最新楼。
- 请求 ID、来源哈希与待提交记录一致。

全部成立时，传记事务只替换唯一 RootTrace 插槽，并把事务标记写入 `message.extra`。`message.data` 留给 MVU 和其他楼层变量框架。

任一条件不成立时拒绝提交，不向别的楼层补写。

### 遣返正文与蝴蝶效应提交

玩家明确遣返时，蝴蝶效应采用“正文先行、后台结算”的独立事务：

1. 在玩家遣返楼生成前冻结当前活动 `runId` 的现实锚点、墟境进入锚点和墟境离开锚点。
2. 以请求专属的 `setExtensionPrompt` 槽注入隐藏协作指令，只要求正文模型正常完成遣返叙事与变量更新，不生成、不猜测、不等待 `<butterfly_panel>`。
3. 正文模型照常流式生成紧邻助手楼；时间内核独立完成现实恢复和流程清理。
4. 助手楼渲染后，脚本先清除隐藏提示槽，再严格核验角色卡、聊天、遣返玩家楼、玩家 swipe 和紧邻助手楼。
5. 后台 API 使用冻结快照生成蝴蝶效应。目标楼没有面板时追加；恰有一个旧面板时只原位替换该面板；出现多个旧面板时拒绝写入，避免破坏正文。
6. 完成结果镜像到当前聊天专用全局世界书。API、楼层或世界书写入失败都不能回滚已经完成的遣返，只保留待结算记录供原样重试。

脚本不会改写目标楼中的遣返叙事、`<UpdateVariable>`、MVU 变量块或其他美化标签，也不会另建助手楼。

## 生命周期清理

`CHAT_CHANGED`、脚本卸载、准备失败和提交结束都会清空本次传记及蝴蝶效应扩展提示槽与内存中的待提交事务。传记正文、候选墟境和蝴蝶效应都按 `角色卡标识 + 聊天 ID` 隔离，换存档后不会沿用上一存档的资料。

候选墟境还使用 `RuinTransactionGuard` 记录生命周期代际。宿主组装时必须把同一个 guard 实例同时传给 `RuinController` 与 `createRuinIdentityAssertion`：

```ts
const guard = new RuinTransactionGuard();
const assertCurrent = createRuinIdentityAssertion(runtime, guard);
const workflow = new RuinWorkflow({ ...dependencies, assertCurrent });
const controller = new RuinController(workflow, runtime, hooks, guard);
```

这样即使请求期间切走聊天后又迅速切回，旧响应也不能落库。重复点击同一楼层、同一 swipe、同一输入时只复用一笔在途请求；新代际不会被旧请求的清理回调误删。

## 生成类型

寻根溯源和墟境探索只处理：

- 正常生成
- 重新生成
- swipe

续写、quiet 和 impersonate 不触发后台传记生成，以免把同一命令误当成新请求。

## 当前接入边界

本模块已经提供统一命令路由、上下文装配、传记两阶段工作流、候选墟境单阶段事务、楼层锁、事件注册器与正式酒馆适配。`dist/index.js` 负责宿主运行时，`dist/timeline.js`、`dist/genealogy.js`、`dist/ruin.js` 与 `dist/biography.js` 通过公开门面读取当前聊天数据。

墟境时空页只调用 `getRuinRuntimeSnapshot()` 读取现有时间内核快照，并按当前命名空间读取蝴蝶效应档案。遣返按钮只发送严格的“遣返”玩家楼；页面自身不能改写世界时地、墟境状态、轮次或锚点。

传记书库只读取当前角色卡与当前聊天命名空间中 `committed` 状态的传记。切换聊天后书架会随门面数据源切换，不读取其他存档，也不向 MVU、正文或世界书回写界面状态。

正式墟境生成页负责：

- 将纪元、可选年月日起止、必填地点、谱系人物引用与补充方向保存为当前聊天草稿。
- 从嵌入构建的规则骰表生成3/4/5组历史材料，再调用墟境独立API。
- 将候选、史稿和4至8个因果节点存入当前角色卡与聊天命名空间。
- 只允许通过严格校验的特异点创建唯一进入玩家楼。

这些适配不读写记忆插件私有数据库，也不修改现有墟境时间控制模块；候选生成本身不会写入世界时间、地点或 `exploring` 状态。

## MVU人物与宗族谱系

工作台不提供独立人物查看器，也不维护人物隐藏清单或自定义人物组。

宗族谱系入口只读获取当前聊天的 `stat_data.关系列表`：

- 只有当前列表中的人物可以成为谱系中心。
- 谱系上下文只提取生成所需的人物摘要，不修改MVU人物对象。
- MVU人物可从族谱节点加入墟境参与人物；非MVU亲属只能查看族谱基础信息。
- 切换角色卡或聊天后重新读取当前列表，不复用其他存档的人物。
- 传记、墟境和蝴蝶效应仍按各自上下文规则读取必要人物资料，不依赖任何人物查看器缓存。
