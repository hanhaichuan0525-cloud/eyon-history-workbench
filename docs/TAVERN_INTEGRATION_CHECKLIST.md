# 酒馆端到端联调清单

本清单用于正式界面接线后的真实酒馆验证。每组测试使用独立的新聊天，测试期间保留现有墟境时间控制脚本和角色卡世界书。

## 1. 启动与命名空间

- 加载 `dist/index.js` 后只出现一个 `window.EyonHistoryWorkbench`。
- 重载脚本不会重复注册生成拦截器和事件监听。
- 切换角色卡或聊天后，传记、族谱、候选墟境和蝴蝶效应列表随命名空间切换。
- 切回旧聊天后只恢复该聊天自己的资料。
- 切换聊天时进行中的独立API结果不得落入新聊天。

## 2. API路由

分别对 `genealogy`、`ruin`、`biography`、`butterfly` 验证：

- `follow_tavern` 使用当前酒馆插头，静默、非流式，不创建聊天楼。
- `custom` 使用当前模块自己的 `apiurl/key/model/source/maxTokens/temperature`。
- 修改一个模块不会改变其他三个模块。
- “应用到全部模块”复制同一份已校验配置。
- 错误端点只报告当前模块失败，不自动切换接口，不写MVU。
- API密钥不进入正文、世界书、状态事件和控制台日志。

## 3. 宗族谱系

- 只能选择当前MVU角色列表中的中心人物。
- 生成结果只进入当前聊天族谱仓库。
- 不创建玩家楼或助手楼。
- 不修改世界、墟境系统或人物MVU字段。
- 左右切换聊天、重载页面后记录隔离不变。

## 3.1 人物查看器

- 初次读取显示当前 `stat_data.关系列表` 的全部有效人物。
- 隐藏一个人物后，MVU变量管理器中的人物对象保持不变。
- 切换聊天存档后，不继承另一存档的隐藏清单。
- 点击同步变量后，误隐藏但仍存在于MVU的人物重新显示。
- 隐藏或同步过程中切换聊天，操作必须失败且不得写入任一存档。

## 4. 墟境候选与进入

- “墟境探索”只生成候选，不修改 `idle`。
- 候选数量、纪元、起止时间、地点、参与人物和补充方向与面板输入一致。
- 点击不可进入节点时不创建玩家楼。
- 点击特异点时重新读取点击瞬间的现实时间地点。
- 非 `idle` 状态拒绝进入。
- 成功时只创建一个“进入节点”玩家楼，并由紧邻助手楼完成正文、面板和唯一变量更新。
- 自动额外变量、手动额外变量和主模型变量三种模式分别验证：
  - `exploring` 不会被旧轮次状态覆盖。
  - 现实锚点保持锁定。
  - 世界时地与墟境当前时地同步。
  - 墟境内后续楼层可以推进时地。

## 5. 寻根溯源

- 严格命令只触发一次后台传记生成。
- 正文仍由正文模型自然生成伊雍对话。
- 已校验传记只替换锁定助手楼中的唯一插槽。
- 重Roll和swipe不会把结果提交到错误版本。
- 传记保存到当前聊天资料库，不进入其他聊天。

## 6. 遣返与蝴蝶效应

- 只有玩家明确输入或点击“遣返”才触发。
- 发送遣返前冻结当前 `runId` 的现实、进入和离开三套时地。
- 冻结不得使用旧归档轮次或不匹配快照。
- 时间控制模块正常恢复现实并清空活动状态，后台API不得阻塞。
- 蝴蝶效应只在紧邻遣返助手楼追加一个面板。
- 同一轮次只写一个当前聊天世界书条目。
- API失败后遣返仍完成，并可使用原冻结快照重试。

## 7. 回归

- 关闭工作台后，原时间控制脚本仍能独立运行。
- 工作台候选、族谱和传记功能均不得直接写流程状态或世界时地。
- 删除楼层、隐藏旧楼、切换swipe和重启酒馆后，不得恢复其他聊天或旧轮次的待处理请求。
- 三套现有美化正则继续识别传记、墟境面板和蝴蝶效应面板。
