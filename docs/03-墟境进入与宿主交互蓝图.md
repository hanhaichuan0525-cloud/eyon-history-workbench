## 1. 当前唯一用户链路

```text
玩家填写墟境条件
  → 批量生成 3—5 份候选提纲
  → 依次自动扩写全部候选史稿
  → 玩家阅读完整史稿、跨度、演变、转向和因果节点
  → 玩家选择候选和缘起/经过/高潮/结果中的任一阶段
  → 点击进入
  → 注入进入契约并发送玩家楼
  → 正文模型建立唯一探索回复楼
  → 脚本校验楼层、提交元数据并清理注入
  → 玩家观察现场后在同页填写干预方向
  → 独立 API 编译一项任务草案
  → 下一条正常正文自然建立任务并写入 MVU
```

旧“只显示提纲，玩家先选，进入时再扩写一份史稿”已经废弃。

## 2. 候选生成与自动扩写

### 2.1 生成阶段

- `RuinWorkflow.generate()` 在返回候选记录前自动扩写全部候选。
- 扩写按稳定候选顺序依次执行；当前合同不要求并发。
- 扩写期间界面显示加载圈和当前进度，玩家能知道系统正在编织并校订完整史稿。
- 单个候选失败不撤销已经完成的候选，也不阻止后续候选尝试。
- failed 和中断遗留的 pending 候选可在界面单独重试。

### 2.2 审阅阶段

- ready 候选直接展示完整史稿，而非只展示提纲摘要。
- 切换候选只切换本地已生成内容，不触发模型请求。
- 玩家必须在看到完整史稿后选择候选和具体历史阶段。
- 非 ready 候选不能进入；按钮状态和工作流硬门必须一致。

### 2.3 明确废弃

- `expandForEntry` 不再属于进入链路。
- 点击进入不得隐式扩写、修复或重新选源。
- 不得恢复“候选提纲已就绪，进入时扩写”的 UI 文案。

## 3. 进入契约与注入

### 3.1 玩家楼与私密契约分离

- 玩家楼只保留玩家原话或确定性默认语。
- 完整墟境进入契约通过 ST 注入层发送，不污染玩家可见文本。
- 输入框读取失败时中止，不建立半截状态。
- 空白输入使用默认语；命中工作台命令格式时使用安全默认语，避免命令拦截。

### 3.2 注入生命周期

```text
idle
  → prepareSelection
  → arm injection
  → sendUserTurn
  → wait assistant rendered
  → assert rendered floor
  → commit metadata
  → clear injection
  → submitted/exploring
```

任何失败路径都必须：

- 清理本次注入；
- 释放或恢复对应 flow state；
- 不留下无主楼层锁；
- 不覆盖玩家在发送期间新输入的文本；
- 通过宿主 toast 给出可理解反馈。

### 3.3 进入时冻结的信息

进入契约绑定：

- 当前聊天命名空间；
- 选中候选与节点；
- 目标墟境时间和地点；
- 现实锚点快照；
- EvidenceBundle/Canon revision 身份；
- RuinTrace；
- 触发玩家楼和预期助手楼身份。

### 3.4 G-01 四阶段与地点合同

- `origin/process/anomaly/result` 四个机器键全部可进入，界面依次显示为“缘起/经过/高潮/结果”。为兼容既有存档与 schema，`anomaly` 不改名，只改变玩家可见文案。
- 一次进入只绑定一个节点。不同阶段提供不同介入边界：缘起可改变萌芽条件；经过可改变人物选择与资源流；高潮可改变关键转折；结果可改变救援、证据、余波和后续传播，但不能无因抹除已经发生的前史。
- 玩家在生成面板可以只填地点简称。候选节点必须把它还原为角色卡 MVU 规范的 4～8 层完整路径：`${大陆名+方位}-${势力/区域}-${子级势力}-${聚落/地标}-${区位}-${详细位置}`，由大到小，以半角连字符连接。
- 进入时，`墟境当前地点`、`本轮墟境进入地点` 和 `世界.地点` 逐字复制同一目标路径。旧候选节点若只存简称，可在原生成地点已是完整路径时确定性补足；两边都只有简称时拒绝进入并要求重建候选，不凭空发明大陆或势力。

候选生成完成后到进入之间，不得偷偷重新检索或切换 revision。若当前版本已经变化，应显式要求重建候选或重新确认，而不是混用两份历史。

### 3.5 进入后的任务建立

- 任务区仍属于“墟境探查”页面，不增加第六个顶栏模块；只有 `exploring|anchored` 才显示。
- 进入楼只建立现场，不自动生成任务。玩家必须在后续明确一个可执行方向，脚本才调用墟境 API 设置编译 `eyon.ruin-task.v1`。
- 草案经本地 schema 校验和难度—FP 确定性映射后，以一次性隐藏契约交给下一条正常正文。正文负责自然引出任务、显示唯一 `<task_info>`，并通过唯一 MVU 更新写入 `stat_data.任务列表`；脚本不直接写变量。
- `[墟境任务·个人]` 与 `[墟境任务·团队]` 共用角色卡既有任务记录字段。任务列表是唯一真源，面板和工作台只读同一份记录。
- 任一未终态墟境任务存在时，界面锁定且工作流在 API 前拒绝第二项。完成、失败、取消、放弃、终止、已结算或可结算后，仍在同一轮次才允许续建。
- API 返回前必须复核聊天、runId 与活动任务。任一变化都隔离迟到结果，不建立玩家楼。

## 4. 楼层事务

### 4.1 唯一楼层

- `sendUserTurn` 建立唯一可见玩家楼并触发回复。
- 渲染断言验证助手楼紧邻触发楼、身份匹配、内容非空且流式完成。
- 断言未满足时保留等待锁，不提前提交，也不销毁可恢复状态。
- 通过后双写请求元数据、提交进入状态并清理注入。

### 4.2 删除与重新进入

- 删除对应进入/遣返楼层时释放 `submitted` 防重状态。
- 同一历史节点在回退后可以重新进入。
- 删除无关楼层不得释放当前有效进入锁。
- Canon revision 回滚由主蓝图和存储层负责；本子系统只提供准确楼层事件和绑定身份。

### 4.3 换聊天和取消

- 换聊天、取消任务或宿主生命周期终止时调用 cancel/clear。
- 注入、pending 锁、计时通知和本次请求缓存必须按聊天隔离。

## 5. 确定性显示

### 5.1 时间标签

- 模型返回的自由 `label` 不能成为时间真源。
- 候选跨度和节点时间由脚本根据规范化年月日时分确定性渲染。
- 节点标题与时间分开显示；时间标签不附加旧 `(N)` 编号后缀。
- 面板、进入契约和工作台 UI 消费同一时间渲染结果。

### 5.2 时期转向

- `shift.from` 是候选起点时期；`shift.to` 是终点时期。
- 转向应反映真实演变，不得总是“稳定→稳定”。
- 面板显示简洁方向，不把模型解释段拼进转向标签。

### 5.3 失败与进度

- 生成全部史稿时显示加载圈、已完成数量和当前候选。
- 成功通知必须自动消失。
- 同类通知有叠加上限，不能长期占据宿主界面。
- 错误通知保留候选或阶段信息，便于单项重试。

## 6. 与统一检索的接口

本子系统只消费已经生成并通过校验的候选记录。它不得：

- 在进入时重新调用检索器；
- 修改 CastManifest、人物事实或 qualification；
- 自行判断 Canon 当前版本；
- 重新扩写史稿；
- 把未 ready 候选通过 UI 绕过工作流硬门。

主蓝图负责历史事实，宿主交互蓝图负责把已经冻结的选择安全送入真实聊天。

## 7. 验收

### 自动化/静态

1. 生成 3—5 个候选时全部依次进入 expansion；
2. 单项失败不撤销其他 ready 候选；
3. 切换候选和进入动作的模型调用数为 0；
4. 非 ready 候选工作流与按钮均禁止进入；
5. `expandForEntry` 无生产引用；
6. 加载圈在扩写开始显示、全部结束或失败后正确收起；
7. 时间标签、shift、通知和删楼重入夹具通过；
8. 换聊天清理注入和 pending 状态。
9. 四个节点均可建立进入契约，界面把 `anomaly` 显示为“高潮”；
10. 目标地点必须为 4～8 层，三处 MVU 地点写回逐字一致；旧简称在缺少完整父级时明确拒绝。
11. 现实态不渲染任务区；探索态无任务时可生成一项，已有未结束任务时 API 调用数为 0；终态后允许下一项。
12. API 只返回 `eyon.ruin-task.v1`，脚本没有 `replaceMvuData` 或任务列表直写路径；紧邻正文楼负责面板与唯一变量更新。

### 真实酒馆

1. 玩家能在选择前看到全部完整史稿；
2. 扩写期间加载状态可见且不阻塞宿主其他必要反馈；
3. 进入只发送一轮玩家楼和一轮助手楼；
4. 玩家输入不被契约文本污染；
5. 删除进入楼后可以重新进入；
6. 成功、失败和计时通知不会无限叠加；
7. 换聊天后无残留注入；
8. 驾驶员确认后才能标记接受。
9. 缘起、经过、高潮、结果四张节点卡都能进入，进入后叙事从所选阶段继续；
10. 简写生成地点不会原样污染 MVU，入境后三处地点变量均为同一条合规完整路径。
11. 进入后任务区出现，任务正文与 MVU 任务栏同名同值；未结束时按钮锁定，完成后可在同一墟境建立下一项。
12. 建立任务不会重复进入墟境、不会自动遣返，也不会把 API JSON 或内部标识显示给玩家。

## 8. 红线

- 不把检索或 Canon 逻辑搬进 UI/controller。
- 不在候选选择或进入时增加模型调用。
- 不因 UI 失败改写候选历史内容。
- 不依赖模型自由 label 作为时间和状态真源。
- 不用美化正则承担进入契约。
- 不在文档整理阶段声称真实酒馆链路已验收。
