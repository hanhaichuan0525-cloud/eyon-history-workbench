## 0. A0 开工三格

### 目标

让同一聊天分支、同一 Canon revision 下生成的传记、谱系与后续墟境能够复用已经建立的少量持久细节，避免同一事件反复换年份、同一物件反复获得、同一关系反复重建；同时保证这些生成内容永远不会冒充世界书、MVU、玩家行动或蝴蝶 Canon。

### 红线

1. 不恢复语义编译层，不拆整篇正文做句子级事实抽取；
2. 不让模型生成或裁决内部稳定 ID；
3. 不把生成事实自动升级为高权正史；
4. 不修改 P1 的当前 Canon，不绕过 P2 的局部有效性，不重做 P3 的因果仲裁；
5. 不因缺锚、坏锚、旧存档、歧义或缓存故障截断传记、谱系、墟境或遣返；
6. 不为普通生成新增第二次模型调用；
7. 不把全部旧产物全文重新塞回提示词；
8. 不在后台删除、改写或“修复”旧传记、旧谱系、旧墟境正文；
9. 不跨聊天、分支或 revision 借用锚；
10. 不把未进入的墟境候选、失败草稿、模型仿写面板或蝴蝶可读面板当成连续性事实。

### 验收

P4 的每一级必须分别通过：纯函数/仓储自动化、typecheck、生产构建、真实酒馆场景和驾驶员确认。任一级通过后停在下一道门，不能一次实现 A—D 后再整体宣称成功。

## 1. P4 只解决什么

P4 只解决：

> **同一有效历史版本中，已经通过校验并提交的生成产物，如何向后续相关生成提供低权、可撤销、可解释的连续性。**

P4 不解决：

- 哪条世界书事实是真正正史——由 P1 `resolveCanon` 负责；
- 历史改变后哪些旧产物失效——由 P2 binding / assessment / consumption 负责；
- 多次玩家干涉的因果链如何断裂、承接和协调——由 P3 负责；
- 普通聊天传记连续性由独立后继 G-08 消费（internal.118 已实施，不计入 P4 分母）；
- 删除档案不等于回滚 Canon；独立后继 G-09 以紧凑记忆残片维持因果可读性（internal.118 已实施）；
- 所有开放世界背景如何自动演绎——不属于本项目可穷举目标。

一句话区分：

```text
P1 决定“现在什么是真的”
P2 决定“旧产物哪一小块还能用”
P3 决定“互相冲突的历史干涉如何局部重基线”
P4 决定“当前版本的新作品如何记住彼此已经写过什么”
```

## 2. 为什么不能把生成内容直接当 Canon

模型生成的传记、谱系和墟境里混有三类内容：

1. **继承事实**：来自世界书、MVU、聊天锚或当前蝴蝶 Canon；
2. **证据相容解释**：资料没有写死，模型选择了一个合理版本；
3. **叙事装饰**：天气、动作、台词、临时人物、感官描写与一次性场景细节。

只有第二类中的少量持久事件值得跨产物共享。若把整篇正文都当 Canon，会形成最危险的反馈环：

```text
一次随机原创
  → 被系统保存成事实
  → 后续模型反复引用
  → 看起来越来越像正史
  → 最终压过真正来源
```

因此 P4 的生成锚是**连续性记忆**，不是**正史写入**。重复出现不会提升其权威，生成次数也不是投票。

## 3. 权威与作用域合同

### 3.1 三条相互独立的轴

P4 不建立一个粗暴的“谁优先”总排行榜，而是区分：

- **Canon 权威轴**：世界书/MVU/玩家行动/verified delta 由 P1—P3 处理；
- **任务方向轴**：玩家本轮明确输入决定本轮想看什么，但不会自动改写 Canon；
- **连续性轴**：P4 锚只用于提醒“同版作品已经如何解释过空白”。

任务方向可以要求探索另一种解释，但只有蝴蝶 Canon 链路能改变当前正史。P4 不能把一句生成指令偷换成历史改写。

### 3.2 P4 锚的最高权限

生成锚最多可以：

- 作为后续传记/墟境的连续性参考；
- 防止同一已发生事件被无意识地换年份重演；
- 提醒已经建立的参与者、地点和持久物件；
- 在有明确依据时声明“这是并行解释”或“来源存在冲突”。

生成锚绝不能：

- 覆盖当前 Canon fact 或 operation；
- 创建蝴蝶 delta；
- 判定人物死亡、复活、监禁、血缘或所有权的高权现状；
- 让 P2/P3 已判失效的内容重新进入普通生成；
- 因多次被引用而自动升格。

### 3.3 作用域

任何 P4 连续性视图必须同时绑定：

- `WorkbenchNamespace`（角色卡 + 聊天）；
- `branchId`；
- `canonRevision`；
- 生产它的 `artifactId + unitId`；
- 与该单位同源的 `ArtifactCanonBinding` 或明确的旧产物兼容状态。

缺任一关键身份时，锚保持不可自动复用；不得猜测所属聊天、分支或 revision。

### 3.4 当前时间原点权威（2026-09-23 冻结补充）

出生、建筑落成、机构成立等“时间原点”不能由任意叙事中的年龄或持续年数反推。它们属于 P1/P3 当前 Canon 投影的基础时间事实；P4 只在 Canon 留白时记住同 revision 作品已经采用的低权解释，不能把该解释升级为正史。

当前 revision 的读取次序冻结为：

1. 当前分支、当前 revision 中仍 active 且 verified 的玩家干涉时间事实；
2. 世界书或 MVU 人物/地点/组织资料中明确写出的出生、建立、成立、建造、落成等字段；
3. 同 revision 已提交生成产物中的 P4 低权连续性锚，仅用于资料空白中的后续一致性；
4. 仍无时间原点时保持未知，交给模型在历史空白中自然发挥，不伪造确定年份。

约束如下：

- “复兴纪元480年，十九岁的某人……”只证明该事件现场的年龄；不得据此把来源标题识别为人物，也不得用当前世界年或事件年反推出生年；
- 年龄、建筑年限和机构历史长度一律在使用处由“该段年份 − 当前 revision 时间原点”计算，不保存为另一份竞争基准；
- 玩家通过正式干涉明确改变出生、建立、成立、建造或落成时间时，新时间原点替换当前 revision 的旧投影；删除遣返楼回滚后恢复父 revision 的原点；
- 时间原点被替换时，旧的 `ageAtRecord / basedOnYear / ageBased` 等派生元数据必须退出当前投影，不能与新出生年并存；
- 同名对象不能仅靠字符串跨实体、跨聊天、跨分支或跨 revision 合并；
- 缺字段、旧存档或冲突无法安全判断时 fail-open：保留未知或低权提示，不截断传记、谱系、墟境、蝴蝶结算或普通正文。

该补充不授权 P4-B/P4-C/P4-D，也不把谱系或任意旧正文全文变成时间事实数据库。特别是“第一次生成的年份”只有在既有 P4 生产者与消费者范围内才可作为连续性参考；谱系成为生产者仍须等待 P4-B。

## 4. 最小数据合同

### 4.1 `GeneratedContinuityAnchor`

P4-A 第一版冻结为“自然语言主张 + 最小结构信封”，不建立句子级事实表：

```ts
interface GeneratedContinuityAnchor {
  schema: 'eyon.continuity.anchor.v1';
  anchorId: string;              // 脚本确定性生成，模型不可填写
  branchId: string;
  canonRevision: number;
  producer: {
    artifactType: 'biography';   // P4-A 只开放已提交传记
    artifactId: string;
    unitId: string;              // origin / stage / status
    bindingId?: string;
  };
  eventId: string;               // 复用已冻结的传记主事件槽，不从正文猜
  claim: string;                 // 完整、简短、可独立理解的自然语言事件主张
  temporalScope: {
    label: string;
    start?: string;
    end?: string;
  };
  participants: Array<{
    entityId?: string;
    name: string;
  }>;
  locations: Array<{
    entityId?: string;
    name: string;
  }>;
  sourceRefs: string[];
  stance: 'asserted' | 'hypothesis';
  createdAt: number;
}
```

设计含义：

- `claim` 承载故事含义，结构只负责身份、作用域、时间和来源；
- `claim` 只取既有 `eventAssignments` 中已经冻结的主事件描述并做长度归一化，不从扩写正文抽句，也不再调用模型概括；
- `eventId` 来自传记规划时已经冻结并在扩写时逐字回报的主事件槽；
- `stance=hypothesis` 对应资料空白中的相容解释，永远不能阻止另一种解释；
- `stance=asserted` 只表示“该已提交产物明确采用了这一版本”，仍不等于 Canon；
- `entityId` 只有目录能唯一解析时才写，不能唯一解析就只留名称且不做跨实体硬归并。

### 4.2 不新增模型必填字段

P4-A 首版不得在传记响应中增加新的强制字段。锚候选只使用已经存在且已经校验的：

- `eventAssignments`；
- `eventId / eventUsage`；
- passage 的结构化 span；
- `people / factions / objects / locations` 索引；
- `sourceRefs / inference`；
- 现有 `ArtifactCanonBinding`。

不扫描正文寻找“像事实的句子”，不让模型额外输出 `anchorId/factKey/dependencies`。

#### 4.2.1 P4-A2 有界修订：最终正文关键连续性附注

真机验收发现：冻结主事件摘要能够保住“发生了搜查”，却可能丢失成稿正文才明确写出的“复兴纪元486年秋书店焚毁、原址化为焦土且未修复”。后续作品于是可能把年份提前、让已毁场所无依据复活。该问题不是 P3 因果冲突，也不是 Canon 缺失，而是 P4-A 的生产粒度不足。

驾驶员授权的 P4-A2 只增加下列有界能力：

- 复用 internal.103 已存在的**整篇语义复核请求**，不增加模型调用；
- 每个 `eventUsage=occurs` passage 最多回报一条可选 `continuityClaim`；它必须是最终 `content` 已明确写出的、可独立理解的短自然语言事实；
- 允许记录出生/建立/建造、死亡/焚毁/消失、归属/持有者变化、具名原件损坏/遗失/封存/修复/替换、唯一赠予、关系建立/断裂等具有跨作品连续价值的边界变化；
- 同段若有两项紧密相关的关键变化，可在同一个短句中并列；普通天气、衣着、心情、气氛、一次性动作及无持久后果细节不记录；
- `continuityClaim` 是**可选软字段**：缺失、空串、非字符串、过长或不够独立时静默忽略，不触发 schema 报错、repair、重试或正文截断；
- 首稿自行填写的附注不采纳；只有完整语义复核成功返回的附注可进入锚。复核失败时退回原 P4-A 事件槽锚；
- 最终正文附注与原事件槽共用同一 `eventId`。存储可同时保留二者用于审计，但后续视图只占一个槽，并优先投递最终正文附注；
- 若语义复核后脚本又确定性改写正文（例如删去冲突的精确年龄），对应附注直接丢弃，不让旧摘要凌驾于最终正文；
- 仍只在新 committed biography、同聊天、同分支、同 revision、当前 ArtifactCanonBinding 有效时可见；删除、回滚、revision 改变与 P2 失效规则完全沿用 P4-A；
- 不回填旧传记，不扫描任意旧正文，不建立句子级事实数据库，不晋升 Canon，不直接建立 P3 因果支撑单元，也不开放谱系/墟境为生产者。

因此，P4-0 的权威边界没有改变：模型理解自然语言，结构只保存一个有界、低权、可撤销的连续性信封。

#### 4.2.2 P4-A2 验收修订：已提交原文定点复核（internal.105）

internal.104 真机重测仍把 486 年 9 月焚毁的“沉睡之眼”写成 486 年深秋继续营业。原因是事件槽锚只有概括性“秋季焚毁”，没有带上旧传记正文的具体月份与 488 年仍是废墟的延续状态；首轮复核原样返回时也会被接受。驾驶员确认后，在 P4-A2 内修订消费端：

- 仅在传记首稿后的全文复核阶段，对**已选中的同 revision、P2 仍有效的锚**，有界附上其产生段落的已提交正文摘录；若锚涉及旧传记目标，再附该作品现状摘录。最多两条锚附原文，每条事件摘录至多 640 字、现状摘录至多 380 字。不是将整本旧传记送入提示词，也不回填或改写旧锚。
- 模型逐段对比旧事件发生时间、后续状态与新草稿。若首轮在看到原文后仍有段落逐字未改，允许**最多一次**定点语义复核；仍使用现有 passage 输出格式，不新增必填字段。此处是对上节“复核不增加模型调用”的明确窄范围例外，普通首稿生成不增加调用。
- 定点复核失败或仍原样返回时保留已通过结构校验的文本，不硬报错、不截断、不用字面规则擅自删除；诊断与真机验收须继续标明低权模型复核不能给出形式化绝对保证。
- 旧作品仍低于玩家明确指令和当前 Canon；可以有证据地修复、重建或换址，不能为了迁就首稿临时编造过程。本修订不开放 P4-B/C/D，也不把原文句子编译成 P3 因果单位。

### 4.3 锚与状态分离

锚记录创建时的不可变内容；“现在能不能用”必须按当前 head 派生，不写回锚本体：

```ts
interface ContinuityAnchorAssessment {
  anchorId: string;
  targetBranchId: string;
  targetRevision: number;
  eligibility: 'assessable' | 'unbound' | 'binding-missing';
  status?: 'current' | 'stale' | 'orphaned' | 'uncertain' | 'reverted';
  reasonCodes: string[];
}
```

状态尽量复用 P2/P3 已有语义，不建立第二套相似状态机。`partially-stale` 属于产物单位状态；一个单事件锚若依赖中有失效项且无法安全拆分，直接 `uncertain`，不能自行截半句。

### 4.4 存储位置

锚应作为生产传记记录的可选附属字段保存，随产物删除、聊天隔离和备份导出一起处理；第一版不建立独立“生成正史数据库”。读取时构建有界索引，索引只是派生视图。

旧记录没有锚字段时保持可读、可手动引用，但不回扫正文补锚。

## 5. 生成锚准入门

### 5.1 六项全部满足才可成为锚

一个候选事件只有同时满足以下条件才可发布：

1. **产物已提交**：来自 committed biography，而非草稿、失败响应或临时预览；
2. **单位明确**：能定位到唯一 origin/stage/status 与 eventId；
3. **事件实际发生**：`eventUsage=occurs`；aftermath/recollection/evidence/background 只引用旧事件，不新建锚；
4. **当前版本兼容**：生产单位在创建 revision 上通过既有 Canon 校验；
5. **可独立理解**：claim 不依赖上一句或隐藏代词才能知道谁做了什么；
6. **具有跨产物价值**：至少明确时间、参与者、地点或持续物件中的两项；只剩氛围或文风时不发布。

### 5.2 明确不准入

以下内容不得成为锚：

- 天气、香味、光线、姿势、服饰细节；
- 一次性台词与心理描写；
- 没有身份支撑的临时路人姓名；
- 纯修辞性称号；
- 仅在正文里出现、没有主事件槽承载的顺手发挥；
- `recollection/evidence/background` 对旧事件的再叙述；
- 未选择的墟境候选；
- 蝴蝶面板文字；
- 模型输出的内部 ID、factKey 或自报权威等级；
- 与当前 Canon 明确冲突的内容。

### 5.3 缺失即不共享，不报错

锚准入失败的唯一运行时结果是：

- 传记正文照常提交；
- 该候选不进入连续性索引；
- 诊断记录有界 reason code；
- 后续任务少一条连续性参考。

不得把锚失败升级为传记失败、repair 或重试。

## 6. 连续性消费合同

### 6.1 `ContinuityView`

后续任务只能读取当前分支、当前 revision、当前任务相关的紧凑视图：

```ts
interface ContinuityView {
  schema: 'eyon.continuity.view.v1';
  branchId: string;
  canonRevision: number;
  queryScopeHash: string;
  anchors: Array<{
    handle: string;              // 本轮短句柄，不暴露内部 anchorId
    claim: string;
    time: string;
    participants: string[];
    locations: string[];
    stance: 'asserted' | 'hypothesis';
    origin: string;              // 人类可读产物/段落说明
  }>;
  omittedCount: number;
  warnings: string[];
}
```

### 6.2 只投递相关锚

相关性继续复用统一检索已有的实体、名称、时间、地点和来源共证纪律；不得新建语义向量服务或一套 P4 私有检索器。

第一版投递预算必须集中为单一常量，至少满足：

- 有锚数量上限；
- 有总字符上限；
- 超限按确定性相关度截断；
- 不把完整旧传记正文塞入；
- 同一 eventId 的回忆/余波不重复占位。

具体数值在 P4-A 实施合同中冻结，不在 P4-0 凭空假定最优常量。

### 6.3 模型看到的是自然语言提示，不是状态机

`ContinuityView` 对模型表达为简短自然语言：

- asserted：同版作品已经采用此事，若玩家没有明确要求另一解释，应保持其身份与时间连续；
- hypothesis：这是已有相容解释，可以沿用，也可在玩家明确方向或新证据支持下采用另一解释；
- 所有锚都低于当前 Canon；冲突时以 Canon 为准；
- 不要求逐条复述，不把锚当演员配额。

### 6.4 不要求模型回报锚

P4-A 第一版只做“相关锚进入上下文 + 新 committed biography 派生锚”。模型不需要在响应中逐条引用锚句柄；是否沿用由现有自然语言成稿与最小确定性检查共同观察，避免再造 Citation Contract v3。

后续若 P4-C 确需声明 parallel/sourceConflict，只允许增加可选短句柄关系，不得把普通生成变成引用考试。

### 6.5 玩家明确方向

玩家明确要求另一种证据相容解释时：

- 本轮可以不沿用 hypothesis；
- 不得静默覆盖世界书或蝴蝶 Canon；
- 不后台改写旧作品；
- 新产物提交后，可在 P4-C 记录为 parallelView；
- 若玩家意图是真正改变历史，必须走墟境/蝴蝶链路，而非 P4。

## 7. 分阶段实施合同

### P4-A · 同 revision 传记事实锚

#### 目标

建立最小 `GeneratedContinuityAnchor` 与 `ContinuityView`，让 committed biography 的主事件在同分支、同 revision 下供后续传记与墟境参考。

#### 生产者

- 仅 committed biography 的 origin/stage/status；
- 仅 `eventUsage=occurs` 的冻结主事件；
- P4-A2 允许同一 occurs 事件附带一条由最终正文语义复核确认的关键连续性短句；
- 锚内嵌于 BiographyRecord；
- 现有 `biographyUsage` 只能作为模型提示，不能作为发布锚的权威证明。

#### 消费者

- 后续传记规划与扩写；
- 后续墟境提纲与扩写；
- 谱系暂不消费，留给 P4-B；
- 蝴蝶结算不消费生成锚作为 Canon 证据。

#### 明确不做

- 不从旧传记正文回填；
- 不从墟境候选反向生产锚；
- 不做 parallelView/sourceConflict 自动分组；
- 不做持久缓存；
- 不增加模型调用；
- 不修改普通聊天记忆注入。

#### 退出条件

P4-A 自动化与真机验收全部通过，并由驾驶员确认“同版连续性提升且生成未被收死”，才可讨论 P4-B。

### P4-B · 谱系局部版本化

2026-09-26 驾驶员授权六项一并实施；具体补充合同、自动化与真机流程见 [`P4-B实施合同与验收.md`](P4-B实施合同与验收.md)。本次不新增谱系成稿事实锚生产格式，不开启 P4-C/D。

2026-09-26 后续真机暴露“证据名册作为准入白名单导致空谱系”。P4-B 合同随即修订：名册只锁定权威事实，资料空白允许生成低权亲属并补足父系、母系；脚本负责去来源、去 MVU/Canon 身份、稳定局部 ID 与局部容错。此修订仍属于谱系局部版本边界，不进入 P4-C/D，详见实施合同 internal.107 修订节。

#### 目标

在现有 node/edge `ArtifactCanonBinding` 基础上，构造当前 revision 的谱系局部视图；只让能证明受影响的节点或关系边退出自动复用。

#### 不变量

- node 与 edge 分开评估；
- 人物提前死亡只有在明确晚于死亡的出生、受孕、收养或关系建立与其矛盾时，才影响对应 edge；
- 时间未知时标 uncertain/manual-review，不自动删除后代；
- 不编造替代父母、继承人或血缘；
- 已有稳定 entityId 唯一匹配才跨谱系归并；名字近似但身份不唯一时保持产物局部；
- 新谱系可以复用当前有效旧 node/edge，但不能把旧谱系全文当成高权来源。

#### 退出条件

一个节点变化只影响直接可证明的 node/edge；无关亲属保持 current；回滚后原局部单位恢复；真实酒馆导出可解释原因。

### P4-C · parallelView / sourceConflict

2026-09-26 已在本总合同之下冻结第一版局部实施合同，见 [`P4-C实施合同与验收.md`](P4-C实施合同与验收.md)。internal.112 已按该合同实施，并于 2026-09-27 通过驾驶员真机验收：只有两次“暮潮移交”形成 `parallelView(time)`，其余相似但不同的事件没有误连。P4-C 只保存低权、可撤销、同分支同 revision 的两视图关系，不自动选赢家。

#### 目标

区分“资料空白中的多个合理解释”和“有来源支撑的明确矛盾”，避免把一切差异都当错误，也避免最后写入者静默获胜。

#### 语义

- `parallelView`：多个解释都与当前 Canon 相容，暂无高权证据决定唯一版本；
- `sourceConflict`：两个有效来源对同一事件的同一维度给出不兼容主张；
- 文风、措辞、镜头与情绪不同不构成 parallelView；
- 没有有效 sourceRefs 的分歧不能升级为 sourceConflict。

#### 有界原则

- 第一版每个冲突簇最多向模型投递两个当前视图；更多候选保留在诊断中，不做笛卡尔组合；
- 不自动选赢家；世界书/Canon 后续给出明确结论时，旧并行视图按 P2 状态退出；
- 玩家明确指定相容解释时可以采用，但不会修改 Canon；
- 模型自报 parallel/sourceConflict 只是一条候选关系，必须经脚本验证引用单位、分支、revision 与来源存在性。

#### 退出条件

同一模糊事件可以保留两种解释而不串成一个事实；明确来源冲突可见、可导出、不会阻断生成；不存在视图爆炸。

### P4-C2 · 史料疑云与冲突成因叙事

完整冻结合同见 [`P4-C2史料疑云与冲突成因叙事合同.md`](./P4-C2史料疑云与冲突成因叙事合同.md)。P4-C2 负责把 P4-C 已识别的相关差异转化为墟境中可感知、可追查、可干涉的历史疑云，而不是把关系记录原样展示给玩家。

P4-C2 冻结的是叙事责任，不冻结解释种类：不得建立 `causeType`、固定枚举、原因菜单或模板化台词。若既有正文或证据已经说明冲突为何形成，必须优先沿用；若尚无解释，模型可依据人物、制度、媒介、时间、地点与证据状态，自由织出局部且有痕迹的成因。成因可以混合、渐变、互相遮蔽，并应自然融进事件、场景、物证和人物认知中，而不是另设一段机械说明。

时间范围决定疑云怎样出现，而不决定它必须属于哪种解释类型：

- 只探查较早版本附近时，只留下可能导致后世异说的前向引子，不预言尚未发生的具体版本；
- 只探查较晚版本附近时，留下能反查早期记录为何变形、缺失或被重新理解的痕迹；
- 同时覆盖两个版本时，让玩家看到分歧如何逐步形成、传播或被固定；
- 与该冲突无关的墟境不强行注入疑云。

任何由 P4-C2 生成的成因仍是低权叙事假设，不自动裁定哪一版为正史，也不自动写入 Canon。只有既有穿越、遣返、蝴蝶效应与 Canon 验证链可以改变当前正史。

#### 退出条件

相关墟境能在不固定原因分类、不静默选边、不泄漏内部关系字段的前提下，将冲突自然编入叙事；无关墟境零污染；删除、revision 前进与回滚仍由 P4-C 当前投影控制。

### P4-D · 影响窗增量缓存

#### 目标

只缓存 P4 派生的 `ContinuityView` 与局部谱系视图，减少同 revision 重复评估；缓存永远不是事实源。

#### 缓存键至少包含

```text
namespace + branchId + canonRevision + queryScopeHash
+ module + subject/entity scope + time scope + location scope
+ anchorSetHash + assessmentPolicyVersion
```

#### 不变量

- revision、anchorSetHash 或 policyVersion 任一变化即拒绝旧缓存；
- 缓存缺失、损坏、超限或写入失败时重新计算；
- 绝不因缓存失败返回旧 revision 结果；
- 第一版优先内存有界缓存，不把缓存混入不可变产物记录；
- 清缓存不删除传记、谱系、Canon 或锚；
- 性能优化不得改变同输入的视图内容与排序。

#### 退出条件

重复同任务命中缓存与冷计算输出等价；相关 revision 变化只令相交影响窗失效；跨聊天、跨分支、跨 revision 零复用。

## 9. 失败与降级矩阵

| 故障 | 正确结果 | 禁止结果 |
|---|---|---|
| 旧传记没有锚 | 旧稿照常可读；本轮不自动共享 | 扫正文猜锚、报错、重写旧稿 |
| eventId/单位缺失 | 跳过单个候选并记诊断 | 整篇传记失败 |
| entity 名称歧义 | 保留名称，禁止跨实体硬归并 | 按相似字符串强行合并 |
| 锚与当前 Canon 冲突 | 排除锚，以 Canon 为准 | 让模型二选一或覆盖 Canon |
| 锚所属 revision 非当前 | 不注入；比较模式才可见 | 跨 revision 偷渡 |
| 生产单位 stale/orphaned | 锚退出当前视图 | 仍作为连续性强提示 |
| ContinuityView 组装失败 | 空视图继续普通生成 | 中止传记/墟境 |
| 存储附属锚失败 | 正文提交成功，记录 warning | 回滚已经成功的正文 |
| parallel/sourceConflict 引用坏 | 丢弃单条关系 | 整批 repair 或失败 |
| 缓存失效/损坏 | 冷计算 | 返回旧值 |
| 数量超限 | 确定性裁剪并报告 omittedCount | 扩大提示词直至超时 |

所有 P4 诊断必须有界，不保存世界书全文、完整 prompt 或额外模型思维过程。

## 10. 删除、回滚与迁移

### 删除生成产物

- 删除传记会一并删除其附属生成锚；
- 这是删除低权连续性记忆，不是回滚 Canon；
- P4-A 不要求模型回报“我实际采用了哪条锚”，因此不能把“曾经收到过该锚”误当成确定依赖；删除后既有其他产物原文与 P2 状态均不改写，只让该锚退出未来 `ContinuityView`；
- P4-A 可以保存“本轮曾投递哪些锚”的有界输入回执用于诊断，但该回执不具有依赖或失效判定权；若 P4-C 以后引入经过验证的显式视图关系，再单独按其合同处理；
- 如果有其他当前锚仍提供同一解释，可以继续使用其他锚。

### Canon 回滚

- revision 回退后，只读取恢复后 revision 可用的锚；
- 原 revision 的锚保留在原产物内用于审计，但不进入当前视图；
- 若回到锚创建时的 revision 且生产单位重新 current，该锚可确定性恢复。

### 旧存档

- 无锚字段 = legacy/unbound，不报错；
- 不进行启动时批量迁移；
- 不扫描旧正文自动造锚；
- 用户重新生成或明确选择“以后单独设计的人工采纳流程”之前，旧稿只作原有全文参考。

## 11. 诊断与解释性

每一级至少提供只读诊断，能回答：

1. 本次任务找到了多少锚、实际注入多少、裁剪多少；
2. 每条锚来自哪份产物、哪个局部单位、哪个 revision；
3. 它是 asserted 还是 hypothesis；
4. 为什么当前可用、被排除或待人工判断；
5. 是否存在 parallelView/sourceConflict；
6. 是否命中缓存，缓存键属于哪个 branch/revision；
7. 删除产物或回滚 revision 后哪些锚退出、哪些恢复。

诊断可以显示内部 ID；模型提示与用户正文不暴露内部稳定 ID，只使用本轮短句柄或人类可读来源名。

## 14. Core Spine / First Usable / Growth / Parking Lot

### Core Spine

- 当前 Canon 与生成连续性权威分离；
- 锚绑定 namespace/branch/revision/artifact unit；
- 锚内容不可变、状态按当前 head 派生；
- 缺锚 fail-open；
- 只投递任务相关的短自然语言视图；
- 删除与回滚可解释、可恢复。

### First Usable

仅 P4-A：一份新 committed biography 的主事件锚能在同 revision 的下一份相关传记和墟境中被看到；无关任务、旧存档、其他聊天和其他 revision 看不到；任何 P4 故障不阻断正常生成。

First Usable 完成后停在驾驶员验收，不自动进入 P4-B。

### Growth Tracks

- P4-B 谱系 node/edge 局部版本；
- P4-C 并行解释与来源冲突；
- P4-C2 史料疑云与冲突成因叙事；
- P4-D 增量缓存；
- 只有出现真实需求后，才讨论更多产物成为锚生产者。

### Parking Lot

- 旧传记人工采纳/手工补锚工具；
- G-08 普通聊天传记 digest 双源已形成独立冻结合同，仍不计入 P4 完成分母；
- 向量或 embedding；
- 通用全文拆句、逐句事实抽取与旧稿自动回填（P4-A2 的“每个 occurs 段最多一条最终正文关键附注”不属于此项）；
- 自动选择并行解释赢家；
- 将未进入墟境候选作为事实；
- 生成锚晋升 Canon 的投票或次数机制；
- 跨聊天共享个人“世界总史”。

Parking Lot 不构成承诺，也不计入 P4 完成分母。
