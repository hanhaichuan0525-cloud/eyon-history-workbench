# Eyon History Workbench

伊雍历史工作台是为《命定之诗》角色卡设计的历史探索系统。

当前对外版本为 **β1.9.1**（更新协议数字版 **0.14.34**）。在β1.9基础上修复带输入框行动的遣返识别，增加独立API地址预检，深化墟境/蝴蝶所选提示词，强化分岔未来与生活化感知；四模块共用保守两阶段检索并隔离全部命定系统的纯运行核心，传记补查同样适用。保留既有事实、年龄、Canon、家庭/特殊谱系与聊天隔离机制。

仅跟读开启且相关的来源，所选正文不按字符硬截；仍按相关性、来源和轮次选取，不把整本世界书灌给模型，也不执行EJS。不新增模型必填结构、依赖或调用。离线整合包为 [0.14.34脚本](release/酒馆助手脚本-伊雍历史工作台-v0.14.34.json)，详细改动见 [β1.9.1发布说明](release/0.14.34-β1.9.1发布说明.md)。旧测试包、私人世界书与聊天导出不上传。

从β1.8升级仍需手动用[伊雍核心文本](release/命定系统-伊雍-β1.9-核心规则.txt)替换原核心条目内容，并替换[原蝴蝶面板正则](release/regex/regex-伊雍-蝴蝶效应面板美化（as）.json)，不新增重复条目。已完成β1.9核心更新者无需再换核心；本次另需替换[原对话框正则](release/regex/regex-伊雍-对话框美化（as）.json)，让显示名始终为伊雍。脚本自动更新不替换玩家世界书或正则。入境后在蝴蝶控制台确认方案、点击“遣返现世”；正文口头遣返仅引导使用工作台。

本包防止已修复路径产生新的跨聊天污染，但不会自动恢复已污染的MVU/外部记忆，导入也不保证杀掉所有旧实例及遗留注入。升级前备份，停用旧工作台脚本和同功能扩展，完整刷新酒馆后只启用一套；旧污染需从正常楼层/备份另行恢复。真实宿主与模型质量仍需玩家复验。

β1 系列保留原生 Git 扩展入口，但它不是本次推荐安装通道；原生扩展的真实初始化、更新兼容性不在本次自动加载器验收承诺内。默认白天模式，工作台由角色卡悬浮球打开。原生扩展与 Tavern Helper 脚本不能同时启用。

如果你的酒馆环境无法稳定初始化原生 Git 扩展，推荐使用 `release/酒馆助手脚本-伊雍历史工作台-β1.json`。它是**整段内联**的加载器（没有静态 `import`，因此不会踩到 GitHub raw 把 `.js` 当 `text/plain` 返回、被浏览器按 MIME 拒绝的坑）：每次酒馆载入时读取 jsDelivr 上的最新 `manifest.json`，下载 `dist/index.js` 与 `dist/workbench.js`，先用 SHA-256 逐字节校验，通过后才在当前 Tavern Helper 脚本上下文加载运行时。首次成功加载后会在浏览器 Cache Storage 保存已验证的清单与 bundle；网络不可用时仅回退到最后一次校验通过的缓存，缓存与网络都不可用时只报错，不会执行未知内容。

自动更新脚本和原生扩展不要同时启用；导入自动更新脚本前请停用旧原生扩展及旧版内嵌整合脚本。脚本成功载入后，点击角色卡上的悬浮球即可打开工作台。已导入本仓库β1自动加载器的用户，下一次完整刷新酒馆、让脚本重新执行时会读取最新清单并按SHA-256校验代码；不是保持页面打开时即时热更新。CDN旧缓存或网络/哈希校验失败可能回退旧内容，更新后请核对工作台显示 **β1.9.1**（数字协议0.14.34）。本次加载器代码与β1.5发布时逐字节相同，无需重新导入，电脑和手机均如此。仅导入离线v0.x内嵌包的用户不会自动更新；核心文本与正文正则仍需按上述说明手动替换。

## 当前阶段

仓库已经进入正式宿主组装阶段：

- `rules/` 保存已经确认的脚本嵌入契约。
- `src/core/` 负责命令与按钮授权、创作参考、历史赎出、传记请求占位槽和聊天命名空间。
- `src/renderers/` 负责输出能被现有酒馆美化正则识别的固定原文。
- `src/adapters/` 定义酒馆、生成接口和世界书归档边界。
- `src/prompts/`、`src/schemas/` 与 `src/validators/` 负责后台提示词、严格结果结构和语义校验。
- `src/workflows/biography.ts` 已实现寻根溯源的第一条完整事务链。
- `src/workflows/ruin.ts` 已实现候选墟境的独立 API 生成、严格校验与存储；`ruinEntry.ts` 负责把玩家选中的历史阶段、点击时现实锚点和 `RuinTrace` 合并成唯一进入玩家楼。
- `src/workflows/butterfly.ts` 已实现遣返前冻结、独立 API 生成、校验、正文追加与本地归档；正文按关键词召回有效的完整原文。
- `src/storage/` 按角色卡与聊天隔离传记、族谱、候选墟境、蝴蝶效应原稿与待结算快照；候选生成不会写入世界时间、MVU 或墟境运行状态。
- `WorkbenchLifecycle` 统一路由命令与本轮按钮授权；聊天、楼层正文、swipe 或生命周期代际变化会使旧请求失效。
- `src/entry.ts` 已组装正式酒馆入口、脚本设置、当前绑定世界书/MVU 只读资料源、生命周期事件、墟境时间内核与工作台公开接口。
- P4 跨产物连续性 A—D 已进入源码，P4-E 文档已收口；P4-D 仅以有界进程内缓存加速连续性与谱系局部派生视图，缓存失败会冷算，不参与正史判断。
- `dist/index.js` 是酒馆助手运行时；`dist/workbench.js` 是统一五栏工作台入口，内部装载时空、谱系、墟境、传记和真实设置页。各独立构建仍保留用于分模块验收；`manifest.json` 记录全部入口、内测版本与 SHA-256。
- `prototype/` 使用演示资料挂载正式页面构建，仅用于交互与视觉验收，不另写一套界面逻辑。
- `prototype/biography-runtime.html` 挂载正式传记书库构建，按参考工作台提供书架检索、单面封套、单页长卷、闭合章节和点击书页返回封面。
- `prototype/timeline-runtime.html` 挂载正式墟境时空构建，只读展示现实/墟境时地、流程状态和当前聊天的蝴蝶效应档案。
- `prototype/workbench-runtime.html` 挂载统一工作台构建，用于验收桌面侧栏、移动端底栏、模块状态保留和设置即时换肤。

墟境时间内核已经并入正式入口：它严格接收完整进入契约、延续同一轮时间地点、锁定现实与进入锚点，并只在明确 `idle + 规则锁 0` 的遣返契约下归档和恢复现实。旧版独立墟境系统脚本不得与 `dist/index.js` 同时启用，以免两个监听器争抢同一组变量。

## 设计边界

- 世界书继续负责伊雍人设、正文格式和角色卡核心。
- 现有时间模块继续负责墟境状态、时间与地点。
- 独立 API 负责宗族谱系、墟境历史、寻根溯源和蝴蝶效应内容生成。
- 工作台负责检索、调度、校验、存储、渲染和受控注入。
- 伊雍对话框由正文模型依据世界书自然生成；脚本不代写台词。传记只替换唯一插槽，蝴蝶效应只在严格相邻的遣返助手楼追加或原位替换唯一面板。
- 候选墟境不占聊天楼；缘起、经过、高潮、结果四阶段均可进入。点击节点后只发送一个“进入节点”玩家楼，紧邻助手楼同时完成剧情衔接、正式面板和变量进入。
- 玩家可用简称描述墟境地点；生成结果与进入写回必须使用角色卡 MVU 的 4～8 层完整地点路径，且三处地点变量逐字一致。
- 遣返前只从当前活动 `runId` 冻结现实、墟境进入与墟境离开三套锚点；旧归档轮次和不匹配快照不能补值。
- 遣返正文生成前只注入一次隐藏协作提示，要求正文正常完成遣返且不自行生成、猜测或等待蝴蝶效应；提示在目标楼渲染后立即清除。
- 蝴蝶控制台先确认方案并准备结算，再由按钮发送唯一遣返玩家楼、登记授权并触发正文；失败保留可重试状态，不另建助手楼。
- 同一玩家遣返楼重roll复用冻结请求与完整结果；删除该玩家楼后重新点击工作台遣返才重新生成。
- 传记与蝴蝶本地归档按关键词召回完整原文，保留有效分支、卡/聊天隔离和历史赎出边界；旧世界书镜像仅作兼容来源。
- 不读取或修改记忆插件的私有数据。
- 不把 API 密钥、聊天全文或完整 MVU 对象提交到仓库。

## 正式入口

加载 `dist/index.js` 后，脚本会公开 `window.EyonHistoryWorkbench`。当前正式接口包括：

- 读取和更新生成 API 设置；
- 保存墟境生成面板草稿；
- 从面板生成候选墟境；
- 按当前角色卡与聊天读取本地候选、传记、族谱和蝴蝶效应；
- 只读获取当前墟境运行快照，用于时空首页展示；界面不能直接写MVU状态。
- 将选定历史阶段组装为唯一“进入节点”玩家楼并触发正文。
- 在蝴蝶控制台确认方案后发送遣返玩家楼，可携带输入框草稿；失败后按当前轮次重试。
- 宗族谱系面板直接读取当前聊天 `stat_data.关系列表`，只把其中人物作为谱系中心和可注入墟境的人物来源。
- 墟境生成面板读取当前聊天候选、人物引用和草稿；按所选时期与文风组装3/4/5组候选，旧骰表不决定题材。
- 因果节点保持同一横向时间轴并允许左右滑动；通过结果校验的缘起、经过、高潮、结果节点均能发送唯一进入玩家楼。
- 设置页可检查当前聊天资料完整性、导出不含 API 密钥的 JSON 备份，并只清理墟境生成草稿与临时参与人物。
- 调试控制台可通过 `inspectContinuityCache()` 查看 P4-D 命中/失效诊断，并用 `clearContinuityCache()` 只清派生内存缓存；两者都不会删除生成档案或 Canon。

工作台状态通过 `eyon-history-workbench:status` 事件发送。工作台不再实现独立人物查看器、人物隐藏清单或自定义人物分组；MVU人物读取只服务于宗族谱系及其后续联动。

## 扩展版安装（历史候选，非推荐通道）

扩展版适合希望由酒馆管理更新的用户：

1. 在 SillyTavern 的扩展管理页选择“安装扩展”，粘贴仓库地址：
   `https://github.com/hanhaichuan0525-cloud/eyon-history-workbench`。
2. 确认按 Git 仓库方式安装，并保持酒馆的 `extensions.autoUpdate` 开启；更新由 SillyTavern 的扩展更新器负责。
3. 重载页面后启用“伊雍历史工作台”。扩展会从仓库内的 `dist/` 加载正式运行时和工作台，不需要远程执行代码。
4. 扩展版与 JSON 脚本版二选一，不能同时启用，否则会有重复监听器。

这里的“自动更新”是酒馆扩展更新器的托管更新，不承诺每次打开页面都强制联网检查；需要立即检查时使用扩展管理页的“更新全部”。更新失败时保留当前已安装版本，断网仍可继续使用。

仓库 `release/` 提供内嵌后台运行时、墟境时间内核和五栏工作台的
`酒馆助手脚本-伊雍历史工作台-v0.14.26.json`，以及四个配套正则、核心文本和 SHA-256 清单。导入前必须关闭旧版伊雍墟境系统脚本、旧悬浮球与同名旧正则。

安装、冒烟测试与校验方式见 [`docs/INSTALL.md`](docs/INSTALL.md)。版本边界见 [`docs/RELEASE_STATUS.md`](docs/RELEASE_STATUS.md)。

角色卡世界书属于角色卡发行物，不同步到本仓库。脚本只在运行时通过受限适配器读取当前启用的世界书资料。
