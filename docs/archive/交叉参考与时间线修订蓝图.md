## 一、讨论共识(核心结论)

### 1.1 交叉参考 = 一张有向无环图(依赖图)

```
世界书 / MVU(根事实 · 永不原地改写)
   ├─→ 传记(生平档案:这段历史的年龄)
   ├─→ 谱系(身份账本推导器:这个人一生的年龄/亲缘/穿越类型)
   └─→ 墟境(分支史:只消费、不产出参考)
蝴蝶效应(归档后果) ──→ 传记 / 谱系 / 墟境(都该读它)
墟境候选史稿 ──✗── 谁都不许反向引用(它只是「待验证的分支」)
正文(当前时间线) ──→ 三个生成模块(近期事实)
```

**五条需求(用户提出)即这张图的五个约束:**

| # | 需求 | 一句话 |
|---|---|---|
| R1 | 墟境内容不作为其他模块参考,蝴蝶效应必须作为参考 | 图上的两条边:墟境候选=终端消费者;蝴蝶=公共参考源 |
| R2 | 世界书/上下文没有确切年龄时,谱系要根据世界书+传记+蝴蝶**合理推导**确切年龄/出生年代 | 谱系 = 身份账本推导器,推导必须落账 + 标来源 |
| R3 | 穿越者/构装体/肉身夺舍者等特殊情况,谱系生成要智能化推断 | 已有七类判定(见 3.1),需补"年龄双轨"与 `lineageKind` 输出 |
| R4 | 墟境内容加入人物/传记后,保证对二者的参考;冲突则自动纠错 | 需要共享账本 + 权威序仲裁(本蓝图 P3) |
| R5 | 这套机制的整体看法(见 1.2/1.3) | — |

### 1.2 机制整体看法(脑暴结论)

- 现有架构已经朝"有向依赖图"走:传记/墟境都读蝴蝶、都不读墟境候选、谱系有七类穿越判定、有界二次检索——**底子比多数插件成熟**。
- 真正的短板:
  1. **蝴蝶 → 谱系 缺边**(genealogyContext 不读蝴蝶效应);
  2. **没有共享"人物身份账本"**(静态:谁是谁)——R2 的"推导确切年龄"、R4 的"冲突自动纠错"都无从落地;
  3. 谱系推导年龄目前只靠提示词软约束,没有强制"落账 + 标注来源",下游无法校验;
  4. **没有"时间线修订"机制**(动态:何时改了什么)——玩家穿越改历史后的跨模块矛盾无解。

### 1.3 终局问题与"分层真"方案

**问题**:玩家穿越进墟境修正历史后,传记/谱系里的内容可能和蝴蝶效应面板冲突——例:① 玩家杀了谱系/传记中的人,这人"不该存在";② 玩家改变了世界书中的宏大格局,蝴蝶面板与世界书冲突。

**结论(阿瞳)**:不要改写世界书,也不要删记录;把"蝴蝶效应"从"一个面板"升级成**一份修订补丁(timeline delta)**,全模块共用公式:

> **有效正史 = 世界书 ⊕ 已应用的蝴蝶补丁**

- 世界书 = 原始正史(卡面设定资产,永不原地改写);
- 蝴蝶效应 = "对真理的修改记录"(X 从 A 改成 B,于何时、由哪次介入造成);
- 传记/谱系/正文 = 当前时间线的"呈现",由"世界书+补丁"计算而来;
- 墟境候选 = 未被采纳的分支草稿,永远最低权威。

矛盾在数学上消失:任何模块读到"世界书"时,读到的已经是修订后的有效正史。

## 二、已拍板的三个决策(2026-08-19)

1. **呈现**:只做 **diff 对比**——当前时间线只展示"修订后";原史只在蝴蝶面板做「修订前 → 修订后」对比,不做"正史/修订"双视图切换。
2. **触发**:**装配时即时生效**——在上下文装配层对世界书条目打补丁,零延迟、不重写任何已存记录。
3. **范围**:补丁**先只覆盖人物/组织的 生卒、存在、亲缘、关键事件**(可机械化匹配);"格局/制度描述"等语义级变更暂缓。

## 四、目标架构

```
[storage] CharacterFactLedger(身份账本·静态)   name → {性别/生卒/寿命/lineageKind/来源列表/权威度/冲突记录}
[storage] TimelineRevisionStore(修订账本·动态) revId → {runId/nodeId/atTime/target/delta{from,to}/status: applied|reverted|contested}

装配层统一入口: applyTimelineRevisions(worldbookSources, revisions)
  —— 三个 assembler 在 getWorldbookSources 之后调用
  —— 命中 生卒/存在/亲缘/关键事件 的条目 → 输出"修订后版本"进检索池
  —— 世界书原文不动;修订 append-only;status 可回滚
```

- **身份账本 vs 修订账本 = 一对互补**:前者管"谁是谁"(静态事实),后者管"什么时候改了什么"(动态变更);两者都只读注入、写时落账。
- 装配时打补丁是**唯一接入点**,三个生成模块零改动自动继承(它们读到的"世界书"已是有效正史)。

## 五、工作分解(按阶段,每阶段独立可验收)

### P0 · 交叉参考补边(小,可最先做)

- **P0-1 蝴蝶 → 谱系**:`genealogyContext` 增加 `getButterflySources()` 读取,经 `selectRelevantContextSources`(limit 4~6)入池;`prompts/genealogy.ts` 注明"蝴蝶归档作为 生卒/后代/后果 的高权威证据"。
- **P0-2 谱系年龄推导契约**:rules/09 + 谱系提示词加「年龄推导协议」——权威序(世界书锁定 > 传记明确记载 > 蝴蝶后果反推 > MVU 状态);每推一个生卒必须带 `inference + 依据 sourceRef`;推不出标"约/未详",禁止凭空精确。
- 验收:typecheck ✅ · tests ✅ · 打包 ✅;谱系生成能引用蝴蝶后果并给出带来源的出生年。

### P1 · 特殊人物智能化(中)

- **P1-1 `lineageKind` 输出**:谱系 schema 增加 `lineageKind`(原生 / 同世界穿越 / 跨世界穿越 / 夺舍 / 转生 / 收养 / 造物),校验器做归一化与一致性软检。
- **P1-2 年龄双轨契约**:穿越 = 抵达前(原生世界年龄)+ 抵达后(现世界年龄)分账;夺舍 = 灵魂 + 肉身双轨;构装体 = 启用纪年;谱系校验对 lineageKind 相关年龄做一致性软检。
- 验收:特殊人物谱系输出带 lineageKind 且年龄账本不穿帮。

### P2 · 时间线修订(大 · 终局问题)

- **P2-1 `TimelineRevisionStore`(storage)**:append-only,每聊天命名空间;字段见 §四;含 `list/apply/revert` API。
- **P2-2 装配打补丁**:`applyTimelineRevisions(worldbookSources, revisions)` 统一函数;匹配规则(人物/组织 sourceId、标题、别名 + 生卒/存在/亲缘/关键事件关键词);在三个 assembler 的 `getWorldbookSources` 之后接入。
- **P2-3 生效范围**:仅 人物/组织的 生卒、存在、亲缘、关键事件(已拍板);格局/制度暂缓。
- **P2-4 呈现**:蝴蝶面板 diff 对比(修订前 → 修订后);被修订的世界书条目加角标"⚠ 已被蝴蝶效应修订"。
- **P2-5 回滚**:`status: reverted`;append-only 留痕;再进墟境救回人物 → 后代自动"复活"。
- **P2-6 冲突仲裁**:权威序 世界书/MVU > 传记 > 蝴蝶归档 > 谱系推断 > 墟境分支史;修订与既有传记/谱系冲突时——"修订后呈现 + 档案留痕"(被推翻方标注为"被否定的历史分支",不静默删除)。
- 验收:构造"玩家杀谱系人物/改格局"用例 → 谱系/传记/墟境引用到修订后事实,蝴蝶面板 diff 可见,原史可回滚。

### P3 · CharacterFactLedger 与自动纠错(大 · 可选强化)

- **P3-1 身份账本**:storage + 生成前读入注入(只注入本批相关人物,按需不贪大)+ 校验后写回落账。
- **P3-2 冲突自动纠错**:生成结果与账本冲突时按权威序自动修正,修正说明写回账本留痕;UI 提示"已按更高权威修正"。
- 验收:跨模块重复生成同一人物时,事实收敛一致;冲突有留痕。

### P4 · 交付与回归

- 全量回归(传记 → 谱系 → 墟境 → 蝴蝶 全流程)、文档同步、打包。
- 风险与回滚:修订补丁为 append-only,任何一版可整体停用;世界书原文零改动。
