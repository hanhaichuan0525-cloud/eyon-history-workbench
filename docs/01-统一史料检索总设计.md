# 伊雍历史工作台 · 统一史料检索总设计

> 文档状态：**ACTIVE / FOUNDATIONAL**
> 合同基线：Retrieval v1.2 + Qualified Evidence v1 + Citation Contract v2 + 确定性检索纪律（internal.72 共证门；语义编译路线已撤销）+ P1-0 字段权力边界 + P2 局部依赖/评估边界
> 适用模块：寻根溯源、宗族谱系、墟境、蝴蝶效应
> 当前进度：[NEXT.md](../NEXT.md)
> 版本化事实与跨产物实施：[02-交叉检索、人物事实与Canon版本蓝图.md](./02-交叉检索、人物事实与Canon版本蓝图.md)

## 1. 目标

统一史料检索负责把当前角色绑定范围内所有开启、非空、未排除的资料建立为可发现知识目录，再围绕本次任务筛选实体、关系和精确证据段落。它解决四个长期问题：

1. 资料存在但没有进入模型上下文；
2. 人物、地点、组织、事件和亲缘被不同条目割裂；
3. 来源虽然入选，但相关内容位于长条目后部，实际未被模型看到；
4. 传记、谱系、墟境和蝴蝶各自重排、截断或补查，导致同一任务结论漂移。
5. 固定关键词、名称后缀和整来源实体集合把“候选线索”误当成“局部证据”，导致地理、人物、组织、事件和时代判断看似精确、实则语义失真。

统一管线是：

```text
宿主来源
  → EnabledWorldbookCorpus
  → SourceSnapshot
  → WorldKnowledgeCatalog（高召回候选目录）
  → TaskQueryScope / EventFrameSeed
  → CompactKnowledgeDirectory
  → CandidatePassagePool
  → 确定性检索纪律（共证门，internal.72）
  → EventFrame / CastManifest / EvidencePassage
  → CanonResolvedView（P1 起）
  → QualifiedEvidenceView
  → EvidenceBundle
  → 四模块提示词与校验器
```

本路线的语义编译层（SemanticEvidenceCompiler / SemanticEvidenceView / SemanticQueryPlan / EvidenceExpansionRequest）已经整体撤销（internal.71）：类型与旧诊断字段仅作历史数据兼容，活动入口无引用、构建产物不含编译器。替代它的是一组**纯确定性检索纪律**（internal.72 共证门）：

- **括号别名校验**（catalog.ts 与 index.ts 同款）：条目标签括号内的「类别/品质」结构标注（含斜杠如「物品/史诗」，或去空格 ≤2 字无分隔的单档位如「(史诗)」）不拆分进别名/实体/搜索词——防止「英雄史诗」经实体匹配污染装备品质条目；
- **强词独证 / 弱词共证**：≥3 字或索引实体名（实体资格，如「荷马史诗」「玲山」「翼民」）可独立开门；2 字非实体泛词（「史诗」「品质」）必须与强词/正文命中佐证，或 ≥2 个弱词互证，才能计分与开门；
- **匹配面统一**：`title-exact` / `indexed-term` / `matchedEntities` 全部收敛到过滤后的查询片段集合（停用词在所有路径生效，而不只是查词层）；
- **实体资格 = 索引实体集合**：真实世界书 343 条数据审计后 2 字实体从 81 个收敛到 10 个纯专名；「品质」「装备」等**字段实体保留为合理锚**（「史诗品质装备」需求场景照常召回装备规则）；
- 全程无向量、无 embedding、无外部语义服务；每个顶层任务只有一次本地确定性检索，无递归补检。

## 2. 非目标

- 不把全部开启世界书整本注入模型。
- 不为每个模块维护一套独立检索器。
- 首版不引入向量服务、embedding、外部向量库或远程摘要。它们只可作为未来可插拔召回加速层，不能成为事实裁决层；是否引入须以 P0-D 无向量真机漏召回证据另行立项。
- 不让模型自行决定互相矛盾的历史版本。
- 不把相关性等同于舞台资格、角色资格或当前事实。
- 不以强硬词表代替时间、地理和实体关系判断。

## 3. 来源与快照合同

### 3.1 EnabledWorldbookCorpus

只要世界书条目满足以下条件，就必须进入本地语料守恒层：

- 属于当前角色绑定范围；
- 宿主状态为开启；
- 正文非空；
- 未被用户或系统明确排除。

“本轮没有被酒馆关键词激活”不等于关闭。所有合格条目必须得到 `indexed | partial | opaque` 状态；本轮是否进入模型由后续任务筛选决定。

### 3.2 SourceSnapshot

每份来源拥有：

- `logicalId`：跨内容更新稳定的逻辑身份；
- `versionHash`：正文和有效检索元数据的确定性 SHA-256；
- `snapshotId`：`logicalId@sha256:versionHash`；
- `sourceType/title/content/metadata/sourceOrder`；
- 世界书绑定范围、策略类型、主次关键词、扫描深度、插入位置、概率、递归、黏性、冷却、延迟和 `extra`。

SourceSnapshot 不可原地改写。历史变化通过 Canon 事实有效性处理，不通过篡改来源正文处理。

### 3.3 来源类型

统一检索至少接纳：

- `worldbook`：不可变世界基线；
- `mvu`：当前角色和现场状态；
- `chat`：近期已确认上下文；
- `biography`：带版本的传记产物；
- `genealogy`：带版本的谱系产物；
- `butterfly`：玩家干涉记录及其有效投影；
- 已提交墟境产物：只能在具有明确提交状态、版本绑定和用途时参与；未选择候选不是正史。

来源类型不是全局权威总分。权威必须落实到事实、版本、时间窗和作用域。

## 4. 知识目录

### 4.1 WorldKnowledgeCatalog

目录覆盖以下实体，并以高召回为目标：

- 人物与别名；
- 地点及大陆、国家、地区、城市、建筑层级；
- 组织、势力、家族、教会与军队；
- 种族、神明、制度、技术和器物；
- 历史事件、时期、因果节点；
- 群体、集合和成员关系。

目录必须保留全文倒排，即使条目只能得到 `partial` 或 `opaque`，仍不得从语料守恒层消失。目录中的实体类型、别名和关系边是**候选线索**，不是 passage 级事实；固定后缀、词表、正则和同源共现不得单独产生硬资格结论。

### 4.2 关系图

关系候选从明确字段、结构化格式、可信陈述和可审计的语义解释建立。至少支持：

- 成员、归属、职责；
- 地点包含、活动地、统治范围；
- 亲缘、师友、敌对；
- 事件参与者、发生地、时间和因果；
- 人物与组织、地点、器物和历史事件的双向邻接。

正向和反向关系都可用于受限扩展。确定性解析能证明的结构关系可直接标为 `structural`；其余关系必须引用局部 passage 并标明认识状态。否定句、修辞比较、同名文本和“同一长条目其他位置出现过该实体”不得误建强关系；无法判定时保留为候选或 `unknown`。

### 4.3 CompactKnowledgeDirectory

紧凑知识目录是给模型阅读的“馆藏目录”，不是把整本世界书塞进 prompt。每个开启来源只提供：

- `sourceId/snapshotId/title/sourceType`；
- 结构标题、显式字段名、已知实体名与别名；
- 短代表片段或段落摘要，且能回指真实 source span；
- 本地宽召回命中的任务词、共现线索和候选关系；
- 覆盖状态、预算和可继续打开的 passage 范围。

目录必须让模型看到“还有哪些来源可读”，同时把正文预算留给真正相关的段落。`partial/opaque` 来源仍要列出，不得因为脚本读不懂格式就从馆藏目录消失。

### 4.4 确定性检索纪律（共证门，internal.72）

语义编译层撤销后的检索资格由**纯确定性纪律**统一（真实案例：补充方向「英雄史诗」曾把装备品质/技能规则条目召入正文，根因与修复如下）。

**根因三通道**（全部实证）：

1. `catalog.ts` / `index.ts` 的括号别名提取把「月桂源生匣(物品/史诗)」「锻造匠师 (史诗)」的**品质档位标注**拆成实体别名「史诗」→ `buildEventFrame` 的 `query.includes(别名)` 命中 → `catalog-direct` +520 开门；
2. `rankDirect` 的 `indexed-term` 用 `query.includes` 裸子串匹配 searchTerms，命中 strongSearchTerms 即 `strongPrimary` 开门；
3. `matchedEntities` 裸子串把「史诗」放进关系扩展。

「史诗」早在 `QUERY_FRAGMENT_STOPWORDS`——但停用词只作用于查词层，三处匹配层裸奔（纪律只在一半路径生效）。

**修复（机制级，无新增词表补丁）**：

1. **括号别名校验**：括号内含斜杠（类别/品质双字段「物品/史诗」）或去空格 ≤2 字无分隔（单档位「(史诗)」）→ 不拆为别名/实体/搜索词（catalog.ts 与 index.ts 同款）；
2. **强词独证 / 弱词共证**：
   - 强词 = ≥3 字（专名/词组，如「荷马史诗」）或索引实体名（任意长度，实体资格，如「玲山」「翼民」）→ 可独立开门；
   - 弱词 = 2 字非实体泛词（「史诗」「品质」「传说」）→ 不能独自成证：需强词/正文命中佐证，或 ≥2 个弱词互证（「史诗品质装备」三词同中）；弱词命中 strongSearchTerms 不再直接开门；
3. **匹配面统一**：`title-exact` / `indexed-term` 命中按强/弱分组计分；`matchedEntities` 收编到过滤后的查询片段集合；
4. **实体资格 = 索引实体集合**（标题/别名/标题行/关系提取的专名）：真实世界书 343 条审计后 2 字实体 81 → 10 个纯专名（伊本/尼尔/断流/泰珂/纳尔/绝望/苏克/金铎/长月/露娜）——「史诗/传说/神话/稀有」清零；「品质」「装备」等**字段实体保留为合理锚**，保证「史诗品质装备」需求场景照常召回装备规则条目。

**验证基线**：真实世界书「英雄史诗」从 2133 分污染降为 **0 入选**；「史诗品质装备」→ 技能装备道具生成规则照常入选；「荷马史诗」「探查荷马史诗」「翼民」（2 字专名）「玲山·哈姆斯沃思」全场景通过；新增 8 项共证门测试；配套 `scripts/worldbook-pollution-scan.mjs` 世界书污染面普查工具（每次世界书更新后运行）。

## 5. 任务查询与跨实体检索

### 5.1 TaskQueryScope

每次任务先拆分：

- 玩家明确人物、群体和对象；
- 年代、日期和时间窗；
- 地理范围和舞台；
- 事件与历史阶段；
- 主方向、补充兴趣和排除项；
- 模块策略；
- 当前聊天分支与 Canon revision。

玩家目标是主查询；当前聊天和 MVU 只能助推，不得凭环境上下文把无关当代资料带入明确历史任务。

### 5.2 扩展层级

```text
L0 直接锚：玩家明确点名的人物、地点、事件、组织、时间
L1 必要邻接：明确归属、成员、亲缘、事件参与者、地点层级
L2 条件邻接：只有能支持本轮因果、角色编排或背景判断时进入
L3 开放素材：预算允许且不与时间、地理、版本冲突的局部创作支撑
```

关系图不能无限展开。每个扩展必须记录关系路径、用途和停止理由；“有关”不等于“必须出场”。固定图边只提供初始路径；只有引用局部 passage、通过引用校验并符合预算的邻接才能进入候选集合。

### 5.3 EventFrame 与 CastManifest

EventFrame 描述本轮历史框架：时代、时间范围、地理舞台、目标事件、前史和后果。CastManifest 描述角色职责：

- `required`：玩家明确要求且当前时空允许；
- `group-required`：玩家要求群体，需要选择有证据的代表；
- `relevant`：适合作为承接者或见证者；
- `background`：只提供制度、信仰或社会背景；
- `excluded/notApplicable`：不应作为在场角色。

CastManifest 是编排建议，不得覆盖人物生卒和当前 Canon。

## 6. 证据合同

### 6.1 EvidenceClaim

证据声明至少记录：主体、谓词、客体、时间适用域、地理适用域、认识状态、冲突组、支持它的 snapshot 和 source span。`explicit / structural / user-asserted / reported / contested / inferred / generated / conflicted` 必须区分；“官方声称”属于被报道的说法，不自动等于客观真相。

### 6.2 EvidencePassage

模型读取的是精确 passage，而不是“入选来源的开头 N 字”。每个 passage 必须：

- 是 SourceSnapshot 正文的真实切片或可审计 fact capsule；
- 有稳定 `passageId/contentHash/start/end`；
- 保留必要相邻上下文；
- 合并重叠区间；
- 记录因什么实体、关系、时间或冲突进入；
- 在同一任务的计划、修复、扩写和校验中保持同源。

中心人物完整条目可通过 `TaskAnchorAttachment` 作为有哈希、有用途、有回执的补充通道，但不能绕开 EvidenceBundle 成为第二真相。

### 6.3 EvidenceBundle

四模块必须消费同一个 EvidenceBundle 合同，包括：

- 来源与 passage；
- 相关 facts；
- EventFrame 与 CastManifest；
- 时间和地理资格；
- 人物事实与在场视图；
- Canon branch/revision；
- Qualified Evidence；
- required/relevant anchors；
- 冲突、预算、截断和失败回执。

模块可以投影不同视图，不能重新选源、重新判版本或隐藏回退 legacy。

### 6.4 Citation Contract v2 / TaskCitationRegistry

`passageId / snapshotId / sourceId / factId / eventId` 是脚本、缓存和 Canon 层的内部稳定主键，不再要求生成模型逐字复制。每个 EvidenceBundle 必须确定性建立同一个任务级短句柄注册表：`P1...` 指向 passage，`F1...` 指向人物 CanonFact，`E1...` 指向世界书/历史事件，`S1...` 指向 source/snapshot；`SELF` 只表示本候选原创开放层事件。模型只看合同实际列出的短句柄并在 `*Refs` 字段中引用；validator 在脚本侧解析成内部主键后再执行存在性、重复事件和 Canon 校验。

短句柄是模型边界，不是新真相层：它不得改变检索排序、证据内容、事实状态、版本或 Canon 身份。合同必须显式列出 `allowedPassageRefs / allowedFactRefs / allowedEventRefs / allowedSourceRefs`；任一表为空时，对应输出必须为空，禁止用示例暗示不存在的 `F1/E1`。计划、修复和扩写必须复用同一注册表；阶段补检只能在表尾追加，旧句柄不得换号。禁止各模块私建编号，禁止接受截短 passageId、snapshotId、sourceId 或拼接变体作为兼容别名。旧缓存缺少注册表时，只可从原 EvidenceBundle 确定性只读重建。

机器引用回执与创作正文必须解耦。墟境的未知/错类型句柄必须在解析边界丢弃、留下 `citation-ref-dropped` 诊断并保留正文，不得写入 Canon 或触发整批历史内容重写；传记、谱系和蝴蝶在结构化规划/来源账本阶段可走既有局部 repair，但不得扩大内部 ID 猜测规则。四模块共享同一注册表、渲染器和解析器。

### 6.5 Canon 证据解释与部分顺序

世界书条目顺序、字段顺序、fact 数组顺序和 source span 顺序都只是资料排布，不是历史 chronology。统一事实层只建立有证据的 `CanonEventRelation`：明确日期、明确“此前/后来”、以及可确定的结构前提可以形成 `before/after/requires`；没有关系边的事件对保持未决。

四模块可以让模型综合人物、地点、组织、器物、关系和当前状态，对未决区间提出一个或多个自洽解释。解释必须引用 factId，区分既定事实、报道/争议、推断与原创桥梁，并保留关键假设和替代解释。validator 只拦截可确定的冲突，例如同一既定事件被当作多个独立事件换年份重复发生；它不替模型选择唯一文学答案。

## 7. Qualified Evidence 的职责

Qualified Evidence 在 passage 进入模块生成模型前标注：

- 时间：同时期、前史、后果、未知或冲突；
- 地理：舞台、范围内、外部参照或未知；
- 事件阶段：原因、进行、后果、遗迹、背景；
- 实体职责：演员、地点、组织、对象、背景；
- 版本资格：由 CanonResolvedView 提供的当前有效状态；
- `allowedNarrativeUses` 与 `forbiddenNarrativeUses`。

责任边界写死：

```text
CanonResolvedView 决定事实在当前 revision 是否有效
Qualified Evidence 决定有效 passage 在本轮能怎么用
模块 prompt 消费结论并进行创作
validator 只执行可确定的硬合同
```

P1 完成前，生成产物可暂标 `unresolved`；P1 完成后，Qualified Evidence 不得再自行猜测哪个版本是当前真相。

资格必须落在 passage 局部：SourceSnapshot 的全局实体集合不得投射到每个 passage。对于只有词面命中、没有局部证据的地点归属、人物身份或事件同一性，应标为 `inferred/unknown` 并作为创作约束或外部参照，不能硬判为舞台、演员或既定事件。同形词污染由共证门在检索资格层拦截（见 4.4），不依赖任何语义裁决。

## 8. 通用时空资格

统一时间资格输出 `exists | notYet | extinct | unresolved` 以及模块策略：

- `accommodate`：传记、墟境、蝴蝶；
- `strict`：谱系内部明确生卒和亲缘一致性。

叙事模块遇到普通时空错位时应把矛盾显式转成：

- 缺席/前史/遗产叙事；
- 有证据的异界或时间异常来源；
- 外部参照；
- `unknown`，而不是无依据判死。

谱系例外只对明确事实执行 strict。年龄换算、推断抵达年和未知寿命不能自动升级为确切生卒硬门。

人物不可逆与可逆状态的详细合同由主蓝图负责。

## 9. 创作自由分层

- `LOCKED`：身份、明确亲缘、生卒硬门、地理层级、当前版本结果、由日期或 CanonEventRelation 明确的事件顺序。
- `GUIDED`：动机、承接机制、可逆状态下的行动范围、未完全记载的过渡过程。
- `OPEN`：匿名人物、对白、气氛、战术、生活细节、微观地点和不改变正史的因果桥梁。

统一检索的目标是锁定事实边界，不是规定唯一剧情。没有 passage 支持时，模型不能创造大陆级制度、神明契约、国家法典或跨世纪确定后果；局部细节仍可自由创作。

## 10. 预算、性能与诊断

- 本地冷索引目标不高于 1 秒，热候选召回 p95 目标不高于 100 毫秒；真实宿主规模变化时重新采样。
- 无语义编译：每个顶层任务只执行一次本地确定性检索；候选扩写、段落生成、repair 与 validator 必须复用最终冻结视图，不再次选源。
- 引用/句柄输出先在唯一边界进行受控归一化与逐项保全，再进入严格内部 schema（Citation Contract v2）；无害的多余字段、近义枚举不得触发整批回退，真正缺少引用身份的坏子项必须单独丢弃并留给回执统计。
- 查询分词必须排除纯日期、纯标点、工作流缩写与同形泛词（停用词在全部匹配路径生效——查词层与匹配层同一条纪律）；这些值既不能打开来源，也不能进入 matchedAnchors 或内容资格。
- 检索结果按 `enabled snapshot set + branch/revision + TaskQueryScope + queryHash` 确定性缓存；相同键不得重复计算。
- CompactKnowledgeDirectory 和 CandidatePassagePool 都有字符与来源上限；超过预算时先保留玩家直接锚、结构命中、冲突材料和跨实体桥梁，再降级开放背景。
- 角色锚、玩家主目标和当前版本事实优先保留；可选背景先降级。
- `complete=false`、缺少强制 passage、版本无法仲裁等必须显式留痕，不能静默混入旧输入。
- RetrievalReceipt 必须能解释入选、拒绝、关系路径、语义解释、引用 passage、补检、预算、qualification 和当前 revision；公开诊断不保存完整世界书正文。
- Prompt 字符诊断只记录长度、阶段、尝试和资格块规模，不保存敏感正文。

旧选择器和 legacySourceIndex 只能在仍有明确对照用途时保留，不能进入正式模型输入。物理删除必须同时满足：

1. 零生产消费者；

## 15. 软硬边界契约（2026-08-27 固化 · Codex 六条反思 → 项目红线）

> 这是对「把正确率误解成增加规则、字段与否决条件」的纠偏。任何新增校验/字段/门槛上线前，必须对照本节：能证明它覆盖**一类问题**且不夺走模型的**合理推断空间**，否则不许进。

**一、责任分配（固定不变）**：
- 检索负责提供足够、相关、可追溯的材料；
- 模型负责跨条目理解、比较、提出解释与创作；
- 校验器只拦截**明确矛盾**与**结构性错误**；
- 模糊问题返回警告、备选解释或局部降级，不判死。

**二、硬锁清单（仅此五类，其余一律软判断）**：
1. 玩家明确填写的时代、地点、任务主题——不偷换；
2. 已知实体不可被偷换成另一个实体（改名/换人=违规；句面小异同允许）；
3. 明确生卒时间不能被无声违反（硬门只对不可逆事实；状态锚=受限在场）；
4. JSON、存档、引用句柄等机器协议必须合法（失效走丢弃+诊断，不毁正文）；
5. 同一个事件不能仅换年份/措辞冒充不同候选（P0-C 事件账本）。

**三、禁止回潮清单（曾犯、不准再犯）**：
- 把模糊叙事硬做成确定性判断（「看到X就判Y不可用/必须在那」）；
- 把「防止胡编」做成「禁止合理补全」（无专属证据≠不能存在；军医/工匠/无名组织是开放层）；
- 用关键词/后缀/共享短词负最终裁决（关键词只负责候选召回，共证门拦截词面资格）；
- 让模型维护机器主键与引用协议（句柄由脚本解析；模型不参与内部 ID 猜测）；
- 补丁叠加互相打架（新规则上线前检查与既有规则的关系，不允许「满足时代牺牲主题」式的内部冲突）；
- 把软判断升级成硬门（人员选择、组织动机、经历阶段、地点角色、异界遗物解释、局部人物创造——都留给模型）。

**四、整体理解合同（internal.76 减法尝试；现行边界由七修订）**：
- 玩家原话以完整 `sourceText` 进入规划与扩写，永远是任务语义主轴；任何结构化拆分只能帮助召回或帮助模型思考，不能替换、压缩或重写玩家原话；
- internal.76 曾完全移除 `taskInterpretation`、`taskFit`，真机证明会同时移除模型必要的认知台阶；现行方案允许七所述软脚手架存在，但禁止把它们当作事实、Canon 输入或正文否决条件；
- 传记不恢复四性质、派生玩家指令与模型自报 `qualityChecks` 等自证式硬校验；
- 骰表是创作素材，不能覆盖玩家主题；这一点由提示词优先级与最终正文真机验收判断，不再用语义字段判死；
- 仍保留可确定验证的硬门：请求身份、骰表阶段、明确时间顺序、人物生卒与身份、来源/事实句柄、同一事件 ID 不得多次发生。

**五、验收视角**：自动化通过 ≠ 理解正确。离线校验通过 ≠ 交付。真机「格式正确但历史变笨」是最高优先级故障信号，优先于任何单点报错。

**六、当代人物防错位引导（internal.76 覆盖包 · 真机回归汀瓦尔案例）**：
- 案例：MVU 当代人物汀瓦尔·贾维（审判官/帝国猎犬，复兴纪元时代）被英雄纪元 93 年候选以本名采用——非主角的 MVU/关系列表当代人物此前无任何防护（主角有 PROTAGONIST_ANCHOR，与世界书同名有双源适配，唯独普通当代人物是洞）；
- 根因定性：检索供料没错（汀瓦尔卡含「奥古斯提姆帝国/审判官/帝国猎犬」，与任务相关，该供料）；错在采用——76 移除理解回执后模型失去「先声明任务与选人再执行」的自我约束步骤，直接凭相关性命中即采用；
- 修法：prompt 选角段加**软引导**（非硬门、不校验）——「检索可能带回当前聊天的当代人物，历史候选不得以本名采用；角色契合时创作同职同构的古代原型，或仅在世界书明确记载同名历史人物时使用本名」；
- 二轮修正（贾维/帝国猎犬雏形真机回归）：模型曾把「古代原型」字面执行为「为当代人及其家族/称号制造历史前身」（贾维家祖先、帝国猎犬雏形）——修正措辞为「invent an original person of that era」并明示 **不得为当代人、其家族名或称号安排历史前身**；墟境同时补入**造名与反回声**规范（新人物须有时代/地域/种族风味的独立记忆点名字，禁止通名、禁止批发名字、禁止借用 MVU 人名/家族名/称号）与**墟境创作基准**（时代可信、人物独立鲜明、事件有因果与翻转、结尾有余韵；历史就是历史，当代就是当代）；
- 原则重申：采用环节用引导而非门（§15「模糊→引导不判死」）。

**七、认知脚手架回归（internal.76 三轮覆盖 · 跳跃病历）**：
- 真机观察：76 全删 taskInterpretation/taskFit 后生成「跳跃」（主题漂移、选角随手、候选松散）——删除的不是校验，是模型**先写主题→再定规模→再选人→候选认领**的思考台阶（self-scaffolding）；
- 落定形态：**75 的桩子 + 76 的自由心**——prompt 恢复输出 `taskInterpretation`（sourceText 逐字/primarySubject/eventAnchor/castDemand(mode·minimum·requiredKinds·selectionRule)/mustServe/materialRole）与候选级 `taskFit`（soft self-record），但脚本**只查** sourceText 防偷换、materialRole=support-only 与基本字段存在；不逐字、不查数量、不查三向一致——`TASK_ALIGNMENT_FAILED` 永不回潮；
- 附加脚手架并存：创作基准（时代可信/人物独立/因果翻转/余韵）、当代人物防错位引导（invent an original person of that era、禁止前身化）、造名与反回声；
- 原则：**字段是模型的思维脚手架，不是校验器的考卷**——校验只留五类硬锁。

**八、收尾三件 + 传记时间线（internal.77）**：

- 卡名/标题引导：Source and worldbook titles are script labels——条目标题/卡名/版本号不得写入正文或用作器物/招式/组织名；

**十、P1-0 · 结构化字段与自然语言协作边界（2026-08-28 冻结）**：

进入 P1 前，每个新增或既有字段必须归入且只能归入下列一种权力等级：

| 等级 | 所有者 | 典型内容 | 持久化 | 能否修改 Canon | 能否阻断正文 |
|---|---|---|---|---|---|
| `authoritative` 权威结构 | 脚本/确定性存储 | `branchId`、`revision`、`factKey`、来源 span、明确生卒、明确日期、delta 状态 | 是 | 可以，须经提交边界 | 仅可确定冲突可阻断 |
| `advisory` 思考脚手架 | 模型 | `taskInterpretation`、`taskFit`、候选 cast、材料用途、可能关系 | 默认否；只读诊断可留 | 不可以 | 不可以 |
| `narrative` 自然语言判断 | 模型 | 跨条目解释、关系合理性、历史空白补全、因果组织 | 作为产物正文保存 | 不可以自动修改 | 不可以 |
| `diagnostic` 诊断 | 脚本/模型边界 | 漏召回、歧义、坏句柄丢弃、候选冲突提示 | 可保存 | 不可以 | 不可以直接阻断正文 |

字段准入必须回答六问：谁产生、依据什么证据、是否持久化、能否修改 Canon、能否阻断正文、失败时如何局部降级。若一个字段的真伪必须先理解散文含义才能判断，它不得进入 `authoritative`，也不得成为硬门。没有跨任务重复病历与可确定判据的新字段，不得上线。

统一链路采用双通道，禁止互相越权：

```text
权威通道：来源 → CanonFact → branch/revision → delta → CanonResolvedView → 回滚
解释通道：玩家原话 + 当前有效事实 + 原始 passage + 软脚手架 → 模型解释与创作
```

解释通道的输出默认不反写 Canon。只有经显式提交、拥有稳定事实键/作用域/来源或可审计行动原稿、且能确定性回滚的变化，才能进入权威通道。P1 的 `resolveCanon` 第一版禁止调用模型；它只做状态投影，不做文学解释。模型参与的 `canon-reconcile` 仍属于 P3，且必须有界、保留 `uncertain`，不能静默裁决歧义。
