## 1. 问题（一句话）

蝴蝶干涉的实体永远活在 `entity:generated:` 一次性命名空间里，与史料检索的稳定实体 id 空间不互通 → `canonResolver` 作用域判定恒判 `outside` → 干涉从不进入后续生成的 `<CANON_CURRENT_VIEW>` → "干涉影响后续生成"在真机上从未生效（2026-09-03 三个候选无视 R7 实证）。

## 2. 目标与不做

**目标**：让"命中稳定实体"的蝴蝶干涉事实进入后续任务的 canon 当前视图（模型看得见），为 P2-B/C 场景 2 重验打通消费链；同时为未来 P2 深化（干涉 replace 人物 lifespan / 事实遮蔽）留好同空间接口。

**不做**（范围锁）：
- 不做模型输出 schema 变更（carrier 仍是模型文本，归并在脚本侧做）；
- 不做 resolveCanon 语义重写、不做跨聊天仲裁、不做自动 repair；
- 不引入语义层/向量（红线）；
- 不删 legacy、不加依赖；
- 旧 pending/旧记录（无映射表）行为完全不变 = 现行为（generated 兜底），零迁移成本。

## 3. 方案（档位 1 主推 + 档位 2 可选）

### 档位 1 · 结算侧实体归并（主推）

**a) 冻结时建立映射索引（可选字段，零破坏）**
`butterflyContext.freeze()` 现场持有完整检索 Bundle（castManifest 条目含稳定 `entityId`/canonicalName/aliases；另有 personCanonViews）。在 freeze 返回对象上新增可选字段：

```
linkingIndex?: Array<{
  entityId: string;            // catalog 稳定 id
  names: string[];             // canonicalName + aliases + identities（归一化去重）
}>
```

来源：castManifest.entries + personCanonViews（人物视图名/别名）；全量 ≤ 既有 cast 规模，有界（截断保护，如 ≤200 条）。
写入 `PendingSettlement.linkingIndex?`（可选字段；旧持久化 pending 缺省 → 归并跳过，行为=现状）。

**b) 提交时归并（纯确定性函数）**
`commitButterflyCanon` 内把 `stage.carrier` 映射到稳定实体后再拼 `subjectEntityId`/`factKey`：

```
linkCarrier(carrier, linkingIndex) -> { entityId } | null
规则（保守，宁缺勿错）：
1. normalize(carrier) 与某实体 names 中一项完全相等 → 命中
2. 否则子串包含匹配（≥2 字，personNameMatches 同款语义）：
   唯一命中 → 采用；多命中（复合描述/重名）→ 不猜 → null
3. 命中 → subjectEntityId = 稳定 entityId（factKey 同空间）
4. null → 维持现行为 entity:generated:… 兜底，并累计 linkingFallbacks
   （写进 receipt/diagnostic，供诊断与验收核对，不报错不阻断）
```

cascadeScope.entityIds 同步用归并后的稳定 id（同源计算，保证提交与投影一致）。
把归并结果摘要（命中数/兜底数/样例）附到 commit 的 receipt 或 action 记录（可选诊断字段），不改变既有 schema 必填。

**效果**：命中人物/组织稳定实体后，该干涉 fact 与 baseCanon 事实同 `subjectEntityId` 空间 → 后续任务 scope 含该实体时 `deltaMatchesQuery` 实体闸通过 → 事实进 `<CANON_CURRENT_VIEW>`（activeRevisionFacts）→ 模型在生成同窗口内容时看到"尤娜 321 年已被扼杀"这类当前状态。
- 示例（今日病历）：结算 carrier=「尤娜」（或其别名）命中 catalog 尤娜 → R7' 的 fact 落在尤娜稳定 id 上 → 之后生成 320–350 黄昏花室候选时视图携带该干涉事实 → 候选不得再写"尤娜活到 350"。

### 档位 2 · 名称维度兜底（可选，待确认是否纳入 v23）

对**未命中**稳定实体的 generated 干涉（模型造的新事物/复合描述），让同主题任务至少"看见"它：
- `delta.cascadeScope` 增可选字段 `subjectNames?: string[]`（载体的归一化名，commit 时填）；
- `canonResolver.deltaMatchesQuery` 增维度：查询侧实体名集合（personCanonViews/cast 的 canonicalName+aliases）与 `subjectNames` 做包含匹配，命中即 `inside`（实体闸之外的第二通道）；
- 事实进入视图后仍是 generated subject——**只告知、不遮蔽**（无 base span 可蔽），语义上诚实标注（epistemicStatus 已是 generated）。

取舍：档 2 让"干涉新事物也能被同主题生成感知"，但扩大 canonResolver 面（加测试矩阵）；若确认 v23 只解决"命中稳定实体的干涉"（档 1），档 2 可延后到下一个有真实病历的版本（YAGNI）。**默认建议：v23 只做档 1**，档 2 记录为蓝图候选。

## 5. 测试计划

1. **单测（纯函数）**：
   - carrier="尤娜" ↔ names 含「尤娜」「尤娜·xxx」→ 命中稳定 id（短名被长名包含）；
   - 完全相等命中；别名命中；
   - 复合描述（"首席工匠巴托洛缪与受损的高塔穹顶"）→ 多候选/无唯一 → 兜底 generated；
   - 重名两实体（同短名不同全名）→ 不猜 → 兜底；
   - 空 linkingIndex / 旧 pending 缺省 → 全部兜底（行为=现状，回归锁）。
2. **集成（canonResolver 消费链，今日 F-01 形状复刻）**：
   - 提交命中稳定人物尤娜的干涉（assert historical_change）→ 构造查询 scope `subjectEntityIds=[尤娜稳定 id]` → `resolveCanon` 的 `activeRevisionFacts` 含该干涉事实；
   - scope 不含尤娜（无关实体）→ outside 不投影（不污染）；
   - 地点/时间维度仍按既有规则生效（回归）。
3. **全量回归 + typecheck**：基线 518/518 只增不减；`pnpm build`。
4. **真机验收剧本（驾驶员执行，修复后）**：
   - 触发一轮命中尤娜的干涉并确认 revision 的 fact/action 落在稳定 id（导出 JSON 核对 factKey 前缀不再是 `entity:generated:`）；
   - 复刻今日场景 2：生成 320–350 黄昏花室/尤娜窗口候选 → **候选应反映"321 年尤娜已死"或至少不与 canon 冲突**（不再出现"活到 350 年"）；
   - 无关 revision（今日场景 1 同款）不误伤回归。

## 7. 风险与红线核对

- **不猜**：多候选/重名一律兜底 generated，绝不瞎映射（宁可漏不可错）；
- **不污染**：映射只发生在结算写入侧；不改检索、不改 prompt 契约、不改评估五态语义；未命中行为与今日完全一致；
- **兼容**：linkingIndex 可选字段，旧 pending/旧蝴蝶档案无感；bundled 产物 schema 只增可选；
- **有界**：linkingIndex ≤200 条；fallback 只计数留痕不报错；
- **验收诚实**：档 1 只承诺"命中稳定实体的干涉进入视图"；未命中（generated）干涉的可见性 = 现状，若未来出现真实病历再评估档 2，不提前造轮子。
