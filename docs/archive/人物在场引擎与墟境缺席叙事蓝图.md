## 1. 问题定义（玲山案例的根因链）

1. **自动时间范围不看人物年龄**：`resolveAutomaticRuinRange` 只用「纪元窗口 + 史料年份」，玲山 27 岁（→ 出生约 461 年）被自动落在 258–269 年——出生前两百年。
2. **寿命兼容判定认不出年龄格式**：`selectedCharacterFitsCandidates` 用正则只认「X纪元N年」格式生卒，「27岁」解析不出任何日期 → 判为「寿命相容」→ 玲山被放行进 sharedCast。
3. **cast 强制参与 + validator 强制出场**：`ensureCastParticipation` 把选中人物强制塞进节点，`validateManifestCast` / `validateSelectedCharacters` 要求 actor 必须出现在 cast 与节点，否则校验失败——模型想守缺席叙事都守不了，唯一能过校验的路就是硬编一个「少女玲山」。
4. **缺席叙事在墟境只实现成软提示**：传记有完整的 `BIOGRAPHY_TIME_ABSENCE_MODE`，墟境只有 `CHARACTER_TIME_ANCHORS` 里一句「未出生/已故时段禁止其在场」——prompt 软约束，模型可无视；`selectedCharacterUsage.mode='notApplicable'` 通道 schema 里本来就有，但被 cast 强制逻辑堵死。
5. **叙事锁定事实无结构化保护**：铃羽被选中去无尽地城、玲山独自离开梵尼亚、圣纹压制环是现状装备——这些「背景口述」里的既定事实只靠检索片段传达（可能被窗口切割/预算省略），`immutableFacts` 只是政策声明，没有实例清单。
6. **蝴蝶效应记忆依赖世界书镜像**：改写后的历史写入「专用全局世界书」，正文是否读到全靠 selective 关键词激活（造化）；多档开新卡时全局世界书残留大量镜像条目，玩家换卡不便；面板内容趣味性提示词（rules/15）也明显薄于传记/墟境。
7. **人物经历没有统一事实层**：年龄是单值字段，现有 catalog 可稳定换算；亲属、分别、赠书、现状装备等事实散落在背景口述/声部，当前四条 `OrderedLifeAnchors` 正则只能留下简短事件标签，缺少主体、关系、时间、来源区间、明确/推断状态与任务相关性。传记扩写的身份证还会再次截取条目前部，墟境所谓完整人物卡又只来自 MVU `stat_data.关系列表`，不是所有启用世界书人物条目；因此会出现「生年正确、人生被漏读或改写」。
8. **当前版本模型只会单点覆盖，不会重算交叉历史**：现有 §5 的 `delta + cascadeScope` 能表达一次改写，却没有分支修订号、事实依赖、产物分段有效性和重基线规则。后一次穿越若发生得更早或与旧波及范围交叉，可能使旧 delta 的前提、旧传记的部分段落、谱系的部分节点/边和旧墟境的部分因果失效；若仍把它们作为同权资料送入模型，模型只能在互相矛盾的版本间猜。

## 2. 目标（验收 = 驾驶员场景，写死）

**场景 A**：复兴纪元 · 未写时间 · 指令「玲山·哈姆斯沃思与妹妹铃羽在梵尼亚所遭遇的困苦之事」
- A1：命中 27 岁年龄内的时间段——候选时间带下限 = 出生年（461），不再出现出生前时段；
- A2：智能判断事件年龄——引擎算好每个节点的人物年龄（事件年 − 出生年）；既定事件链有序（离开梵尼亚(独自) → 流浪 → 到帝国 → 梅薇娜赠书 → 建立琉璃塔 → 社长，当前 27 岁）；硬互斥可判定：「27 岁在梵尼亚流亡」⇄「27 岁已是帝国社长/头版女王」、「带着妹妹流浪」⇄「独自离开、妹妹被选中去无尽地城」。

**场景 B**：复兴纪元 214 年 · 同一指令
- B1：命中缺席叙事——玲山与铃羽**不出场**；
- B2：出现与她们未来命运息息相关的内容——哈姆斯沃思氏族的历法血脉、梵尼亚圣纹传统、辉煌女神幻梦体系的早期形态、无尽地城守卫制度的起源、日后将有一对翼族姐妹的命运伏笔（点明但不现身）。

**场景 C**（真相版本管理，P1 达成后验收）：玩家通过穿越使世界书人物 A 提前死亡 → 蝴蝶效应记录 → 之后生成传记显式标注「A 于 X 年死亡（蝴蝶效应改写）」；生成墟境（命中正史本该活着的年份、却是蝴蝶/传记中已死亡的年份）→ 进遗产叙事，且能读到玩家修改历史后蝴蝶效应带来的变化；「世界书原值 vs 干涉现值」的矛盾归类为**版本差异**而非错误。

**场景 D**（蝴蝶效应面板记忆，§6/§7 达成后验收）：输入「遣返」→ 后台独立 API 生成（链路已有）→ 结算后当前 revision 最近 1~2 个仍有效变化常驻必见，更早且仍有效的日志在正文提及相关关键词时触发；失效片段永不进入普通正文；工作台可查看全部版本档案；世界书镜像彻底删除（新档零残留）；面板内容本身有传记级趣味性（历史演变有动作/翻转/代价、证据可核查、文风与伊雍一致）。

**场景 E**（交叉干涉与自动纠错，§5 达成后验收）：正史记载 A 于 470 年死亡；第一次穿越 D1 令 A 于 458 年提前死亡，传记 B 的 465 年段因此写成遗产叙事；第二次穿越 D2 在 450 年阻止 D1 的起因，使 A 存活至 466 年。系统必须自动得到当前分支最新真相：D1 在重叠事实上的效果被 D2 局部取代，B 只把依赖「458 年已死」的段落标为 `partially-stale`，无关段落仍有效；依赖该死亡的谱系边/旧蝴蝶后果进入重基线或失效，不相关地点/人物的旧 delta 继续生效。普通生成默认只读当前有效版本；比较历史版本时才同时提供正史、D1、D2，并逐条标注版本与失效原因。删除 D2 对应楼层后，D1 与 B 的有效性必须自动恢复。

**传记共通**：同一引擎支持传记 span 建议（出生年后）、时期分区年龄（已有）、缺席溯源（已有）、硬互斥（新增）、人物正史事实贯穿（P0-A）与同 revision 生成事实连续性（P4）。

## 3. 架构决策：人物在场 = 引擎共通能力，模块声明策略

沿用《时空错位容纳蓝图》的档位架构，把「人物在场」完整纳入共通管线；**真相版本管理同样并入检索引擎**（见 §5，合并论证）：

```
统一人物与当前真相管线（检索引擎内，模块无关）
  ├─ WorldKnowledgeCatalog
  │    ├─ CharacterCanonFacts（人物身份/关系/人生事件/当前状态）
  │    └─ CanonFact + InterventionDelta + ArtifactDependency
  ├─ CanonResolvedView（当前分支、当前修订、目标时空下唯一有效事实视图）
  ├─ PersonCanonView（只筛本任务相关人物事实，逐条绑定来源 passage/span）
  ├─ 输出：PresenceAssessment
  │     { state: alive|absent(原因)
  │     , eventAge: 事件年龄（事件年 − 出生/抵达年）
  │     , feasibleWindow: 可行时间带 [出生年下限, 当前剧情时间]
  │     , hardConflict: 硬互斥命中（同岁状态/地点矛盾）
  │     , absenceNarrative: 按缺席原因生成的叙事方针 }
  ├─ 策略档位：
  │    accommodate —— 叙事模块：墟境 / 传记 / 蝴蝶（缺席 → 缺席叙事，validator 不拦）
  │    strict      —— 结构模块：谱系（生卒硬门，只用显式生卒，现状保留）
  └─ 引擎不猜合理性数字：只算年龄、推导可行窗、判在场、仲裁可证明的版本覆盖、注入有来源事实；语义级级联若不能证明则进入有界重基线或 unknown
```

**引擎与模块的分界（与驾驶员确认一致）**：
- 引擎（retrieve 阶段）只产出数据与判定，**不抛硬错误**（active 检索失败 = 任务终止，违反「不因错位截断」红线）；
- 硬互斥命中 → 模块 validator 在 repair 路径上按档位处理（墟境/传记：带指引 repair；不终止任务）；
- 缺席 → 模块注入缺席叙事契约（不是硬错误）。
- 模块不得自己从正史、旧传记、谱系和蝴蝶记录中二次挑版本；它们只能消费引擎给出的 `CanonResolvedView/PersonCanonView`。旧版本可保存、可查看、可比较，但不得无标签混入普通生成。

## 4. 引擎层设计（src/retrieval/temporal.ts 扩展）

### 4.1 可行时间带推导 `deriveFeasibleWindow(persons, currentTime)`
- 输入：选中人物 lifespans（`resolveLifespanFromBaseline` 换算，含 ageBased；P1 起输入为**版本化 lifespan**，见 §5.3）+ 当前剧情时间（`currentWorld.time` 解析）；
- 输出：`{ earliestBorn, latestAllowed }`——下界 = 全体人物出生/抵达年中的最晚者；上界 = 当前剧情时间（或最早亡故年，若存在且更早）；`arrivalBased` 的推断抵达年作下界但标注「推断」；
- 无人物年龄信息 → 返回 null（调用方回退现状，不误伤）；
- 消费方：墟境自动范围（替代纪元窗口下限）、传记 span 建议。

### 4.2 区间在场判定下沉 `assessPresenceInWindow(entity, windowStart, windowEnd)`
- 把传记的 `assessStagePerson` 下沉为引擎公用（四态 + 年龄区间 + 缺席方针），墟境/传记/谱系共用同一份代码；
- 点判定 `assessPersonTimeline` 维持现状；
- P1 起 lifespan 输入经版本化（delta 覆盖）后进入本函数。

### 4.3 人物正史事实层 `CharacterCanonFacts`（`OrderedLifeAnchors` 的正式扩展）

`CharacterCanonFacts` **不是独立数据库或第二套检索器**。它是 `WorldKnowledgeCatalog.KnowledgeEntity(person)` 的结构化事实面，负责把人物卡中零散的身份、关系、经历与当前状态变成可筛选、可追溯、可版本化的事实；`OrderedLifeAnchors` 降为其中 `lifeEvents` 的兼容投影。四模块不得各自重做人物解析。

```ts
interface CharacterCanonFacts {
  entityId: string;                    // 稳定实体 ID，不随改名变化
  names: CanonFact[];                  // 权威名、别名、旧名
  identities: CanonFact[];             // 身份/职业/种族/组织归属
  relations: CanonFact[];              // 亲缘、师承、同伴、所属等
  lifeEvents: CanonFact[];             // 离开/抵达/被选中/获赠/任职等
  currentState: CanonFact[];            // 当前地点、身份、装备、状态
  lifespan?: VersionedLifespan;
}

interface CanonFact {
  factId: string;
  subjectId: string;
  predicate: string;
  object: string | { entityId?: string; value: string };
  temporal?: { start?: TimePoint; end?: TimePoint };
  spatial?: string[];
  epistemic: 'explicit' | 'structural' | 'user-asserted' | 'inferred' | 'generated';
  confidence: 'high' | 'medium' | 'low';
  sourceRefs: string[];
  sourceSpans: Array<{ snapshotId: string; startOffset: number; endOffset: number }>;
  revisionIntroduced: number;
  revisionRetired?: number;
}
```

**来源与提取顺序（保守、可解释）**：
1. MVU/世界书的明确字段与结构化关系；
2. 标题标签、身份/装备段和明确关系句；
3. 背景口述中有完整主谓宾的事件句；
4. 玩家本次明确断言（标 `user-asserted`，只在当前任务/分支生效）；
5. 多句组合才能得出的关系只生成 `inferred` 候选，不能静默晋升为硬事实；拿不准 = 不建事实。

**玲山条目的判定示例**：
- `年龄=27岁`、`当前身份=琉璃塔信报社社长`、`当前佩戴圣纹压制环`：明确事实；
- `铃羽被辉煌女神幻梦选中去无尽地城做守卫`、`玲山离开梵尼亚`、`玲山后来抵达帝国`、`梅薇娜赠予《白日尽头》`：明确事件事实；
- 仅凭该条目可确认铃羽是重要相关人物，但「铃羽=妹妹」「玲山独自离开」「两事构成姐妹分别」若没有另一条关系资料或玩家明确指令，只能是 `inferred`；玩家指令明确写「妹妹铃羽」后，本次任务可形成 `user-asserted` 硬锚，不能反向污染全局正史。

**当前状态锚**：现有「我离开X的时候」「官方说…被…选中」「后来我到X」之外，补足 `currentLocation/currentIdentity/currentEquipment`。圣纹压制环必须表达为「当前佩戴的压制装备」，不能被模型改写成出生即扣、身体器官或熔铸后的其他物件。

**模型可见合同**：
- 每个事实必须绑定真实 `EvidencePassage` 或精确 `sourceSpan`；`PersonCanonView` 只选本次任务相关事实和必要邻接事实，不把整个人物目录无差别注入；
- 完整人物卡只可作为带 `sourceId/contentHash/charCount/purpose` 的 `TaskAnchorAttachment` 补充通道，并进入 `sourceHash` 与回执；不能在 EvidenceBundle 外形成不可追踪的第二真相入口；
- 墟境 `EVIDENCE_LEDGER.immutableFacts`、传记 plan/各段扩写、谱系 `<EXISTING_RELATIVES>` 必须消费同一组 `factId`，不得只传人名或一句顺序提示；
- 任务明确要求的事实进入 `requiredFactIds`；只与背景相关的事实进入 `relevantFactIds`。改名、改身份、颠倒明确事件或违背 required fact 走 repair；未使用无关/低置信事实不算失败。

**旧 `OrderedLifeAnchors` 兼容**：由 `lifeEvents` 按时间/相对顺序确定性投影，保留旧 prompt 与测试；不再用四条人物专用正则承担完整人物理解。P0-A 起接入统一人物事实，P4 再与旧传记、谱系、墟境的通过校验生成事实同构合并，并进入 §5 的版本仲裁。

### 4.4 硬互斥校验（只拦可判定，引擎不猜合理性）
- 判定规则：候选节点人物年龄 = 当前年龄 **且** 节点地点/状态与当前状态锚互斥（梵尼亚 ⇄ 帝国；流亡 ⇄ 社长；随行 ⇄ 无尽地城守卫）→ 命中；
- 互斥对**只来自世界书明确事实**（当前所在地/身份/关系），不是词表、不是系统猜测；
- 命中后模块按档位处理：墟境/传记 → repair（错误信息给三条路：后移时间带 / 更换参与人物 / 缺席叙事），谱系 → 现状硬门；
- 相对时序合理性（「几年才合理」）**不判**——交给有序链注入 + 模型排布；
- **硬互斥只针对不可逆事实**（未出生/已故/同岁状态矛盾）；可逆状态（囚禁/失踪/失能/放逐/异界/除名）**不构成时间硬门**（见 4.6）——状态是「受限在场」而非退场。

### 4.5 缺席判定
- 候选时段与全体选中人物 lifespans 无交集 → `absent` 结论 + 按原因的叙事方针（见 4.6）；
- 同一函数服务传记（单对象缺席）与墟境（全体缺席 / 部分缺席）。

### 4.6 缺席原因模式扩展（硬时间门 + 受限在场）

**关键语义（驾驶员拍板 2026-08-21）**：状态 ≠ 退场。只有**不可逆**状态才是时间硬门（validator 拦截）；**可逆**状态是「受限在场」——人物可以出场，只是受位置/认知/能力约束，validator 一律不拦（减少误杀，状态成为叙事素材而非禁令——如 466 年失踪 → 466 年后可回归出场，正文点明「曾失踪」即可；墟境可围绕「探明失踪动向」展开）。

| 模式 | 约束类型 | 结构化来源 | 叙事方针（引擎生成，模块直接消费） |
|---|---|---|---|
| `not-born` 未出生 | **硬时间门** | 出生/抵达年（已有） | 前史叙事：其到来前的世界；禁止作为在世者出场 |
| `deceased` 已故 | **硬时间门** | 死亡年（已有；P1 起版本化） | 遗产叙事：余波/影响/纪念；禁止作为在世者出场 |
| `missing` 失踪 | 受限在场（软） | 失踪时间锚 | 线索叙事：以线索/传闻/最后踪迹/「探明失踪」过程出场；回归需点明「曾失踪」 |
| `incapacitated` 失能 | 受限在场（软） | 失能时间锚（重伤/瘫痪/沉睡/封印） | 静物叙事：躯壳在场、行动缺席——被照护/被利用/名号被借用；可出场但不得写其自主行动 |
| `imprisoned` 囚禁 | 受限在场（软） | 囚禁时间锚 | 囚笼叙事：只在其囚禁地点出场（狱中视角合法）；外界围绕囚禁运转/营救伏笔；不得写其在大牢外自由行动 |
| `exiled` 放逐 | 受限在场（软） | 放逐时间锚 | 别处叙事：被逐期间的传闻可写；回归需点明 |
| `otherworld` 异界 | 受限在场（软） | 位面外/封印时间锚 | 异界叙事：召唤/回归需点明来源 |
| `erased` 除名 | 受限在场（软） | 除名/更名时间锚 | 匿名叙事：可匿名出场，名册之外 |
| `unknown` 未知 | 不约束 | 提取不到 | 不猜 |

- **硬时间门（not-born/deceased）**：走 `notApplicable` 通道（§8.3）+ manifest 锚按模式降级（未出生 → 前史线索；已故 → 遗产线索）；
- **受限在场（其余模式）**：不强制 notApplicable——人物可出场但按「状态在场方针」约束（位置/认知/能力），prompt 注入、validator 不拦；
- **不构成时间硬门**：候选时段落在「失踪/囚禁/失能时间锚」之后 ≠ 禁止出场（与已故严格区分）——释放/回归后的正常出场合法，正文交代状态即可。

### 4.7 状态提取原则（灵活、智能，不机械）
- 状态词提取**不靠死板词表**：对「失踪多年 / 被囚于X / 沉睡至今 / 遭放逐 / 名册除名」这类**时段级明示**句式提取为状态锚；对修辞性表述（「他仿佛消失了」「如同死去」）**智能判断为修辞，不提取**；
- 判定依据：时段量词（多年/至今/X年起）+ 主被动结构 + 上下文一致性（世界书其他段落/传记/谱系是否佐证）——多项佐证才确认；拿不准一律 `unknown`（宁可放行，不可误判硬拦）；
- 每条状态锚带 `sourceLabel` 与置信标注；`unknown` 不注入、不约束。

## 5. 真相版本管理（干涉后历史的参考与归类，合并进检索引擎）

### 5.1 真相不是四层文本优先级，而是一个可回放分支

```text
CanonBranch（当前聊天）
  ├─ revision 0：BaseCanon（世界书不可变基线）
  ├─ revision 1..N：已提交 InterventionDelta（玩家干涉）
  ├─ CanonResolvedView(revision=N, queryScope)
  └─ MaterializedArtifacts（传记/谱系/墟境：某 revision 的可追溯视图，不自动成为更高真相）
```

- 世界书是不可变**基线**，不是永远优先的“当前真相”；被有效 delta 覆盖后仍保存原值供回放。
- 已提交的玩家干涉是当前分支的最高改写权威，但只在自己的事实键、时间窗、地点窗与依赖范围内生效；不相关 delta 并存，不能“最新一条全局覆盖全部历史”。
- 传记/谱系/墟境是带版本的**物化视图**，不是因为模型写过就自动晋升为正史。只有其中带来源、通过校验且被驾驶员/合同确立的结构化事实锚，才能作为 `generated` 低权事实参与同版本连续性；它们不能覆盖世界书明确事实或玩家干涉。
- chat/MVU 是当前现场状态与任务输入，可证明“现在怎样”，不能无依据倒推出过去怎样。

每个分支必须同时记录两条时间轴：
- `commitOrder/revision`：玩家实际进行穿越改写的先后；**后提交的明确改写**在相同事实键与重叠作用域上优先；
- `effectiveTime`：改写在世界历史中的生效时间；级联重算按历史时间从早到晚传播。后提交但发生得更早的改写，必须触发其后历史的重基线，不能只覆盖一个数值。

### 5.2 `CanonFact`、`InterventionAction` 与 `InterventionDelta`（P0，前置）

`InterventionAction` 保存玩家实际完成的穿越行动，是元历史审计事实，不因后续重算而静默删除；`InterventionDelta` 保存该行动对当前历史分支产生的可版本化效果：

```ts
interface InterventionDelta {
  deltaId: string;
  branchId: string;
  revision: number;
  parentRevision: number;
  actionRef: string;                    // 玩家行动/进入与遣返锚，不可静默改写
  effectiveFrom: TimePoint;
  operations: Array<{
    op: 'assert' | 'retract' | 'replace';
    factKey: string;                    // stable subjectId + predicate + scoped object
    originalFactIds: string[];
    current: CanonFact;
  }>;
  preconditionFactIds: string[];        // 该干涉成立时假定仍为真的事实
  dependsOnDeltaIds: string[];
  cascadeScope: { entityIds: string[]; time?: TimeInterval; locations: string[] };
  preserves: string[];                  // 明确不被本次改写波及的关键事实
  supersedesDeltaIds: string[];
  status: 'active' | 'partially-active' | 'superseded' | 'orphaned' | 'reverted';
  verified: boolean;
  createdAt: number;
}
```

- **产生**：蝴蝶结算必须基于当时的 `CanonResolvedView` 输出行动、前提、直接操作、影响范围与保留项；只给一段自然语言面板不再足以承担真相改写。
- **撤销**：删楼回退撤销对应 revision，再从最近有效父 revision 增量重算；恢复先前被覆盖的 delta 与产物段落有效性。
- **作用域**：chat-scoped；换聊天恢复各自分支，不共享未授权历史。
- **稳定引用**：人物改名、组织改制、地点易名不能改变 `entityId/factId` 的身份；版本关系不能只靠显示名称匹配。

### 5.3 当前真相仲裁 `resolveCanon(branch, revision, queryScope)`（唯一入口）

普通检索、人物在场和四模块 prompt 之前必须先生成唯一 `CanonResolvedView`：

1. 读取 BaseCanon 与当前分支未撤销 delta；
2. 按 `effectiveTime` 建历史因果顺序，按 `revision` 处理玩家后续改写权；
3. 事实键和作用域不重叠 → 组合生效；
4. 同一事实键且时空重叠 → 后提交的已验证 operation 局部覆盖早期值，保留原值与覆盖链；
5. 新 delta 破坏旧 delta 的 `preconditionFactIds` → 旧 delta 不可继续假装有效，进入 §5.4 重基线；
6. 生成 `verdicts`：每个候选事实只有 `active | superseded | composed | orphaned | uncertain` 之一；普通生成只消费 `active/composed`。

版本化 lifespan、组织存续、亲缘、身份、事件结果均从这份视图读取。`assessPresenceInWindow` 不再自己扫描世界书/蝴蝶记录；例如 A 的死亡由 470 改为 458 后，465 年自然得到 `deceased`。`EvidenceBundle.canon` 携带当前 branch/revision、有效干涉、verdict 与来源链，prompt 渲染 `<CANON_CURRENT_VIEW>`；旧 `<CANON_INTERVENTIONS>` 名称可作为兼容别名，但不得把已失效 delta 与当前值并列成两份命令。

### 5.4 交叉干涉重基线（自动处理的核心）

新 delta 提交后只重算受影响的依赖子图，不全库重写：

1. 用 `factKey + entityIds + time + location` 找出直接重叠事实；
2. 沿 `dependsOnFactIds/dependsOnDeltaIds` 找出后继 delta 与产物片段；
3. 不重叠者保持 active；完全覆盖者 superseded；只覆盖一部分 operations 者 partially-active；
4. 旧 delta 的前提仍成立 → 自动在新基线上复用；前提被破坏但稳定实体/行动目标仍存在 → 进入 `rebase-required`；目标已不存在且无法稳定映射 → `orphaned`；
5. 重基线必须保存原始 `InterventionAction`，只能重算其历史效果，不能偷偷改写玩家当时做过什么；若行动在新历史中变得不可能，保留为「旧分支发生过、当前分支无有效落点」的悖论档案，不把虚构替代行动写成玩家行为。

确定性规则能完成的覆盖、撤销、生卒/存续窗口重算不调用模型。只有 `rebase-required` 涉及开放叙事级因果时，允许在**蝴蝶 commit/回滚事务内**调用一次有界 `canon-reconcile`：输入当前视图、不可改的玩家行动、失效前提和允许影响窗；输出 `CorrectionProposal`，经 schema、来源、时空与不变量校验后才提交。普通检索与四模块生成不增加额外模型调用。

### 5.5 世界书事实遮蔽 + 产物分段有效性（旧文本不删除，失效部分不再供料）

世界书 `SourceSnapshot` 永远保存原文，但当前检索不能把“含一条旧史的整段原文”无差别送给模型，也不能因一条事实失效而丢掉同段其他设定。目录须先生成事实级视图：

```ts
interface CanonPassageView {
  snapshotId: string;
  passageId: string;
  branchId: string;
  canonRevision: number;
  activeFactIds: string[];
  inactiveFactIds: string[];
  activeSourceSpans: Array<{ startOffset: number; endOffset: number }>;
  mode: 'raw-current' | 'span-projected' | 'fact-capsule' | 'history-read-only';
}
```

- 段内所有事实仍有效 → `raw-current`，可原样进入 EvidenceBundle；
- 段内新旧事实混合且 sourceSpan 可安全切分 → `span-projected`，只投影有效句段并保留原始 offset；
- 原文高度缠绕、无法安全切句 → 不让模型自行从矛盾原文挑版本，改给脚本生成的 `fact-capsule`（当前有效事实 + 来源引用 + 被遮蔽事实 ID）；
- 用户明确比较旧历史时才给 `history-read-only` 原文，并醒目标注 branch/revision/inactive；
- 这只是对不可变世界书的**读取投影**，不回写、不删条目、不修改角色卡。回滚 revision 后，原 source span 可按 verdict 自动重新显现。

传记、谱系、墟境、蝴蝶记录提交时必须记录：

```ts
interface ArtifactCanonBinding {
  artifactId: string;
  branchId: string;
  canonRevision: number;
  segments: Array<{
    segmentId: string;                 // 传记 stage / 谱系 node或edge / 墟境 node或史稿 / 蝴蝶 operation
    factRefs: string[];
    inferredFromFactRefs: string[];
    time?: TimeInterval;
    entityIds: string[];
    locations: string[];
    status: 'current' | 'partially-stale' | 'superseded' | 'branch-incompatible' | 'unverified';
    invalidatedBy?: string[];
  }>;
}
```

- 新 delta 只使真正依赖被改事实的段落/节点/边失效，不因共享一个人物名或地点名就整篇作废；
- 旧产物正文保持不可变，供审计、版本比较和回滚恢复；工作台显示当前/部分过时/已取代及原因，不在后台静默改写旧文章；
- 普通交叉检索默认排除 stale/superseded 片段，只保留仍有效片段；用户明确要求比较旧史线时才注入旧文本，并加不可混淆的版本标签；
- 删除导致 delta 回滚时重新计算绑定，原本因该 delta 失效的片段可自动恢复 `current`。

### 5.6 传记、谱系与墟境的事实地位

- **传记**：从结构化字段与通过校验的正文提取 `generated` 事实锚，记录其依赖；同 revision 内用于连续性和避免重复，不覆盖明确正史/delta。新传记只接收当前有效旧锚；`parallelView` 是同事实的不同视角，`sourceConflict` 必须有来源才可提出纠错候选。
- **谱系**：node/edge 分开绑定事实。人物提前死亡只在能证明其与子女出生/受孕/收养时间矛盾时使相关边 stale；时间未知时标 `unverified/affected`，不得自动删除后代或编造替代父母。谱系 strict 只校验当前 resolved view 内部一致性。
- **墟境**：候选、节点、史稿分别记录时地人物事实；进入特异点后形成的历史不反向改写已归档原候选，而是由蝴蝶 delta 建新 revision。
- **蝴蝶**：面板是可读摘要，`InterventionAction + InterventionDelta.operations` 才是机器真相。旧面板若部分失效，工作台标记对应 operations 状态；不能仅凭面板文字继续覆盖当前历史。

### 5.7 冲突分类与唯一仲裁结果

每个冲突组必须先分类，不能把所有矛盾都丢给模型：

| 类型 | 含义 | 自动处理 |
|---|---|---|
| `version-superseded` | 后续 revision 明确覆盖旧值 | 旧值退出当前视图，保留版本链 |
| `scope-disjoint` | 名称相同但时间/地点/事实键不重叠 | 两者并存 |
| `composed` | 多个 delta 改不同属性，可同时成立 | 合并为当前值 |
| `dependency-orphaned` | 旧 delta/产物依赖的前提被撤回 | 重基线或标 orphaned/stale |
| `same-revision-contradiction` | 当前 revision 内两个同权事实互斥 | 确定性来源仲裁；仍不明则 repair/unknown |
| `identity-alias` | 改名/别名被误当两个人 | 用稳定 entityId 合并显示名，不合并身份不同的同名人 |
| `uncertain-cascade` | 波及可能存在但缺少可证明依赖 | 不自动改史；标 affected/unknown，生成时安全回避或显式保留不确定性 |

所谓“自动纠错完美”的可验收定义不是让模型永远猜中开放世界的全部后果，而是：**任何进入普通生成的事实都有唯一当前 verdict；任何无法证明的矛盾都不会被静默混用、伪装成已解决或污染未来任务。**

### 5.8 自动纠错事务（resolve → invalidate → rebase → verify → publish）

1. **Resolve**：建立新 revision 的候选当前视图；
2. **Invalidate**：按精确 fact dependency 优先、实体/时空影响窗次之，标记受影响 delta 与产物片段；
3. **Rebase**：确定性覆盖先做；必要时产生一次模型 `CorrectionProposal`，但模型没有直接写真相的权限；
4. **Verify**：校验稳定实体、玩家行动不可改、时间顺序、亲缘/生卒、作用域、sourceRefs 与 preserves；失败提案隔离，不发布；
5. **Publish**：原子提交 `canonRevision + verdicts + artifact statuses`，任一步失败都回滚到父 revision；
6. **Observe**：生成 `CanonResolutionReceipt`，记录输入 revision、应用/跳过/取代/孤立的 delta、受影响片段、纠错方式、未决项和耗时。

纠错不得无限循环：每次 revision 最多一次模型重基线 + 一次结构 repair；仍无法通过时发布不含争议事实的安全视图，把冲突标 `uncertain`，任务继续采用不依赖该事实的叙事方案。不得把失败模型提案写入历史。

### 5.9 模型可见防污染合同

- 普通任务只注入 `<CANON_CURRENT_VIEW branch="..." revision="N">`：当前有效事实、命中的改写、必要原值摘要、人物事实与明确不确定项；
- 被 superseded/stale 的旧事实默认不进入 `EvidenceBundle.passages`。混合新旧事实的世界书段落必须先经过 `CanonPassageView`；不得为保留有效半段而把失效半段原样暴露。若为了说明版本差异必须出现旧原文，只能进入 `<CANON_HISTORY_READ_ONLY>`，并标 `inactive`，禁止作为当前事实使用；
- `PersonCanonView`、在场判定、CastManifest、sourceIndex、传记二次证据和 validator 必须基于同一个 revision，禁止某层读 D2、另一层仍读 D1；
- 缓存键增加 `branchId + canonRevision`；revision 改变只失效相关实体/时间/地点索引，不全量重建世界书 catalog；
- 模型输出引用的 `factId/sourceRefs` 必须存在于当前视图。使用 inactive fact、混用不同 revision 或篡改玩家行动 → repair；只是没有使用非必要背景事实 → warning/正常。

### 5.10 解释性与用户控制

工作台诊断至少能回答：
- 当前历史分支与 revision 是多少；
- 某事实为什么是当前值，原正史和历次 delta 分别是什么；
- 哪个旧传记段、谱系节点/边、墟境节点或旧蝴蝶 operation 已失效，失效范围和触发 delta 是什么；
- 自动纠错是确定性完成、模型重基线完成，还是仍为 uncertain；
- 删除某次干涉将恢复哪些旧事实与产物片段。

用户可查看版本链、对比和手动重新生成受影响产物，但普通流程不要求用户逐条裁决。任何“手动强制采用某版本”都必须形成新的显式 revision，不能改数据库中的旧记录。

### 5.11 合并论证（为什么并入检索引擎，不独立）
1. **数据同一**：delta 改写的人物生卒、关系、事件与组织存续就是 catalog 的 `CanonFact`；独立系统会产生双 catalog 与同步漂移；
2. **计算位置同一**：在场、冲突、证据、角色编排和 prompt 装配都必须读取同一个 resolved revision；模块自行仲裁必然再次混版；
3. **产物依赖也是检索维度**：检索不仅问“哪段相关”，还要问“这段在当前 revision 是否仍有效”；版本判定必须发生在 EvidencePassage 进入模型之前；
4. **责任边界**：蝴蝶模块产生行动与 delta 候选；存储层保存不可变版本与依赖；检索引擎仲裁、失效、重基线并输出视图；模块只消费，不得另建覆盖规则。

### 5.12 实施分级（先收口，再扩建）
- **P0-A 人物事实收口**：`CharacterCanonFacts/PersonCanonView`、来源 span、任务相关 fact 筛选；修正生卒与普通事件日期混淆；完整人物卡改为可哈希 `TaskAnchorAttachment`；玲山经历真机门。
- **P0-B 版本骨架**：`CanonBranch/canonRevision/CanonFact/InterventionAction/InterventionDelta` 存储、删楼回滚、`CanonResolutionReceipt`；尚不做模型重基线。
- **P1 当前视图**：`resolveCanon`、版本化 lifespan/关系/事件、`<CANON_CURRENT_VIEW>`、四模块同 revision 消费；场景 C。
- **P2 依赖与局部失效**：四类产物 `ArtifactCanonBinding`、segment status、当前检索排除失效片段、工作台诊断与回滚恢复。
- **P3 交叉重基线**：delta preconditions/dependsOn、partially-active/orphaned、一次有界 `canon-reconcile` 与隔离校验；场景 E。
- **P4 演绎连续性**：同 revision 传记事实锚共享、谱系局部版本化、`parallelView/sourceConflict` 与影响窗增量缓存。

每一级独立通过自动化、typecheck 与真实酒馆门后再进入下一级；不得以“自动纠错很重要”为由一次性重写 Retrieval 主干。

### 6.1 目标与约束
- 目标：让「当前分支仍有效的改变后历史」作为可阅读内容直接进入正文模型——当前 revision 的近期有效变化必见，更早但仍有效的变化按相关性触发，不依赖世界书激活；玩家在工作台可查看全部版本档案；
- 约束：
  1. 面板仍是 `<butterfly_panel>` 六行可读摘要，`serializeButterflyPanel` 与既有记录内容**一律不做后台改写**；正文注入前必须先经 `CanonResolvedView` 过滤，不能把旧面板整段当机器真相；
  2. 不改玩家看到的既有面板原稿与渲染格式；新增的只是版本元数据、当前有效摘要投影与注入过滤；
  3. 世界书镜像彻底删除（新档零残留，玩别的卡不受干扰）；
  4. 工作台档案读取从世界书镜像改为本地 IndexedDB；
  5. `superseded/orphaned/reverted` 的 operation 及只依赖它们的面板片段不得进入普通正文；`partially-active` 面板只序列化仍有效 operation 的当前摘要，原面板保留在版本档案中。

### 6.2 持久化与查看本地化
- IndexedDB `ButterflyRecord` 保存不可变的**行动原稿与面板原稿**；它是审计来源，不等于当前机器真相。当前真相由记录绑定的 `InterventionAction/InterventionDelta` 经 `resolveCanon` 计算；
- 工作台档案列表（rules/07 蝴蝶效应档案读取）改为读本地记录：展示 `panel` 文本 + 元数据（runId / 遣返楼层 / 三套锚点 / 关键词 / branchId / canonRevision / operation status / invalidatedBy）；
- **删除世界书镜像链路**：`archive.mirrorButterflyRecord`、镜像条目筛选（`extra.source === 'eyon_butterfly_anchor'`）、`resolveArchiveWorldbookName`、镜像可见性切换（聊天隔离逻辑）——全部移除；
- 检索引擎 butterfly 候选源改为本地记录，但必须先按 `branchId + CanonResolvedView.verdicts` 投影为当前有效片段；不得直接把 `ButterflyRecord[]` 当正文候选池。

### 6.3 注入层设计（正文必见通道）
- 通道：ST `setExtensionPrompt`（in_chat、system、贴近最近对话的 depth）——与传记协作指令 / 进入特异点注入合流同一架构，先例已验；
- 内容：`<CANON_MEMORY branch="..." revision="N">` 私密简报——按 6.4 从当前有效 operation 生成的可读摘要；框定语：「以下是当前分支仍有效的改写历史，正文自然体现；禁止复述标签/格式，禁止恢复被标为 inactive 的旧史」；
- 刷新时机：① 蝴蝶结算 commit 后；② 聊天切换（清除/重建）；③ 删楼回退（同步撤销）；④ **正文生成前**（触发式匹配基于最近 6~8 楼正文 + 玩家当前输入，生成前刷新最准——复用既有生成前置钩子）；
- 注入空串 = 清除（幂等，切到无蝴蝶效应的聊天自动清空）。

### 6.4 分层注入
| 层 | 策略 |
|---|---|
| 当前 revision 最近 1~2 个 `active/composed/partially-active` 变化 | **常驻**——刚改完且仍有效的历史必然相关；部分有效时只注入仍有效片段 |
| 更早且仍有效的变化 | **触发式**——先过版本过滤，再由关键词匹配（§6.5）决定 |
| `superseded/orphaned/reverted` 或 stale 片段 | 普通正文永不注入，只留在工作台版本档案；显式历史对比才进入只读区 |
| 有效但未命中 | 不注入，只留在工作台档案 |

### 6.6 关键词智能化（触发匹配的核心）
#### 6.5.1 硬/软关键词分层
- **硬关键词**（脚本确定性提取，高权重）：仅从当前有效 `InterventionDelta.operations/cascadeScope` 提取——`subject`、`target` 人物/地点、制度/事件稳定实体；已失效 operation 的专名不得继续触发旧历史；
- **软关键词**（模型 `historicalKeywords`，低权重）：事件性内容概括（圣纹祭典/无尽地城守卫制）——保留但只作加分项，不单独触发。
#### 6.5.2 泛词过滤 + 特异性评分
- 停用泛词表（帝国/城市/历史/灾祸/命运/影响/变化…，复用检索侧 `QUERY_FRAGMENT_STOPWORDS` 同款经验）；
- **特异性 = 词在当前 chat 全部面板中的稀有度**（词频反比）：只出现在一条面板的词特异高；多条共有的词（如梵尼亚）降权但保留（地名本来就可能多条相关）；
- 只保留专名形态（人名/地名/制度名/事件名），排除抽象名词与形容词。
#### 6.5.3 别名与形态扩展（可匹配性）
- 全名 + 简称（玲山·哈姆斯沃思 → 玲山）；
- **独占身份称呼**（只有这条面板涉及的「头版女王」才做别名；泛身份「社长」不做）；
- 机构全名 + 简称（琉璃塔信报社 → 琉璃塔）。
#### 6.5.4 触发打分
- 得分 = Σ(命中权重)：**硬关键词命中 ≥1 即触发**；软关键词需叠加（≥2 个或 1 个特异词）才触发——避免「帝国」单泛词误触发；
- 匹配源：最近 6~8 楼正文 + 玩家当前输入；
- 常驻层（当前有效序列最近 1~2 条）不受打分影响，但仍必须通过版本有效性过滤。
#### 6.5.5 质量保障（两层）
- **提示词规则升级**（rules/15 关键词节）：必须是能区分本条目的专名（人物全名/地名/制度名/事件名），禁止泛词（帝国/命运/变化等），同义别名可并列；
- **脚本过滤兜底**：泛词表 + 特异性评分在脚本侧再滤一遍；模型关键词降为软词参与打分。
#### 6.5.6 验收夹具
- 面板「A 于 458 年死亡」+ 正文提「A 的旧部」→ 命中注入；
- 面板「梵尼亚圣纹祭典」+ 正文只提「帝国政局」→ 不触发（无特异词命中）；
- 两条面板都含「梵尼亚」→ 正文只提梵尼亚时两条低权命中（都相关）；正文提「圣纹祭典」→ 只高权命中祭典那条。
- D2 使 D1 的「A 于 458 年死亡」operation 失效后，即使正文提「A 的旧部」，D1 也不得进入普通 `<CANON_MEMORY>`；回滚 D2 后同一夹具自动恢复触发。

### 6.7 边界（不做）
- 不照搬柏宝书状态机（物品/NPC/计划/场景/变量注入）；
- 不做向量/embedding/语义理解（字面匹配 + 别名扩展 + 结构化兜底；红线：不引新依赖）；
- 不改面板内容与渲染格式；
- 关键词是注入层数据，脚本修正不影响玩家看到的面板。

7. **v1.4 事件链年份参考（兼容路径）**：事件链锚若带既定年份（来自当前 revision 仍有效的既有史稿/世界书明确记载），传记 span 建议直接引用该年份——跨模块时间对齐（真机案例：剥离圣纹在既有史稿为 477 年，传记另写 468 年即失配；墟境史稿被删时无参考，模型在链约束内自由排布，属正常）。锚无年份时不猜、自由排布（引擎不猜合理性数字）；正式路径由 P0-A 的 `CharacterCanonFacts` 与 P4 的同版连续性取代。
8. **归档绑定**：按时期/事件段落保存 `ArtifactCanonBinding`。后续历史改写只屏蔽依赖失效事实的段落；旧传记原文保留用于比较与回滚恢复。

## 10. 谱系接入（基础准入已实施，其余适配按清单推进）

> 谱系保持 strict 档位：生卒硬门只用显式生卒（ageBased 不参与）；strict 校验的是**谱系内部一致性**（生卒/亲属关系），不是与世界书文本一致。
> 清单内所有核对均为 **warning 级**（存在性核对，缺失只提示不 repair、不硬拦）——谱系任务同样不截断（红线 §14）。

### 10.1 证据约束下尽量贴近 maxPerGeneration
- `maxPerGeneration` 仍是每代软目标和硬上限；脚本先建立 `GenealogyEvidenceRoster`，只从存在与亲缘均有证据的候选中填充；
- 合格人物足够时按直系、旁系、关系距离尽量达到上限；不足时如实少生成，并在 `referenceSummary.brief` 说明史料实际确认人数；禁止创造人物或亲缘凑数。

### 10.2 父系母系证据平衡
- 父方与母方均有合格证据时，生成应兼顾两侧；只有一侧有证据时只输出该侧，不得为了视觉平衡补造另一侧。

### 10.3 既有亲属名单注入 `<EXISTING_RELATIVES>`
- 正式实现使用 `GenealogyEvidenceRoster`：从当前 revision 的 `PersonCanonView.relations` 生成既有人物、别名、允许关系方向/类型和 sourceRefs；玩家本轮明确输入可作为 task-scoped `user-asserted` 事实：**保留原名与身份，不得改名、不得替换**；
- 案例：铃羽不得改名；
- **v1.4 身份摘要注入**：注入既有亲属时**连同其既定身份与命运摘要**（如铃羽=被选中去无尽地城守卫的翼族少女），模型不得改换其设定——只保名字不保身份时，模型会改写整个角色（真机案例：铃羽被改名「希羽」且被改成「体弱受宠公主」，无尽地城命运整条消失）。

### 10.4 命名守卫 warning
- 当前正式路径已升级为确定性准入：名册外人物、`generated` 节点、名册外关系边或无关系 sourceRef 均拒绝；
- “合格人物未全部用满”仍是软目标，不因人数不足硬拦，避免资料稀少人物频繁失败。

### 10.5 谱系 personTimeline 权威生卒注入
- 谱系模块接入当前 `CanonResolvedView` 投影的 personTimeline（引擎按 baselineWorldTime 换算的生卒）注入 prompt，作为该 revision 的权威来源；
- strict 档位保持：只用显式生卒，ageBased 不参与硬门。

### 10.6 人物 TaskAnchorAttachment 接入 GenealogyContextBundle
- 中心人物相关启用世界书人物条目/MVU 人物卡以带哈希的 `TaskAnchorAttachment` 接入 `GenealogyContextBundle`（EJS 保留，独立预算）；结构化 `PersonCanonView` 承担事实约束，附件承担语气与长背景参考，两者都进入回执且固定同一 revision。

### 10.7 lifeAnchors 接入谱系
- `CharacterCanonFacts.lifeEvents/relations` 渲染进谱系 prompt（既定事件链与亲缘事实约束事件排布）；旧 `OrderedLifeAnchors` 只是兼容投影，提取不到不注入。

### 10.8 谱系诊断输出
- 谱系生成诊断（每代人数 vs maxPerGeneration、`reducedGenerationReasons` 存在性、命名守卫命中、生卒换算来源）输出到工作台诊断区（仿时间锚诊断）。

### 10.9 identity fidelity（CANONICAL_CHARACTER_IDENTITY_CHANGED 误判修复）

- 引擎不猜合理性数字（「几年合理」由模型在有序链约束内排布）；
- 不在 retrieve 阶段抛硬错误（任务不截断红线不变）；
- 不剥离 EJS 模板（人设在模板中，用户明确 2 不必做）；
- 不引入新依赖 / 向量库 / embedding；不删 legacy；不 Git 提交（除非单独授权）；不打包（实施完成后再走打包门）；
- 不为玲山、铃羽或任一专名写角色特判/硬编码关系；人物事实必须来自通用结构化抽取、明确来源或本轮用户断言；
- 不允许无 `sourceSpan/sourceRefs` 的模型猜测晋升为 explicit 正史；生成产物默认是带版本的物化视图，不因“已经写过”自动覆盖世界书或玩家干涉；
- 硬互斥只限世界书明确事实推导出的对，不引入词表式判断；状态词提取不机械（修辞不提取，拿不准 = unknown）；
- **状态锚不构成时间硬门**：囚禁/失踪/失能/放逐/异界/除名是「受限在场」（软方针，validator 不拦）——只有未出生/已故是不可逆时间硬门；
- **不独立建「真相版本」系统**（版本是统一 catalog/retrieval 的事实有效性维度，见 §5.11）；
- 不把“最后写入/最后生成”简化为全局最新真相；必须同时考虑 revision、effectiveTime、事实键、时空作用域与依赖；
- 不在后台重写或删除旧传记/谱系/墟境/蝴蝶原稿；以 segment/node/edge/operation 状态控制当前供料，并支持回滚恢复；
- 不让不同阶段或不同模块混读不同 revision；不能一边用 D2 的人物生卒、一边用 D1 的旧面板或谱系边；
- 引擎不穷举或伪造开放世界的全部干涉级联；可证明者确定性重算，叙事级歧义只允许有界提案，无法证明者标 uncertain 并从普通当前事实中隔离；
- 谱系 strict 不扩展到叙事模块（分界固定：叙事容纳、结构严格）；
- **不照搬柏宝书状态机**（蝴蝶记忆只注入面板内容，无物品/NPC/计划/场景/变量状态注入）；
- **不改蝴蝶效应面板内容与渲染格式**（只改注入方式与提示词）；
- **关键词不依赖模型单方**（结构化硬关键词兜底 + 脚本过滤，模型词只作软词）；
- **谱系事实准入与内容质量分级**：人物存在、亲缘方向/类型及 sourceRefs 是结构硬门；人数是否达到软目标、人物侧写是否足够丰富不作为硬失败，避免谱系任务因审美判断截断；
- **谱系 strict 校验谱系内部一致性，不校验与世界书文本一致**（identity fidelity 按 §10.9 方向处理，不因史料身份与谱系文本措辞差异误判）。

### 15.3 七条针对性审阅建议（实施时不得遗漏）
1. **先建稳定身份，再谈智能推理**：人物、地点、机构、事件、关系、事实键必须有稳定 ID；改名/别名不可制造“第二个人”，同名也不可粗暴合并。
2. **把“事实”和“文章”分开**：正文好看不等于可作为机器真相。面板/传记/史稿保留原文，检索消费的是带来源、版本和有效状态的事实投影。
3. **局部失效优先于整篇报废**：依赖追到 segment/node/edge/operation；否则一次小改史会让整套传记和谱系失效，重生成成本与叙事损失都不可接受。
4. **双时间轴不可省略**：revision 回答“玩家后来改了什么”，effectiveTime 回答“世界中何时开始改变”；只看其中一条都会把 D2 覆盖 D1 算错。
5. **不确定性必须是一等状态**：自动纠错的最高标准是绝不静默混版。不能证明的级联宁可隔离为 `uncertain`，也不能由模型编出一个看似完整的新正史并永久污染后续。
6. **解释性就是纠错系统的一部分**：每次自动修正都要能回答使用了哪些事实、覆盖了什么、保留了什么、哪些产物局部失效、回滚会恢复什么；没有回执的“智能纠错”不可验收。
7. **世界书也要事实级失效，不能整段二选一**：SourceSnapshot 保持不可变，但模型只读 `CanonPassageView`。同段混有新旧事实时保留有效 span、遮蔽失效 span；无法安全切分时给当前事实胶囊，不把矛盾原文丢给模型“自由理解”。

> 冻结判断：方向正确，但不能从现有“base + 单条 delta + 面板记忆”直接跳到模型自由消解矛盾。首要顺序固定为 **人物事实收口 → 版本骨架 → 唯一当前视图 → 局部依赖失效 → 交叉重基线 → 跨产物连续性**。每级均有自动夹具和真实酒馆门，前级未过不得宣称“自动纠错完成”。
