# 一、适用模块

本契约只管理四个按需调用的生成模块:

- `genealogy`: 宗族谱系。
- `ruin`: 墟境生成。
- `biography`: 寻根溯源。
- `butterfly`: 蝴蝶效应结算。

四个模块可以使用同一个API端口和模型，也可以分别选择不同来源。

# 二、设置结构

```json
{
  "defaultRoute": "tavern",
  "modules": {
    "genealogy": "inherit",
    "ruin": "inherit",
    "biography": "inherit",
    "butterfly": "inherit"
  },
  "external": {
    "baseUrl": "",
    "apiKey": "",
    "model": ""
  }
}
```

允许值:

- `defaultRoute`: `tavern | external`
- 模块路由: `inherit | tavern | external`

`inherit` 表示使用 `defaultRoute`。

# 三、酒馆插头路由

使用 `tavern` 时:

1. 在模块实际调用的瞬间读取酒馆插头当前可用的端口、鉴权和模型。
2. 不复制、覆盖或持久化酒馆插头配置。
3. 不修改正文模型预设、采样参数或聊天历史。
4. 每个生成请求仍为无历史的独立请求。
5. 只发送当前模块规则和当前请求资料。

# 四、独立API路由

使用 `external` 时:

1. 读取设置页中的 `baseUrl`、`apiKey` 和 `model`。
2. API密钥只保存在脚本私有设置中。
3. API密钥不得进入世界书、正文、MVU、本地资料导出或调试日志。
4. 每个请求必须是无历史的独立调用。

# 五、按需规则

脚本调用模块时只装配该模块所需规则:

- `genealogy` 只读取宗族谱系规则与共享世界观上下文。
- `ruin` 只读取墟境生成规则、骰表结果与共享世界观上下文。
- `biography` 只读取寻根溯源规则与共享世界观上下文。
- `butterfly` 只读取蝴蝶效应生成规则、冻结锚点、骰点结果与相关史料。

未被调用的规则不得进入请求，不消耗上下文Token。

# 六、隔离

每个请求必须拥有独立:

- `requestId`
- `taskType`
- 输出Schema
- 缓存键
- 超时与取消控制器

禁止复用生成模型的聊天历史。禁止把一个模块的原始输出自动附加到另一个模块请求；只有经过脚本筛选的结构化引用可以跨模块使用。

# 七、失败处理

- 当前路由不可用时，显示明确错误。
- 不得在玩家不知情的情况下从酒馆路由自动切换到独立API，或反向切换。
- 不得因API失败而写入MVU、切换墟境状态或向正文发送残缺内容。
- 玩家修改设置后，只影响下一次调用，不中断已经开始的请求。

# 八、界面

API来源只在“设置 > API调用”中配置。

宗族谱系、墟境生成、传记书库和蝴蝶效应档案页面不得重复出现端口、密钥、模型或候选接口选择控件。

# 九、蝴蝶效应路由边界

`butterfly`请求可以与遣返正文生成并行，但不得阻塞现有时间控制模块完成遣返。

- API调用前必须已经产生不可变冻结快照。
- API返回后只能进入校验与归档队列。
- API失败不得切换墟境状态、恢复活动字段或回滚世界时地。
- 重试必须使用原路由、原模型、原冻结快照、原骰点与原 `runId`。
