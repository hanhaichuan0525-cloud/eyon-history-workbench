# F04 · 蝴蝶效应趣味性回归（β1 / 内部版本 0.12.0）

- 触发：驾驶员反馈「蝴蝶效应文本太晦涩、不直观、不好玩；禁令与条条框框太多，矫枉过正」，并给出两类期望样本：
  1. 旧版体验——回到过去与精灵生子、穿越回来后那孩子成了圣人并取代一位神明；
  2. 荒诞因果——几年前朝下水道撒了泡尿，几年后地下长出一个以「祈祷天降甘霖」为宗旨的聚落。
- 方针原文（最高优先级）：**「只需要充分阅读世界书，把掷骰子的不同档位写明白范围，然后越有趣，越有蝴蝶扇动翅膀掀起风暴的快感越好。告诉模型：惊喜、趣味性——这点最重要。」**
- 范围纪律：**只改蝴蝶效应链路**。`rules/` 下 16 个文件中仅 `15_蝴蝶效应生成规则-API.txt` 被改动，其余（含骰点判定表 08、检索 03、校验 05、其它三个生成模块 09/11/13）零改动。代码侧 `butterflyProseContract.ts` 仅被 `prompts/butterfly.ts` 引用，`prompts/butterfly.ts` 仅被蝴蝶 rules 装配、遣返正文协作壳与蝴蝶测试引用，**影响半径不外溢**。

## 1. 诊断：为什么会变得无聊

对改动前的 `rules/15` 做机械盘点：

| 指标 | 改动前 | 改动后 |
| --- | --- | --- |
| 约束类表达（不得/禁止/不能/不要/必须/至少/只能/不可） | ≈97 处 | ≈62 处，且集中在 §四 锚点、§十七 Schema、§二十一 脚本契约 |
| 八档定义里的**上限禁令** | 每档 1 条（「不得扩成整个聚落」「不得升级成集体制度」「不得空泛扩大为整个世界」…） | **0 条** |
| 「代价 / 阻力 / 副作用」 | 硬性要求 | 可选 |
| 「误读」 | 媒介清单里的一句话 | 一等叙事手段 + 一等因果媒介 + 自检必答项 |
| 示踪样文 | 调粮函（制度先例链，公文腔） | 撒尿→祈雨教团（正例）+ 公文版（失败样文） |
| §十六 自检 | 15 条工程自省 | 6 条，含「世界把它误读成了什么」「有没有惊喜」 |

三个具体病灶：

1. **档位被写成了天花板。** 模型读「不得扩成整个聚落」时学到的是「别想有趣的事」，于是把戏剧性让位给安全性。
2. **上限禁令与因果链要求打架。** 规则一边要求「微小行动通过关键媒介扩散为巨大影响」，一边逐档封顶；模型于是选择最保守的交集——一份正确、精确、没人想读第二遍的账册流程。
3. **正史腔调 + 公文示踪样文。** 把「像史料」放在可读性之前，等于给模型一份模仿样本：抽象名词链、制度流程、无人无物无证物。

## 2. 三条原则（写进 §零 最高指令，优先级高于其余全部条目）

1. **惊喜与趣味第一。** 玩家会真的读完这段文字；「像史料」排在可读性之后。
2. **因果不必相称，越不成比例越好。** 一泡尿可以催生一个祈雨的地下聚落；一声呵斥可以让一整个世纪的仓库规矩围绕「神在看着」运转。
3. **唯一不能牺牲的是「回看合理」。** 读者笑过之后要承认——**换我也会这么信**。

配套口径：宁可荒诞、讽刺、黑色幽默、传奇，也不要写一份安全而正确的账册流程；庄严与滑稽的反差是鼓励项（教义越郑重、起因越滑稽，效果越好）。

## 3. 四条硬限（唯一保留的禁令）

1. 三套冻结锚点不可改写（§四）。
2. 不虚构玩家没做过的行动（§六、§十二）。
3. 不与已启用世界书 / 已归档 Canon 的**显式**事实冲突；冲突时写成争议版本或地方传说（§五、§十六）。
4. 输出必须是单个合法 JSON（§十七）。

除这四条外，创作不再受「不得……」约束；§十八~§二十一 已明确标注为**脚本契约**，对模型只有一句要求：输出单个合法 JSON，不附加解释。

## 4. 档位 = 落地规模（不限制起因）

骰点只回答一个问题：**结果最后长到多大**。它不限制起因的大小，也不要求因果关系成比例。

| 档位 | 落地规模（要**达到**的高度） |
| --- | --- |
| 个人 | 一个人的一辈子被改写——他信了什么、丢了什么、临死前还念着谁 |
| 双人 | 两个人之间多了一条永远解不开的线——血债、契约、说不出口的恨 |
| 小队 | 一个小圈子有了自己的规矩、暗号或信仰，并因此与外人区分开来 |
| 聚落 | 一个地方的人开始共同信什么、怕什么、做什么（教团、节庆、禁忌、圣物） |
| 城市 | 一座城的信仰、权力或生计被替换（圣所取代旧祠、行会改写规矩） |
| 省份级地区 | 多城共享的一套东西成立（教团网络、律法、语言、历法），并由一个具体的人或物串起来 |
| 国家 | 国法、王统、军制、货币或国教级别的改写，并造出「人们会为之赴死的东西」 |
| 跨国 | **必须掀起风暴**——信仰/语言/律法/王统级别的替代，至少两方因同一载体长期互相作用 |

规则同时写明：**档位是要达到的高度，不是天花板**；写不到这个规模算失败；而达成它的原因越小、越偶然、越不成比例，越有趣。

## 5. 误读引擎（趣味与「回看合理」的共同来源）

- 定义：某个具体的人或群体，把玩家的行为**理解成了别的东西**，并据此行动。
- 地位：一等叙事手段（§八 明写「误读本身就是一等媒介」）+ 因果账本必答项（§6.1 第 4 步）+ 自检第 2 题（「谁先信的、为什么信」）。
- 边界：读歪可以，但**读歪之后的行为必须自洽**。
- 允许：封圣、成神化、教团取代旧神信仰等**社会性**结果；禁止的是**本体论造神**——改写世界神系本身、让神真身降临。

### 正例 / 反例（同时写进 rules §零、§十三 与 prompts STYLE 段）

> **正例**：玩家几年前在旧城下水道撒了泡尿，被守夜人当成甘霖之兆抄进了祷文。旱年里有人靠这段祷文聚起信众；几十年后下水道被扩建成地下圣所，一群以「祈雨」为宗旨的教团握住了全城的清渠权。现世玩家走回旧城，渠口刻着一行没人认得的祷文，而清渠人正挨家挨户收「雨捐」。

> **反例**：玩家干涉后，相关记录被保存下来，制度因此发生变化，数十年后该地区形成了新的管理规范，并对当地社会产生了深远影响。——每个字都正确，没有一个人、没有一个动作、没有一处证物。

## 6. 子嗣与人物口径（回应「回到过去和精灵生了孩子」这类体验）

- 禁止：**为既有史料人物凭空添加亲缘**（那是篡改别人的人物）。
- 放开：**玩家自己那次行动直接造成的后果不受此限**——玩家的后代、门徒、造物、留下的东西，几百年后成为圣人、暴君、教派始祖或一段神话，正是这类事件最迷人的形态。

## 9. 交付与版本口径

- 对外版本名 **β1**，内部数字版本 **0.12.0**。自动更新加载器硬校验 `^\d+\.\d+\.\d+$`（`manifest.version`），写「β1」会让它直接拒绝远端清单，因此 β1 只能是展示名。
- 投递路径：推送 `main` → purge jsDelivr 分支缓存 → 驾驶员刷新酒馆，现有**内联 CDN 加载器**会读取新 manifest、校验 SHA-256 后加载新 dist，设置不丢。
- 可回滚点：`release/杂项/回滚点-β1旧加载器（驾驶员现用版）.json`（驾驶员当前正在用的加载器整份留档）+ git 标签 `stable-0.11.9`。
