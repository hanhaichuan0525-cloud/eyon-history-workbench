# 一、目标

本契约规定伊雍历史系统的设置、传记、族谱、墟境候选、蝴蝶效应、草稿和运行中请求如何保存与隔离。

本地资料库不替代聊天正文、MVU或世界书核心设定。只有蝴蝶效应模块例外：已校验并成功提交的当前聊天结构化锚定记录以本地资料库为权威原稿，专用全局归档世界书保存其可注入镜像。镜像写入不得修改其他世界书条目。

# 二、三层存储

## 2.1 运行内存

仅保存当前页面生命周期内的数据:

- 正在进行的请求。
- `AbortController`。
- RootTrace占位槽与待替换正文。
- 当前打开标签、选中节点和临时表单状态。
- 尚未通过校验的API原始输出。

刷新页面或关闭酒馆后允许丢失。未校验数据禁止进入持久化层。

## 2.2 脚本设置

使用脚本变量保存小型设置:

- 界面偏好。
- API默认路由和模块覆盖。
- 世界书检索范围。
- 最近选择的模型名称。
- 数据库版本和迁移状态。

不得把传记全文、完整族谱或候选史稿塞入脚本变量。

## 2.3 本地资料库

使用 IndexedDB 保存体积较大的结构化成品。

数据库名:

`eyon-history-system`

数据库版本从 `1` 开始，由脚本集中迁移。

禁止使用单个 `localStorage` 字符串保存整库，避免容量不足、部分写入和并发覆盖。

# 三、命名空间

所有持久化记录必须包含:

```json
{
  "namespace": {
    "characterKey": "当前角色卡稳定标识",
    "chatId": "当前聊天标识"
  }
}
```

## 3.1 角色卡级资料

可以跨同一角色卡的不同聊天复用:

- 玩家主动标记为角色卡共享的传记。
- 玩家主动标记为角色卡共享的族谱。
- 非敏感界面偏好。

共享键:

`characterKey`

## 3.2 聊天级资料

默认只属于当前聊天:

- 墟境生成草稿。
- 候选墟境。
- 当前参与人物。
- 当前选中节点。
- 当前聊天生成的传记和族谱。
- 当前聊天已提交的蝴蝶效应锚定记录。
- 当前聊天尚未完成的蝴蝶效应结算快照。
- 请求历史摘要。

隔离键:

`characterKey + chatId`

任何资料默认先保存为聊天级。只有玩家明确操作“共享到此角色卡”时才能提升为角色卡级。

## 3.3 禁止全局混用

不同角色卡、不同聊天、不同用户导入的数据不得因名称相同自动合并。

人物姓名、传记标题、地点和 `runId` 都不能单独作为命名空间。

# 四、对象仓库

## 4.1 `biographies`

主键:

`characterKey + chatId|shared + biographyId`

保存:

- 已校验的结构化传记JSON。
- 由已校验结构化传记确定性渲染的 `rootTrace`。
- 目标对象与别名。
- 时间跨度。
- 来源ID。
- `sourceHash`。
- 创建、更新时间。
- 生成模型和路由的非敏感标识。
- 是否共享。

不保存:

- API密钥。
- 内部自省。
- 未校验原始响应。
- 伊雍开场正文的重复副本。

## 4.2 `genealogies`

主键:

`characterKey + chatId|shared + focusMvuId + genealogyId`

保存:

- 已校验族谱JSON。
- 中心MVU人物标识。
- 向上、向下代数。
- 节点和关系。
- 来源与推断标记。
- `sourceHash`。
- 创建、更新时间。

族谱缓存可以删除和重建，不得被当作MVU或世界书事实回写。

## 4.3 `ruinDrafts`

主键:

`characterKey + chatId + draftId`

保存:

- 纪元与可选起止年月日。
- 必填地点。
- `selectedCharacters`。
- `supplementaryDirection`。
- 最近一次骰表结果。
- 最近一次生成请求ID。
- 当前选中的候选与节点ID。

不保存已经进入后的墟境运行状态。进入状态始终读取MVU。

## 4.4 `ruinCandidates`

主键:

`characterKey + chatId + requestId`

保存:

- 已校验候选JSON。
- 本次表单快照。
- 骰表命中结果。
- `sourceHash`。
- 创建时间。
- 当前是否仍可进入。

状态规则:

- API生成完成后为 `preview`。
- 正文面板成功生成后为 `confirmed`。
- 与真实 `墟境轮次` 建立关联后为 `entered`。
- 聊天变化、来源失效或轮次不匹配时为 `historical`。

`historical` 只可查看，不可直接再次进入。

## 4.5 `requestRecords`

只保存最小请求摘要:

- `requestId`
- `taskType`
- 路由类型
- 模型名称
- 开始、结束时间
- 最终状态
- 错误码
- 关联成品ID

不得保存完整提示词、完整世界书上下文、API密钥或失败响应全文。

## 4.6 `butterflyRecords`

主键:

`characterKey + chatId + runId`

保存:

- 已校验的 `eyon.butterfly.v1` 结构化JSON。
- 冻结的现实锚点、墟境进入锚点和墟境离开锚点。
- 本轮玩家行动摘要与骰点命中结果。
- 对应AI遣返楼消息ID。
- 专用世界书镜像的条目标识。
- `sourceHash`、`ruleBundleVersion`、`schemaVersion`。
- 创建、更新时间与提交状态。

状态规则:

- 校验通过但尚未写入正文时为 `validated`。
- 已写入正确AI遣返楼、但世界书镜像尚未完成时为 `message_committed`。
- 正文、本地记录与世界书镜像全部完成时为 `committed`。
- 镜像失败时为 `mirror_pending`，只允许重试镜像写入，不得重新生成内容。

同一 `characterKey + chatId + runId` 只能存在一条已提交锚定记录。重试必须更新原记录，禁止新增第二条。

## 4.7 `pendingSettlements`

主键:

`characterKey + chatId + runId`

在发送“遣返”之前同步保存:

- 三套成对锚点。
- `runId`。
- 玩家行动摘要及其来源楼层ID。
- 骰点与命中结果。
- 目标遣返请求ID。
- 创建时间和来源哈希。

此仓库用于防止API失败、页面刷新或酒馆关闭后丢失结算依据。它不得恢复 `exploring`、不得修改世界时间地点，也不得从旧轮次自动补齐新轮次。

只有对应 `butterflyRecords` 达到 `committed` 后，才可删除同轮 `pendingSettlements`。玩家主动放弃结算时必须二次确认。

# 五、不重复保存的数据

以下数据只读取权威来源，不复制为本地成品:

- `世界.时间`和`世界.地点`。
- `墟境系统`运行状态与快照。
- 完整MVU人物对象。
- 世界书全文。
- 记忆插件内容。
- 聊天正文全文。

本地记录只保存必要来源ID、哈希和短摘要。

例外:

- 已提交的蝴蝶效应结构化记录保存于 `butterflyRecords`。
- 专用全局归档世界书只保存由该记录渲染出的当前聊天镜像，不作为反向重建锚点的来源。
- `pendingSettlements` 只保存尚未完成的同轮冻结结算快照，不属于墟境运行状态。

# 六、API设置与密钥

## 6.1 普通设置

API路由、地址和模型名属于脚本设置。

## 6.2 密钥

- 密钥与普通设置分开保存。
- 优先使用宿主或浏览器可提供的私有凭据存储。
- 若运行环境没有安全凭据存储，只能保存在当前浏览器本地，并明确提示“本地保存不等于加密保险箱”。
- 密钥不得进入IndexedDB成品仓库、聊天变量、世界书、导出包、错误日志或请求记录。
- 导出设置时密钥字段固定为空。

# 七、写入事务

持久化成品必须遵循:

1. API响应完成。
2. 严格解析JSON。
3. Schema和语义校验通过。
4. 确认请求仍属于当前角色卡和聊天。
5. 在单个IndexedDB事务中写入成品和请求摘要。
6. 事务成功后更新界面。

任何一步失败时不得留下半条成品。

RootTrace替换成功与传记入库必须使用同一完成标记。若消息替换成功但入库失败，允许从最终消息重新解析恢复；不得再次生成传记。

蝴蝶效应使用分阶段提交:

1. 遣返前同步写入 `pendingSettlements`。
2. API结果通过校验后写入或更新 `butterflyRecords: validated`。
3. 固定面板成功写入目标AI楼后更新为 `message_committed`。
4. 专用世界书镜像成功后更新为 `committed`，再删除同轮待结算快照。

任一步失败都从上一个已提交阶段继续，不得重新取锚点、重新掷骰或重新生成另一份内容。

# 八、并发与版本

- 每条记录含 `revision`，从1递增。
- 更新时比较原 `revision`，防止旧窗口覆盖新数据。
- 同一 `requestId` 只能提交一次最终成品。
- 同一 `characterKey + chatId + runId` 只能提交一次蝴蝶效应成品。
- 多标签页同时打开时，以最后成功提交的更高 `revision` 为准。
- 旧请求返回不得覆盖当前表单或当前选中节点。
- 不同轮次的 `pendingSettlements` 和 `butterflyRecords` 不得相互补值或合并。

# 九、缓存失效

记录至少保存:

- `sourceHash`
- `ruleBundleVersion`
- `schemaVersion`
- `generatedAt`

以下变化使缓存失效:

- 角色卡或聊天变化。
- 相关世界书条目变化。
- 相关正文被编辑、删除、隐藏或重roll。
- 相关MVU人物资料变化。
- 玩家修改表单。
- 嵌入规则版本变化。

失效记录不自动删除。界面标为“资料已变化”，允许查看或重新生成。

# 十、迁移

每次数据库结构变化必须提供顺序迁移:

- 迁移只新增、重命名或转换已知字段。
- 无法识别的旧记录先备份到 `migrationQuarantine`。
- 禁止因单条坏数据清空整库。
- 迁移失败时停止写入，仍允许导出原始本地资料。
- 数据库版本升级与规则文本版本升级分开记录。

# 十一、导入与导出

导出包必须包含:

- 导出格式版本。
- 角色卡标识。
- 可选聊天标识。
- 玩家选择的传记、族谱和候选墟境。
- 玩家选择的蝴蝶效应结构化记录。
- 来源摘要与时间戳。

不得包含:

- API密钥。
- 世界书全文。
- 聊天全文。
- MVU完整对象。
- 记忆插件数据。

导入时:

- 先校验格式和Schema。
- 默认作为新记录导入，不覆盖同ID现有记录。
- 跨角色卡导入必须由玩家确认。
- 导入资料始终保留 `imported: true` 和原始来源说明。

# 十二、删除

- 删除聊天级资料不影响角色卡共享资料。
- 删除族谱不移除已保存传记中的来源引用，只把引用标记为不可用。
- 删除传记后，旧墟境候选仍可查看，但相关引用标记为缺失。
- 删除墟境草稿不修改MVU、不删除世界书锚定日志。
- 删除本地蝴蝶效应记录前必须提示其专用世界书镜像不会自动删除；若玩家选择同步删除，只能按保存的精确条目标识删除对应镜像。
- 删除专用世界书镜像不删除本地权威原稿；界面将其标记为“镜像缺失”，允许重新同步。
- 删除角色卡全部本地资料必须二次确认。

# 十三、启动与恢复

启动时:

1. 获取当前 `characterKey` 和 `chatId`。
2. 打开数据库并完成迁移。
3. 读取脚本设置。
4. 恢复当前聊天草稿。
5. 检查未完成的一般请求并统一标记为 `interrupted`。
6. 从MVU重新读取真实墟境状态。
7. 读取当前聊天的 `pendingSettlements` 与 `butterflyRecords`。
8. 对 `message_committed` 或 `mirror_pending` 记录，仅检查并补写专用世界书镜像。
9. 从专用世界书读取当前聊天镜像，用于显示镜像状态和发现缺失；不得反向覆盖本地结构化原稿。

禁止从本地草稿恢复 `exploring`、`returning`或世界时间地点。
