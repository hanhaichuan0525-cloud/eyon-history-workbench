## 1. 病历（2026-09-03 真机）

- 用户生成 320–350 黄昏花室/尤娜窗口候选：无视 active 干涉 R7（321 年尤娜已被扼杀），三稿全写「尤娜活到 350」。
- 诊断链：R9（internal.82 下新干涉）factKey 仍 `entity:generated:尤娜`；留痕 `index=0`——
  蝴蝶结算检索（行动结算型，非生成型任务）不产出 cast/personCanonViews；尤娜又无档案实体（世界书 0 命中）→ 映射源为空，F-01 归并无从谈起。
- 代码层第二缺陷：`canonResolver.deltaMatchesQuery` 的**实体闸是第一道闸**（L530-531）——
  delta 实体与查询侧 `subjectEntityIds` 无交集即判 `outside`，**地点闸与时间闸永远轮不到**。
  而蝴蝶 delta 的 `cascadeScope.locations`（黄昏花室地点链）本就携带可用的时空投递信息。

## 2. 目标与不做

**目标**：让无档案（`entity:generated:`）的干涉，在**时空/主题命中**时进入后续任务的 `<CANON_CURRENT_VIEW>`
（模型看见「321 年尤娜已被扼杀」这类本聊天正史状态），且不污染无关任务、不破坏已验收语义。

**不做**：
- 不改稳定档案实体的精确匹配语义（P1-1/RC/AB/AS/PC 与场景 1「无关 revision 不误伤」全部依赖它）；
- 不为原创人物建立持久档案（那是 G-08/记忆注入层的事，另行立项）；
- 不改模型输出 schema、不加依赖、不引入语义层；
- 不做跨聊天仲裁、不做自动 repair。

## 3. 方案（受控放宽，单向）

### 3.1 deltaMatchesQuery 修订（canonResolver.ts 核心改动）

现逻辑（L526-543）：实体无交集 → `outside`（一票否决）→ 地点 → 时间。

新逻辑：

```
1. 若 delta 实体均为「档案可判定实体」（非 entity:generated: 前缀）：
   维持现语义（实体精确交集，无交集 → outside）——零变化。
2. 若 delta 含 entity:generated: 实体（原创叙事层身份）：
   a. 实体闸豁免：不因 generated 实体无交集判 outside（generated 本就不在档案空间，
      不该用档案身份卡死）；
   b. 改由「地点或名称 + 时间」投递判定：
      - 地点命中：delta.cascadeScope.locations 与查询侧 spatialScopes 任一
        `locationOverlaps`（相等，或双向子串包含 ≥2 字——比现 sameScope 精确相等
        放宽一档，覆盖「艾瑟嘉德皇宫高塔-黄昏花室」vs「黄昏花室」真实粒度差）；
      - 名称命中（可选增强）：delta.cascadeScope.subjectNames（载体归一化名）与
        查询侧名称集合任一包含匹配——覆盖查询侧恰好带出该叙事人物（MVU/聊天人物视图）的场景；
      - 时间：delta.cascadeScope.time 与查询侧 temporalScopes 纪元区间重叠
        （parseTemporalScope 现语义）；缺省（旧数据未填）视为不拦截。
      - 组合：generated 通道下，地点或名称任一命中 且 时间不冲突 → `inside`；
        否则 `outside`（与现状一致：不可见）。
3. 'unknown' 分支与跨分支隔离不变。
```

### 3.2 蝴蝶结算补全 cascadeScope（workflows/butterfly.ts）

- `cascadeScope.time`：填 `{ start: { label: ruinEntry.time }, end: { label: ruinExit.time } }`
  （字段已存在于 contracts，蝴蝶从未填）；
- `cascadeScope.subjectNames`：新增可选字段（contracts），填各 stage.carrier 归一化名（去重，≤8 个，每名 ≤16 字截断）；
- `entityIds` 保留（归并结果或 generated），locations 保留（locationChain 已有）。

### 3.3 视图措辞（可选小项，prompts/activeEvidence.ts）

`<CANON_CURRENT_VIEW>` 内对 `epistemicStatus === 'generated'` 的条目附一行说明：
「以下条目为本聊天演绎产生的叙事状态（非档案史实）；同窗口叙事以其为当前状态，不得外推污染其他人物/地点/时期。」
——保留 P1-1「只约束命中对象」合同句，加一层 generated 身份提示（防模型把演绎状态当史料外推）。

### 3.4 兼容与迁移

- `cascadeScope.time/subjectNames` 均为可选字段：旧 delta 缺省 → generated 通道退化为
  「地点命中且时间不拦」（无时间=不拦）——**历史 generated 干涉（R7/R9 等）同样获得投递能力**，无需迁移；
- 稳定实体路径一行不改 → 已验收语义（RC/AB/AS/PC/场景 1）不受影响；
- generated 通道是**单向放宽**（从"恒不可见"到"命中才可见"），不存在可见性回退。

## 4. 风险与护栏

| 风险 | 护栏 |
|---|---|
| generated 干涉误投到同地点无关任务 | 需「地点或名称命中 **且** 时间不冲突」双条件；视图只读 + generated 身份标注；prompt 合同句「不得外推污染」保留 |
| 地点匹配过宽（子串包含）误伤 | 双向子串 ≥2 字 + 归一化（NFKC/去空白/小写）；「金谷界石案」（R8）与「黄昏花室案」（R7/R9）地点不相干 → outside 不变（场景 1 行为保住，列入回归） |
| P1-1 冻结合同被破坏 | 改动面限定在 `deltaMatchesQuery` 内部 generated 分支 + 可选字段；RC-01—RC-07 全套回归锁死 |
| 旧数据不可见 | 见 3.4：无迁移即获得放宽（如需收紧再按病历调） |

## 5. 测试计划

1. **canonResolver 单测（canon.test.ts 追加）**：
   - generated delta + 查询侧同地点同纪元 → `inside`，activeRevisionFacts 含其事实；
